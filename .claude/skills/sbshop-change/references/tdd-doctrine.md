# TDD 교리 (Red → Green → Refactor + Tidy First)

## TDD 사이클
1. **Red** — 가장 단순한 실패 테스트 먼저. 동작 설명 이름(`shouldSumTwoPositiveNumbers`). 실패 명확히. **RED 테스트는 리뷰 대상 1급 산출물이다** — GREEN 전에 Red 테스트가 요구사항의 예외 경우를 다 덮는지 스스로 검토한다.
2. **Green** — 통과시킬 **최소** 코드만.
3. **Refactor** — 통과 상태에서만. 한 번에 하나씩, 매 단계 후 테스트 재실행. 중복 제거·명료성 우선.

매번 한 테스트 → 통과 → 구조 개선. 항상 전체 테스트 실행(장기 제외).

## Tidy First — 구조/행위 분리
- **구조 변경**: 동작 불변 — 리네임·추출·이동.
- **행위 변경**: 기능 추가/수정.
- 한 커밋에 혼합 금지. 둘 다 필요하면 구조 먼저. 구조 변경은 전후 테스트로 동작 불변 검증.

## 커밋 규율
커밋 조건(전부 충족): ① 바꾼 영역의 게이트 통과 ② 단일 논리 단위 ③ 구조 변경과 행위 변경은 별도 커밋. 작고 잦은 커밋. **하위 에이전트는 커밋·브랜치 금지** — 주 세션이 게이트(와 등급이 요구하는 승인) 뒤에 커밋한다. 메시지 규약·승인은 `sbshop-change/SKILL.md`의 "커밋" 절.

## 롤백 규율 (비파괴)
잘못된 방향 지속 / 테스트 해결 불가 / 설계 방향 오류 시, 계속 가는 것보다 빠른 롤백이 효율적이다. 단 **파괴적 `git reset --hard` 금지** — tracked worktree 전체·사용자 변경·스파이크 탐색 코드를 영구 손실하고, untracked 산출물은 잔존해 재시도 시 오염 컨텍스트를 주입한다.
1. 작업 전 **checkpoint** 확보(브랜치 `archive/attempt-{ts}` 또는 patch 저장).
2. 롤백은 **범위 한정 복구**: `git restore --source=<checkpoint> -- <대상 경로>`.
3. untracked 산출물은 **삭제 말고** `.staging_backup/fail_dump_{ts}/`로 이동(사후 부검 보존).
4. **주 세션 전용 + 명시 승인**(비가역 — 승인 관문 준용). 하위 에이전트는 reset·커밋 금지.

## 코드 품질
중복 박멸 · 이름과 구조로 의도 표현 · 의존성 명시 · 작고 단일책임 메서드 · 상태/부수효과 최소 · 가장 단순한 해법.

## TDD 적용 한계 (과적용 금지)
테스트 가능한 동작이 있는 **코드**에만. 설계서·인프라·탐색/리서치·UI 감각엔 TDD 강제 X — 그땐 `dev-rules.md`의 목표 주도(성공 기준 정의)로 대체.
