# defect-triage — 진단·원장

결함을 **재현할 수 있는 레코드**로 만든다. 원장이 정확해야 수정이 헛돌지 않는다.

## 진단 순서 (싼 것부터)

1. 컴파일: `cd backend && ./gradlew compileJava compileTestJava`. 실패하면 그 자체가 P0다.
2. 기존 테스트: `.github/workflows/tests.yml`에서 해당 영역 job의 `run` 줄. 명령은 여기 옮겨 적지 않는다 — 원본은 CI 파일이다.
3. 경계면 정적 대조: `integration-qa` 체크리스트를 진단 모드로 — API 응답 DTO ↔ 프런트 타입, 스케줄러가 쓰는 로직 ↔ 서비스, 운영 스키마 ↔ 엔티티 ↔ `backend/docs/ddl/`.
4. 아래 유형의 신규 사례와, 고친 결함의 재발을 확인한다.
5. 운영 데이터를 읽는 조사는 `sbshop-ops-write` §3(읽기)을 따른다 — 주 세션만, 읽기 전용 역할로.

## 남아 있는 결함 유형

개별 사례의 현재 상태는 원장이 정본이다. 2026-07 초기 유형(빈 충돌·중복 구현)은 그 뒤 사례가 없어 뺐다 — 같은 점검은 `integration-qa`(설정↔빈, 포트↔어댑터)에 있다.
- **경계면 계약 불일치** — 프런트 ↔ 백엔드 필드명·enum 값·엔드포인트(예: D-357 지연 드릴다운 필터가 집계 조건과 달랐다).
- **스키마 드리프트** — 엔티티 ↔ 운영 스키마의 정합은 코드도 테스트도 보증하지 않는다. `backend/docs/ddl/`에 빠진 파일도 있다.
- **헛-그린 게이트** — 검사 대상이 0건인 검증 명령(예: `-p tsconfig.app.json` 없는 `tsc`).

## 원장 레코드 (`docs/normalize/defect-ledger.md`)

```
### D-{번호} — {한 줄 요약} ({날짜}, {출처: 사용자 제보·운영 대사·작업 중 발견})
- 심각도: P0~P3 · 리스크: 경량|표준|중대 (코드 변경이 없는 운영 조치는 운영 등급 W1|W2|W3|대량) · 상태: {어휘}({날짜·근거})
- 위치: {파일·함수}
- 증상: {관찰한 사실. 사례는 주문 id로}
- 재현: {명령·쿼리·경로. 못 하면 "미재현 — 이유"}
- 원인(확인|추정): {근거(파일:줄)를 확보한 것만 "확인"}
- 수정: {무엇을 어떻게. 테스트 이름}
- 운영 조치: {일시 · 대상 기준 · 건수 · 백업 위치 · 재조회 결과 · 잔여}  ← 운영 쓰기가 있었을 때만
- 검증: {게이트 결과 · 검증자 판정 요지 · 로컬 미실행 게이트}
- 이력: {날짜 상태 변경, 한 줄씩}
```

상태: `발견`(기록만) · `수정완료`(고쳤고 로컬 게이트 통과, 검증·커밋 전) · `검증통과`(등급이 요구하는 검증자 PASS와 로컬에서 돌 수 있는 게이트를 통과해 커밋됨, 배포 전. 로컬에서 못 돌린 게이트는 "검증" 줄에 적는다) · `종결`(배포됐고 라이브에서 확인함. 코드 없는 운영 조치는 재조회 확인까지) · `보류(사유)` · `무효(사유)`.
- `검증통과`와 `종결`을 나누는 이유: 푸시가 매번 승인이라 커밋과 배포 사이가 벌어진다 — 이 구분이 없으면 배포 대기분을 찾을 수 없다. 반려는 상태가 아니라 이력 줄에 적는다(예: "1차 부분 → 수정 → 재검증 PASS").
- 원장은 주 세션만 쓴다. 번호는 이어서 늘리고 재사용하지 않는다. 레코드는 지우지 않는다 — 오판은 `무효(사유)`로. 한 ID에 헤더는 하나, 후속은 그 레코드의 이력 줄에. 이유: 원장은 감사 추적이다.
- 옛 레코드는 고쳐 쓰지 않는다. 읽을 때: `해소`·`완결`·`라이브검증완료`·`해결`·`구성완료`·`검증통과(라이브 검증 완료)`·`배포·검증통과` = 종결(괄호 속 잔여 일은 STATUS가 정본), `무효화` = 무효, `수정완료(검증대기)` = 수정완료. 한 ID에 헤더가 여럿이면 파일에서 가장 뒤의 것이 현재다. 새 어휘는 D-366부터다.

**우선순위** — P0(빌드·데이터 손상) > P1(기능 불능) > P2(오동작) > P3(품질). 같은 심각도면 ① 다른 진단을 막는 것 ② 사용자가 지목한 기능 ③ 수정 파급이 작은 것. 조용히 죽어 있는 기능(예: D-348 — 쿠팡 정산 동기화가 매일 "대상 없음 성공"으로 끝났다)을 경고류 P3보다 앞세운다.
