# 아이허브 축소 → 영국 소싱(포트넘·오카도) 전환 단계별 계획 (D-360)

- 작성: 2026-10-31 · 요청: 사용자(2026-10-30)
- 배경: iHerb KR 결제에 구매자 본인인증이 필요해졌다. 통관부호만으로는 결제가 안 되고 주문마다 고객 연락·인증이 필요하다. 감당할 인력이 없어 iHerb 상품을 점진적으로 내린다.
- 사용자 지정 순서: ① 몇 개월 내 팔린 적 없는 것부터 ② 연동된 마켓에서 삭제 ③ 삭제가 확인되면 시스템에서 삭제. 그 뒤 포트넘앤메이슨(FTN)·오카도(OCD) 상품 등록을 늘린다.

## 1. 현황 (2026-10-31 운영 DB 실측)

| 항목 | 값 |
|---|---|
| IHB 상품 | 2,146개 (전체 3,195개의 67%) |
| 마켓 등록(존재 확인) | 카페24 1,731 · 스마트스토어 1,728 · 11번가 1,768 · 쿠팡 810 |
| 카페24 경유 G마켓·옥션 리스팅 | G마켓 1,436 · 옥션 1,327 (카페24 상품에 매달린 자식 리스팅) |
| 판매 이력 | **한 번도 안 팔림 2,000** · 최근 3개월 내 판매 91 · 3~6개월 전 판매 55 |
| 주문 데이터 범위 | **2026-05-21부터만 있음** (약 5개월) |
| 최근 3개월 주문 라인 | **IHB 200** · FTN 5 · VTB 1 — 매출의 약 97%가 아이허브 |
| IHB 진행 중 주문 | 53건 (결제완료~배송중) |
| 쿠팡 IHB 등록 중 심사 걸림 | `BLOCKED_BY_MARKET` 555 (심사중 상품은 쿠팡이 삭제를 거부) |
| 기존 FTN / OCD | 393 / 407개 등록. **마지막 크롤 2026-09-12** (7주째 가격·재고 미갱신), OCD 원본 소멸 136 |

### 계획에 영향을 주는 사실 4가지
1. **"몇 개월"은 최대 5개월까지만 판정할 수 있다.** 주문 기록이 5/21부터라 그 전에 팔린 상품은 "안 팔림"으로 보인다. 한 번도 안 팔린 2,000개가 곧 "5개월 이상 판매 없음"이다.
2. **지금 삭제 기능을 그대로 쓰면 D-358(툴시 잎차) 같은 유령 리스팅이 대량으로 생긴다.** 현행 `ProductManageUseCase.deleteProduct`의 문제는 세 가지다.
   - 카페24 상품을 지우면서 G마켓·옥션 자식 리스팅은 "수동"으로만 기록하고 남겨 둔다. 카페24 상품이 사라지면 G마켓·옥션 리스팅은 판매중인 채로 연결이 끊긴다.
   - 외부 삭제가 실패해도 SB 상품을 **즉시** 소프트 삭제한다(`disposed = true` 고정). 사용자 방식("삭제 확인 후 시스템 삭제")과 순서가 반대다.
   - 11번가는 자동 삭제가 미지원(수동)이고, 쿠팡은 심사중이면 삭제가 거부된다.
3. **아이허브가 매출의 거의 전부다.** 판매 이력이 있는 146개를 언제 어떻게 내릴지가 매출에 직결된다.
4. **영국 상품은 이미 800개가 올라가 있는데 거의 안 팔리고(FTN 3개월 5건), 가격·재고가 7주째 갱신되지 않았다.** 신규 등록보다 기존 800개 정상화가 먼저다.

## 2. 단계별 계획

### 0단계 — 결정 (코드 작업 없음, 사용자 결정)
| # | 결정할 것 | 추천 |
|---|---|---|
| 0-1 | 1차 삭제 기준 | 판매 이력 없음(2,000개). 주문 기록이 5개월뿐이라 "5개월 이상 판매 없음"과 같다 |
| 0-2 | 판매 이력 있는 146개 | 1차에서 제외. 아이허브 매입이 가능한 동안 유지하고, 4단계에서 따로 결정 |
| 0-3 | 진행 중 IHB 주문 53건 | 매입 경로(본인인증)로 처리하되, 처리 불가 건은 취소 기준을 정해 둔다 |
| 0-4 | 쿠팡 IHB 브랜드 심사 소명 | 1차 삭제 대상 브랜드는 소명을 중단한다(삭제할 상품에 증빙을 쌓지 않는다) |
| 0-5 | "시스템에서 삭제"의 의미 | 소프트 삭제(행은 남기고 숨김). 과거 주문·정산이 상품을 참조하므로 하드 삭제는 하지 않는다 |
| 0-6 | 영국 소싱의 매입·배송 경로 | 5단계 전에 반드시 확인(아래 5-1) |

### 1단계 — 퇴출(retire) 도구 정비 (코드, 표준~중대)
목표: "마켓에서 지운다 → 지워졌는지 확인한다 → 확인된 것만 시스템에서 지운다"를 상품 수천 개에 안전하게 돌리는 도구.

1. **퇴출 상태 도입:** 상품에 `RETIRING`(퇴출 진행 중) 상태를 둔다. 이 상태의 상품은 가격·재고 배치와 마켓 전송에서 빠진다(카페24 재고 0 전송 금지 규칙 유지).
2. **마켓별 삭제 순서 고정:** G마켓·옥션(ESM) → 카페24 → 스마트스토어 → 쿠팡 → 11번가. **카페24 상품은 G마켓·옥션 리스팅이 지워진 게 확인된 뒤에만 지운다**(D-358 재발 방지).
3. **G마켓·옥션 삭제 경로 조사·구현:** ESM은 쓰기 API가 없다. 조사 대상은 아래 두 가지이고, 실측 후 고른다. 자동화가 불가능하면 대상 목록 엑셀을 뽑아 사람이 일괄 처리하는 반자동 경로로 간다.
   - 마켓플러스의 마켓상품 삭제(카페24가 대신 지움)
   - ESM 목록의 일괄 다이얼로그(판매중지 → 삭제)
4. **11번가:** 삭제 API 유무를 재확인한다. 없으면 판매중지(`stopdisplay`)로 대체하고, "삭제 확인" 대신 "판매중지 확인"을 퇴출 완료 조건으로 삼는다.
5. **쿠팡 심사중 상품:** 삭제가 거부되므로 퇴출 대기열에 두고 심사 결과 후 재시도한다(반려되면 삭제 가능). 판매중지 API도 승인완료 상품만 된다.
6. **삭제 확인:** 마켓 재조회(`/internal/registrations/probe` 계열)로 부재를 확인했을 때만 `DELETED_ON_MARKET`으로 기록한다. 쓰기 성공 응답만 보고 확인으로 치지 않는다.
7. **시스템 삭제 조건:** 모든 마켓이 "부재 확인(또는 11번가 판매중지 확인)"일 때만 SB 소프트 삭제. 하나라도 남으면 `RETIRING`으로 남겨 다음 회차에 재시도한다.
8. **가드:**
   - 진행 중 주문·활성 클레임이 있는 상품은 제외한다.
   - 실행 단위는 dry-run, 건수 상한, 마켓별 throttle(네이버 1200ms 이상)로 묶는다.
   - 매 회차 결과 리포트(마켓별 성공·거부·대기)를 남긴다.
9. **기존 `deleteProduct` 정리:** 수동 단건 삭제도 같은 순서·조건을 쓰게 하거나, 최소한 G마켓·옥션이 남아 있으면 카페24 삭제를 막는다.

### 2단계 — 파일럿 (20개)
- 판매 이력 없는 IHB 중, 모든 마켓에 등록된 상품 20개를 고른다. 쿠팡 심사중이 아닌 것 위주로 한다.
- 실행 → 마켓별 결과 → 각 마켓 화면에서 실제 삭제를 확인한다(크롬).
- **고아 리스팅 대조:** ESM 전체 리스팅과 우리 상품을 대조해(D-358 때 쓴 방식) 새로 생긴 유령 리스팅이 0개인지 확인한다.
- 문제가 없으면 회차 크기를 정한다(예: 하루 200개).

### 3단계 — 판매 이력 없는 2,000개 단계적 퇴출
- 하루 1회차씩 진행하고, 회차마다 대조 리포트를 확인한다.
- 소싱 배치가 도는 시간과 겹치지 않게 한다.
- 쿠팡 심사중은 대기열로 빠지니, 쿠팡 심사 결과가 나오는 대로 재시도한다.
- 완료 기준: 판매 이력 없는 IHB 중 `RETIRING`·남은 마켓 리스팅 0, 유령 리스팅 0.

### 4단계 — 판매 이력 있는 146개 처리 (사용자 결정 후)
- 0-2에서 유지하기로 한 상품은 매입 부담과 매출을 함께 보고 결정한다.
- 선택지:
  - 계속 판매
  - 품절 처리 후 일정 기간 관찰
  - 퇴출
- 선택지마다 영국 대체 상품이 있는지(같은 카테고리 수요)를 함께 본다.

### 5단계 — 영국 소싱 기반 정상화 (신규 등록 전)
1. **매입·배송 경로 검증 (가장 먼저):** 포트넘·오카도에서 실제로 1건씩 사서 한국 고객에게 보내는 경로를 확정한다.
   - 확인 항목: 배송대행지 사용 여부, 오카도의 해외배송 불가 여부, 통관(목록통관/일반통관·개인통관부호), 구매자 인증 요구 여부, 리드타임, 실제 원가.
   - **아이허브와 같은 인증 함정이 있는지 여기서 걸러낸다.** 현재 가격 정책(£10.5 + £2/500g)이 실제 배송비와 맞는지도 검증한다.
2. **기존 800개 정상화:**
   - 정기 크롤 재가동: 9/12 이후 멈춤 → 가격·재고 갱신.
   - FTN GraphQL 고속 경로 전환(백로그 ①, 상품당 20초 → 0.5초, 원가·중량·HS코드·성분까지 확보).
   - OCD 원본 소멸 136개 정리(이 역시 퇴출 도구로).
3. **수요 점검:** FTN 393개가 3개월 5건만 팔린 이유를 본다. 가격 경쟁력(마켓 최저가 대비), 노출, 카테고리 오등록 중 무엇이 원인인지 확인한다.

### 6단계 — 영국 상품 신규 등록 확대
- 상품 추천·자동등록 파이프라인(S0~S6)은 아이허브 기준으로 만들어져 있다. 발굴(S0)·통관게이트(S2)·인리치먼트(S4)를 FTN·OCD 스크레이퍼로 확장한다.
- 미완인 S6(마켓 등록 페이로드)을 마무리한다.
- 쿠팡 브랜드 심사를 고려해 새 브랜드는 **매입 증빙이 가능한 브랜드부터** 등록한다. 쿠팡이 인정하는 증빙은 주문 상세 화면 캡처다.
- 등록 속도는 4단계 퇴출 속도와 매출 추이를 보며 조절한다.

## 3. 순서와 의존 관계
```
0 결정 ─┬─ 1 퇴출 도구 → 2 파일럿 → 3 미판매 2,000 퇴출 → 4 판매이력 146
        └─ 5-1 영국 매입 경로 검증 → 5-2·5-3 기존 800 정상화 → 6 신규 등록
```
- 1~3(퇴출)과 5(영국 정상화)는 서로 독립이라 병행할 수 있다.
- 4(판매 상품 퇴출)는 5의 결과(대체 매출원)를 보고 결정한다.
