# D-248 소싱처별 가격 정책 — 리팩토링 계획

작성 2026-08-30 · 라이브 검수(배치 업데이트 · 설정 및 연동) 기반

판매가를 만드는 값들이 파이썬 파일·자바 상수·리액트 화면 세 곳에 흩어져 하드코딩돼 있다.
전부 아이허브 기준이라, 정가로 사고 배송비까지 내는 영국 소싱처에도 그대로 걸린다.
가격 정책의 축을 **마켓에서 소싱처로** 옮긴다.

## 1. 가격이 만들어지는 곳은 세 군데다

| 계층 | 위치 | 박혀 있는 값 | 문제 |
|------|------|-------------|------|
| 해외 배송비 | `scraper/pricing.py` | `BASE_SHIP_GBP 10.5`, `STEP_GBP 2.0 / 0.5kg` | 파운드 전용. F&M 규칙을 다섯 소싱처가 공유. 바꾸려면 파이썬 이미지 재배포 |
| 국내 배송비 | `MarginCalculator` | 40,000원 미만 → +6,000원 | 자바 상수. 아이허브 조건인데 전 소싱처 적용 |
| 화면 기본값 | `BatchUpdatePage.tsx:350` | 마진 15 · 쿠폰 20 · 최소마진 5,000 | 아이허브 값. **소싱처를 바꿔도 변하지 않는다** |

### 라이브 실측 — 배치 업데이트 화면

소싱업체를 `IHB` → `VTB`(비타바이오틱스)로 바꿔도 `마진 15 / 쿠폰 20 / 최소마진 5,000`이 그대로다.
비타바이오틱스는 쿠폰이 없고 정가 매입인데, 화면은 **20% 할인 매입**을 가정한 채 배치를 실행한다.

### D-250 수정이 이 위험을 키웠다

쿠폰율·최소마진가를 상품에 저장하도록 고쳤다. 이전에는 잘못된 기본값이 흔적 없이 사라졌지만,
이제는 **상품에 영구히 새겨진다.** Phase 3-2가 가장 급한 이유다.

## 2. 축이 틀렸다

| | 결정하는 것 | 저장 위치 |

| **소싱처** | 마진율·쿠폰율·최소마진가·기초배송비·추가배송비·통화·국내배송비 | 없었음 → `sb_vendor_price_policy` 신설 |

설정 화면의 가격 정책 카드는 `Settings.tsx:449`, **마켓 탭 조건문 바깥**에 있다.
탭마다 다시 렌더되는 중복이 아니라 하나뿐인 카드다. 다만 마켓 탭 아래 놓여 마켓별 설정처럼 보인다.
**중복이 아니라 오배치다.**

## 3. 확정된 결정 (사용자)

- 마진율·쿠폰율·최소마진가·기초 배송비·추가 배송비 **전부** 소싱처별로 다르다.
- 국내 배송비 4만원/6천원은 현재 값이 맞다. 다만 아이허브 조건이므로 **소싱처별 설정값으로 빼고 화면에서 조정 가능**하게 한다.
- 상품 0건 소싱처는 목록에서 제외: `AMZ`(상품 0·크롤러 없음), `TES`(어제 98건 전량 폐기).

### 대상 소싱처

| 소싱처 | 활성 상품 | 통화 | 비고 |
|--------|----------|------|------|
| IHB | 2,146 | KRW | 쿠폰 매입 · 해외 배송비 없음 |
| OCD | 407 | GBP | 정가 매입 · 배대지 배송비 |
| FTN | 393 | GBP | 마진율이 20/25로 갈려 있음 |
| VTB | 100 | GBP | 정가 매입 · 배대지 배송비 |
| COK | 48 | GBP | 정가 매입 · 배대지 배송비 |

| AMZ | 0 | — | 목록 제외 |

## Phase 1 — DB 테이블 (완료)

```sql
CREATE TABLE sb_vendor_price_policy (
  id                 bigserial PRIMARY KEY,
  vendor             varchar(8)  NOT NULL UNIQUE,
  margin_rate        numeric(5,2),
  coupon_rate        numeric(5,2),
  min_margin_price   numeric(15,2),
  ship_currency      varchar(3),      -- GBP / USD / KRW
  ship_base_amount   numeric(10,2),   -- 기초 배송비
  ship_base_weight_g integer,         -- 기초가 커버하는 무게
  ship_step_amount   numeric(10,2),   -- 추가 단위 요금
  ship_step_weight_g integer,         -- 추가 단위 무게
  domestic_fee       numeric(10,2),   -- 국내 배송비
  domestic_free_over numeric(15,2),   -- 이 금액 이상이면 국내 무료
  status varchar(16) NOT NULL DEFAULT 'ACTIVE',
  created_at timestamptz NOT NULL DEFAULT now(),
  updated_at timestamptz NOT NULL DEFAULT now()
);
```

기초·추가 두 쌍으로 두면 현재 규칙(0.5kg까지 £10.5, 이후 0.5kg마다 +£2)이 그대로 표현되고,
달러 소싱처는 통화만 바꾸면 된다. 기존 `sb_price_policy`는 **소싱처 미지정 시 폴백**으로 남긴다.

시드 완료: IHB(15/20/5000, KRW) · FTN·OCD·COK·VTB(25/0/5000, GBP £10.5+£2/500g) · 전부 국내 6,000/40,000.

## Phase 2 — 백엔드

### 2-1. 해석 순서 (완료)

```
오버라이드 → 상품 저장값 → 소싱처 정책 → 전역 정책
                            ^^^^^^^^^ 신설
```

`VendorPricePolicy` 엔티티 + `VendorPricePolicyRepository`(JPA, core 배치 — 기존 `PricePolicyRepository` 관례) +
`VendorPricePolicyService` 신설. `MarketSalePriceResolver`의 세 해석 메서드에 소싱처 단계를 끼워 넣었다.

테스트 `VendorPricePolicyResolutionTest` 3건 — Red 를 단언 실패로 확인.

### 2-2. 배송비 계산을 Python → Java (완료)

스크래퍼는 이미 `price`·`currency`·`weightGrams`를 반환하므로 **계약을 바꿀 필요가 없다.**

```
스크래퍼 →  price £7.49 · currency GBP · weightGrams 680     (사실)
자바   →  소싱처 정책 + 환율 → 배송비 → 원가(원)            (판단)
```

`goodsKrw`·`shippingKrw`는 당분간 유지해 호환을 깨지 않고, 자바 경로 검증 후 제거한다.
환율은 통화별로 조회하고, 실패 시 계산 중단하는 현재 안전장치를 유지한다.

### 2-3. 국내 배송비 상수 제거 (대기)

`MarginCalculator`의 `DELIVERY_FEE_THRESHOLD 40000` / `DELIVERY_FEE 6000`을 정책 값으로 받는다.
기본값은 현재와 동일.

## Phase 3 — 프론트

### 3-2. 배치 업데이트 (완료)

- `GET /api/v1/vendor-price-policy` (목록) · `GET|PUT /{vendor}` 신설.
- 화면이 정책 목록을 불러와 **소싱업체 셀렉트를 정책 보유 소싱처로 채운다** — `AMZ`·`TES` 는 정책 행이 없어 자동으로 빠진다(별도 목록 관리 불필요).
- 소싱업체를 바꾸면 마진·쿠폰·최소마진이 그 소싱처 값으로 교체된다. 하드코딩 `initialValues={{15, 20, 5000}}` 제거.
- 배송비 조건(해외 통화·기초/추가, 국내 요금·무료기준)을 셀렉트 아래에 읽기 전용으로 노출한다.

**주의 — 배치는 여전히 화면 입력값만 사용한다.** 배치 경로는 `MarketSalePriceResolver.resolve(PricingInputs, ...)` 를 타며
상품값·소싱처 정책을 조회하지 않는다. 소싱처 정책이 배치에 닿는 유일한 통로가 이 화면 자동 채움이다.

### 3-1. 설정 및 연동 (완료)

```
[쿠팡] [N스토어] [11번가] [카페24] [가격 정책]
                                    └ 소싱처 선택 → 매입·마진 / 해외 배송비 / 국내 배송비
```

- `가격 정책` 탭 신설. 이 탭에서는 마켓 API 카드를 숨기고 `VendorPricePolicyPanel` 만 보인다.
- 소싱처 버튼(정책 목록에서 생성) → 세 묶음으로 편집: **매입·마진**(마진율·쿠폰율·최소마진가) / **해외 배송비**(통화·기초 금액/무게·추가 금액/무게) / **국내 배송비**(요금·무료기준).
- 쿠폰율에 "매입가를 깎는 비율. 정가로 사는 소싱처는 0" 이라고 명시했다 — 이 오해가 [[D-248]] 의 원인이었다.
- 기존 전역 정책은 **"공통 폴백 정책"** 으로 이름을 바꿔 같은 탭 아래에 남겼다(소싱처 정책이 없을 때만 사용).
- 마켓 탭에서는 가격 정책이 더 이상 보이지 않는다 — 오배치 해소.

## Phase 4 — 데이터 정리

- **D-249 백필**: 아이허브 `margin_rate=4`는 2026-02 레거시 이관값이고 현재 판매가와 맞지 않는다.
  재크롤 직후 **같은 원가 기준으로** 판매가에서 역산해 채운다. 원가가 변한 뒤 역산하면 오염된다.
- **FTN 마진율 정리**: 393건이 20%(358) / 25%(35)로 갈려 있다. 통일 여부 결정 후 반영.
- **드라이런**: 소싱처별 배치를 오버라이드 없이 돌려도 안전한지 먼저 확인.

## 주의할 것

- **배치 중 배포 금지.** main 푸시는 자동 배포 → API 재시작 → 돌던 배치 중단. 문서만 바꾼 커밋도 마찬가지.
- **쿠팡 가격 변경 폭 제한(D-246)이 살아 있다.** 1회 한도 −50% ~ +100%. 새 정책으로 가격이 크게 바뀌면 쿠팡만 반영 실패.
- **기존 상품 3,095건은 `coupon_rate`·`min_margin_price`가 전부 NULL.** 지금은 전역 정책으로 폴백하지만
  Phase 1 시드가 들어가면서 **소싱처 정책으로 폴백이 바뀐다** — 이 전환의 가격 영향을 반드시 확인할 것.
- **`Product.create` 가 `marginRate` 를 0 으로 기본값 채운다**(`createPriceInfo` 의 `defaultIfNull(..., ZERO)`).
  상품값이 소싱처 정책을 이기므로, 마진 없이 생성된 상품은 **0% 마진이 고정된다.** 별도 결함으로 다룰 것.
