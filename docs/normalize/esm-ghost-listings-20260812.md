## 1. 왜 매핑이 안 됐나

카페24 주문 API 원문(2026-08-12 라이브 조회):

```
order_item_code            = 20260811-0000015-01
product_no                 = -99999          ← 카페24 몰 상품 미연동 센티널
product_code               = 2005125893      ← G마켓 상품번호
custom_product_code        = null
market_custom_variant_code = 5ffd2a8e27776   ← G마켓 판매자 관리코드(난수)
product_name               = Pure Indian Foods 오리지널 기버터 Original Ghee
```

`Cafe24OrderSyncService.cafe24ResolveProductId()`는 `product_no → product_code` 두 키만
`sb_market_registration`에서 찾는다. `-99999`도 `2005125893`도 우리 DB에 없어 `product_id`가
NULL로 남았고, **경고 한 줄 없이 조용히 넘어갔다.**

## 3. 문제의 본질 — 매핑 버그가 아니라 매출 누수

난수 코드 리스팅은 카페24 몰 상품과 연동이 없다. 그래서
**우리 재가격 배치가 닿지 않아 등록 시점 가격에 얼어붙었고**, 대부분 정상 리스팅보다 싸다.
G마켓 검색에서 같은 상품이 두 개 뜨면 구매자는 싼 쪽을 산다.

이번 건: 기버터 2개가 유령에서 **128,800원**에 팔렸다. 정상 리스팅이었으면 171,800원.
**한 건에 43,000원 손실.**

추가 위험: 13건 중 **11건이 재고 99999(무한)**. 실재고 0이어도 계속 주문을 받는다 →

## 5. 2026-08-12 조치

**제외 2건의 사유**

- **#4 크랜베리** — 판매중지하지 않았다. 짝이 되는 정상 리스팅이 **없어서**, 중지하면 이 상품이

  없다 — 우리 파이프라인으로 G마켓에 올린 적이 없는 레거시 리스팅이다.
- **#5 NatureWise 180캡슐** — 짝도 없고 우리 DB에 상품도 없다(단종). 재고 99999로 계속 주문을
