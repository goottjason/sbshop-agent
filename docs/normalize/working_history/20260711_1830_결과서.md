## 근본원인·수정
- **D-073**: `Order.updateCustomsClearanceNo`가 번호 변경 여부 무관 항상 `customsStatus=PENDING·verifiedPerson=NONE` 리셋. 5개 마켓 SyncService가 매 동기화마다 같은 통관번호로 재호출 → 사용자 수기 검증 소실(신고 직접원인). VALID→PENDING이 통관 스케줄러 재검증 루프(OVW-4)도 유발. 사용자 수기 통관번호 수정 경로(OVW-3)도 동일. → **번호가 실제 변경된 경우에만 리셋**하도록 도메인 메서드 1곳 수정으로 3결함 동시 해소.
- **D-074**: 쿠팡·Cafe24만 progressed 주문 주소 보호(protectAddress) 가드 보유, 스마트스토어·11번가·ESM+는 lineItems 미수신으로 가드 부재. zipcode는 전 마켓 미보호. → 3마켓에 lineItems 전달(기존 조회 재사용) + address·zipcode 세트 보호, 쿠팡·Cafe24 zipcode 확장.
