# 2026-08-19 수동 편집값을 마켓 동기화가 되돌리지 않게 한다

## 배경

직전 사이클(배송메시지 편집 추가)에서 남긴 항목: 수동으로 고친 주소·통관번호·배송메시지가
다음 동기화에 덮인다. 사용자 지시로 세 필드를 묶어 처리.

## 왜 단순 잠금이 아닌가

"한 번 손대면 동기화가 그 필드를 영영 안 건드린다"는 가장 단순하지만 **오배송을 만든다** —
고객이 마켓에서 실제로 배송지를 바꿔도 우리가 무시하게 된다.

채택안: **마켓이 마지막으로 보낸 값을 스냅샷으로 보관하고, 그 값이 실제로 달라졌을 때만 반영.**
- 마켓이 같은 값을 재전송(=대부분의 동기화) → 무시 → 수동 수정본 유지
- 마켓 값이 진짜로 바뀜(=고객 변경) → 반영 → 오배송 없음
- 별도의 "수동 편집함" 플래그가 필요 없다. 비교만으로 판정된다.

## 구현

| 파일 | 변경 |
|------|------|
| `core/domain/order/Order.java` | `lastMarketAddress`/`lastMarketMessage`/`lastMarketCustomsNo` 필드(@JsonIgnore) + `marketValueChanged()` + `update()`·`applyCustomsClearanceNoFromMarket()`에 가드 |

- 가드는 **도메인 `update()`에 두어 4개 마켓 동기화 서비스가 한 번에 커버**된다
  (Cafe24/SmartStore/Elevenst/Coupang 모두 `order.update(...)` 경유).
- 수동 경로(`updateAddress`/`updateMessage`/`updateCustomsClearanceNo`)는 스냅샷을 건드리지 않는다 —
  건드리면 비교 기준이 오염돼 보호가 풀린다. 전용 테스트로 고정.
- 기존 PII 가드(`isMeaningfulPii`, 빈값 거부)는 그대로 앞단에 유지. 이번 가드는 그 뒤에 붙는다.

## 도중에 뒤집은 판단 1건 (기록해둘 것)

처음엔 "스냅샷이 없으면(레거시 행) 덮지 않는다"로 구현했다. 기존 테스트 5건이 깨졌고,
확인해보니 **그 규칙이 틀렸다**: 배포 직전에 고객이 배송지를 바꾼 주문은 첫 동기화에서 그 변경이
무시된 채 스냅샷에만 기록돼, 이후로는 "변경 없음"으로 보여 **영영 반영되지 않는다.**
막으려던 오배송을 오히려 만드는 규칙이었다.

→ `스냅샷 null = 종전대로 적용`으로 되돌리고, 대신 **배포 시 백필**로 null 상황 자체를 없앴다.
기존 5개 테스트의 계약("정상 실값은 기존 값을 갱신한다")도 그대로 지켜진다.

## 스키마 (중대 등급 — 사용자 승인 후 진행)

`ddl-auto: update`가 자동 생성:

```
last_market_address     varchar(500)
last_market_message     varchar(1000)
last_market_customs_no  varchar(50)
```

백필(수동 실행, 배포 직후 1회):

```sql
UPDATE sb_order SET last_market_address = address,
                    last_market_message = message,
                    last_market_customs_no = customs_clearance_no
WHERE last_market_address IS NULL AND last_market_message IS NULL AND last_market_customs_no IS NULL;
-- UPDATE 256 (= sb_order 전체 건수, 100% 커버)
```

## 남은 검증 (사람이 해야 함)

**아직 실제 동기화를 한 사이클 돌려보지 않았다.** 확인 방법:

1. 주문 하나의 배송메시지(또는 주소)를 화면에서 고친다.
2. 다음 마켓 동기화가 돌 때까지 기다린다.
3. 고친 값이 그대로 남아 있으면 성공. 되돌아갔으면 실패이므로 원장에 등재한다.

## 알아둘 것

배포 **이전에** 이미 손으로 고쳐둔 값이 있다면, 그 값이 스냅샷에 "마켓이 준 값"으로 기록됐다.
마켓이 원래 값을 다시 보내면 "바뀌었다"고 판단해 **한 번은 덮어쓴다.** 이후로는 정상 보호된다.
(종전에는 매 동기화마다 덮였으므로 더 나빠진 것은 아니다.)
