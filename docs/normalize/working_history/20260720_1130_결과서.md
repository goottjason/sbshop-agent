# 2026-07-20 11:30 결과서 — D-090 옥션/G마켓 발주확인 "AUCTION credentials not found" 수정

## 개요
사용자가 서종수 옥션 주문(196) 발주확인 시 오류. 서버 로그: `주문 196 접수 확인 실패: AUCTION credentials not found`. `OrderService.confirmOrder`가 Cafe24 기반 마켓(옥션/G마켓)에도 마켓 크레덴셜을 필수로 요구해 실제 Cafe24 호출 전에 실패했다. **[[D-088]] 수정이 드러낸 잠재 버그.**

## 근본원인 (D-090)
`confirmOrder`(OrderService.java:96)가 `credentialRepository.findByMarketType(marketType).orElseThrow(...)`로 크레덴셜을 필수 요구. 그러나 옥션/G마켓 발주확인은 `Cafe24AuctionOrderAdapter/Cafe24GmarketOrderAdapter.acceptOrders`가 **credential 파라미터를 무시**하고 Cafe24 토큰(Cafe24TokenManager)으로 호출한다 → AUCTION/GMARKET 크레덴셜은 설계상 DB에 없음(Cafe24가 연동주체). 크레덴셜 조회 단계에서 실패.

**노출 경위:** D-088 수정 전에는 N10이 PREPARING으로 오분류돼 발주확인이 `hasProgressedOrEnded` 가드("이미 발주확인됨")에서 차단 → 크레덴셜 조회에 도달조차 못 했다. D-088(N10→NEW)로 발주확인이 실제 실행되며 이 잠재 버그가 노출됨.

**판정근거(비대칭):** 같은 코드베이스의 송장·취소 경로(`MarketplaceShippingService.java:73,141`, `OrderShipProcessor.java:54`)는 이미 `findByMarketType(...).orElse(null)` + "Cafe24 기반(G마켓/옥션)은 cred 없어도 포트 위임" 주석으로 올바르게 처리하고 있었다. **발주확인 경로만 `.orElseThrow`로 누락**된 일관성 결함.
