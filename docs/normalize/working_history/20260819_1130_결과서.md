### 1. 배송메시지 인라인 편집 (표준 등급 — 다파일·기능 수정)

배송정보 칸에서 주소는 편집되는데 배송메시지는 읽기 전용 텍스트였다(`OrderGrid.tsx:1584`).
백엔드도 함께 열어야 했다 — `OrderUpdateRequest`가 `address`/`customsClearanceNo`만 받고 있었다.

| 파일 | 변경 |
|------|------|
| `api/dto/OrderUpdateRequest.java` | `message` 필드 + `toCommand()` 매핑 |
| `core/application/order/dto/OrderUpdateCommand.java` | `message` 필드 |
| `core/domain/order/Order.java` | `updateMessage(String)` 신설 |
| `core/application/order/service/OrderService.java` | `command.getMessage() != null`이면 적용 |
| `frontend/src/pages/OrderGrid.tsx` | 메시지를 `InlineInput`으로 + `selectAllOnFocus` 옵션 신설 |

**시맨틱은 주소와 동일하게 맞췄다**: `""` = 클리어, `null`(미전송) = 변경 안 함(F-ORD-23).
동기화 경로(`Order.update`)의 "빈값 거부" 가드와 혼동하지 말 것 — 그 가드는 마켓이 빈 메시지를
보내와 사용자가 적어둔 요청사항을 지우는 걸 막기 위한 것이고, 수동 경로는 사용자가
**의도적으로** 지우는 것이라 빈값이 통과해야 한다.

**클릭 시 전체 선택**(`selectAllOnFocus`): `select()`만으로는 부족하다 — 마우스 클릭은 focus
직후 커서를 놓아 선택을 푼다. `setTimeout(…, 0)`으로 클릭 처리 뒤에 선택한다.
주소에는 적용하지 않았다(긴 텍스트라 중간 클릭 편집을 막게 된다).

## 알아둘 것

**수동 편집한 배송메시지는 다음 마켓 동기화에서 덮일 수 있다.** `Order.update`는 마켓이 보낸
메시지가 비어 있지 않으면 그대로 덮어쓴다. 주소도 같은 성질이라 새로 생긴 문제는 아니지만,
"내가 고쳤는데 되돌아왔다"는 현상이 나오면 원인은 이것이다. 수동값을 지키려면 별도 보호
플래그가 필요하고, 그건 이번 범위 밖이다.
