## 6. 함정
- **`advance`는 상품을 고를 수 없습니다.** 반드시 `start` → ESM → `esm-confirm` → `advance?limit=새로 시작한 수` 한 번 순서로 합니다. 순서가 바뀌거나 두 번 돌리면 D-361 잔여 10개의 쿠팡 삭제가 승인 없이 다시 시도됩니다. 두 번째 회차가 필요하면 멈추고 따로 승인받습니다.
- `start`·`advance`의 `dryRun` 기본값은 `true`입니다.
- `esm-confirm`과 `advance`를 동시에 돌리지 않습니다.
- 63의 G마켓·옥션 리스팅이 ESM에 실제로 남아 있는지는 모릅니다(카페24가 먼저 지워진 상품). 사용자가 ESM에서 검색했을 때 없으면 "없음"도 확인입니다.
- 파일럿의 ESM 확인은 사용자의 "지웠음" 보고가 근거입니다. 세션이 검색 0건을 직접 보지는 못했습니다 — 이 세션에는 브라우저 도구가 없습니다.
- 퇴출 회차의 api 로그에는 ERROR가 남습니다(삭제 뒤 부재를 확인하는 조회의 404, 이미 지워진 쿠팡 상품의 삭제 응답). 파일럿에서 3줄이 그랬습니다. SQLState와 그 밖의 ERROR만 이상으로 봅니다.
- DB 시각 칸은 UTC입니다(KST − 9시간).
- 새벽 시간대(00:55, 02:00~04:30)를 피합니다.
