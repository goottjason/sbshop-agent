## 근본원인 (재확인)
`MarketClient.syncPriceAndStock`는 인터페이스·4개 구현체에 존재했으나 **호출처가 0** — `ProductManageUseCase.updatePriceStock`가 DB만 저장. 게다가 스토어·11번가만 실 API 호출, 쿠팡·카페24는 로컬 Map만 패치(실 API 없음), G마켓/옥션은 클라이언트 부재.

## 수정 (4계층)
1. **배선(핵심)**: `updatePriceStock` → DB 저장 후 `syncPriceStockToMarkets`가 MarketRegistration 순회하며 `syncPriceAndStock` 호출. D-049 이미지 재게시와 동일 규율(클라이언트 없는 마켓 스킵, 마켓별 부분 실패 수집·롤백 없음). marketItemId=D-052 `extractMarketCode()`.
2. **쿠팡 실 API**: 로컬 Map 패치 → `syncImagesAndHtml`과 동일한 전체 seller-product PUT 추가(dev 검증 패턴).
3. **카페24 실 API**: 로컬 Map 패치 → `publish`/`syncImagesAndHtml`의 `PUT /admin/products/{id}` 패턴(price/supply_quantity).
4. **컨트롤러/프론트**: 엔드포인트가 `MarketRepublishResult`(synced/skipped/failed) 반환, ProductPage가 마켓별 성공/실패 토스트 표면화.

## 핵심 결정과 이유
- **실 API를 dev 검증 패턴으로 구현**: 쿠팡/카페24의 기존 `syncImagesAndHtml`·`publish`가 이미 같은 엔드포인트·PUT 패턴으로 write하므로, 이를 그대로 미러링해 신규 계약 추정 위험을 최소화(쿠팡은 PUT 한 줄 추가 수준).
- **부분 실패 표면화**: 자사 DB 저장 성공해도 마켓 반영 실패를 토스트로 노출(조용한 실패 금지).
