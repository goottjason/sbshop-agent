## D-160 — 백필이 최근 주문을 거짓 취소 → 정산액이 0으로 굳는다

**인과 사슬**

1. D-159 백필이 30일 구간을 오래된 쪽부터 걸으며 구간마다 `syncCoupangOrders(from, to, false)`를 부른다.
2. `postSyncProcess`가 **조회 구간을 무시하고 언제나 `now-30d ~ now`**로 취소 감지를 돌렸다.
3. → 4월 구간 응답에 최근 주문이 없는 것을 "사라졌다"로 읽어 종결 전 주문을 전부 `CANCELED`로 만들었다.
   쿠팡 `detectCancellations`는 11번가 `detectClaims`(D-099)와 달리 **단건 조회로 확증하지 않는다.**
4. 뒤이어 D-098 정규화가 정산액을 **0 + verified**로 내렸다(설계대로 — 입력이 거짓이었을 뿐).
5. 마지막 구간이 **배송상태는 복원**했지만 **정산액을 되돌리는 주체가 없어** 0이 영구히 남았다.

**증거**: `sb_action_log` 2026-08-08 13:30:32 / 13:31:06 / 13:31:45 / 13:32:07 `COUPANG_SYNC` 4연속
(이어 스토어4·11번가4·G마켓2)이 원장의 *"D-159 라이브 검증 — 쿠팡4·스토어4·11번가4·G마켓2"* 와 일치.
피해 행의 `updated_at`(13:32:06)은 **상태를 복원한 마지막 구간**의 커밋 시각이다.

**핵심은 비대칭이었다** — 배송상태는 매 동기화가 되살리는데 정산액은 되살리는 주체가 없다.

**수정 3층**

| 층 | 내용 | 이유 |
|---|---|---|
| 사정거리 | `postSyncProcess`가 **실제 조회 구간**을 받는다 | 부재 추론은 조회한 범위에서만 유효하다 |
| 권한 | 갱신 전용(`createMissing=false`, 백필)은 취소·반품 감지를 **하지 않는다** | 백필은 값을 채우러 가지 상태를 판정하러 가지 않는다 |
| 복구 | 종결 전인데 정산 0이면 마켓 값으로 되살린다 (`recoverSettlement`, verified 해제) | 손상이 다시 생겨도 스스로 낫는다 |

부분 조회 실패도 같은 근거 붕괴다 — `CoupangOrderAdapter.FetchOutcome(orders, complete)`을 신설해
**못 본 것을 사라진 것으로 읽지 않는다.** 종전엔 부분 실패를 경고 로그로만 남기고 조용히 반환했다.

정산액 산출을 `MarketLineItemSyncPolicy.settlementAmount(dto)`로 뺐다. 종전엔 `createLineItem` 안에만
있어 **생성 시점 한 번**만 계산됐고, 그래서 복구할 방법 자체가 없었다(D-136 잔여 #1과 같은 뿌리).

## D-161 — 11번가가 준 `prdNo`를 버리고 있었다

- `claimservice/orderlistall` 라이브 응답(2026-08-06 픽스처): 순번2 `<prdNo>6124097725</prdNo>`
- 운영 DB `sb_market_registration` id 9439 → `{"sellerPrdCd":"230806IHB154","prdNo":"6124097725"}` → **상품 2500**
- 사용자가 말한 값과 정확히 일치한다.

`StatusRow`가 `prdNo`·`prdNm`을 읽지 않았고, `elevenstResolveProductId`는 `sellerPrdCd` 한 경로뿐이었다.
**순번1이 멀쩡한 이유**: 07-31 결제완료 단계엔 전체 정보 목록이 `sellerPrdCd`를 줬다. 순번2는 3계층
전환(08-06) 때 처음 로스터에 올랐는데 그 주문은 이미 배송중이라 그 목록에 없었다.

수정: `StatusRow`에 `prdNo`·`prdNm`을 싣고 `prdNo → sb_market_registration` 폴백을 추가(쿠팡
`vendorItemId` 경로와 동형). 순서는 뒤집지 않았다 — `sellerPrdCd`는 우리가 발급한 코드라 더 권위 있다.

**수동 DB 교정이 필요 없다**: 골격의 `applyLineItem`이 다음 동기화에서 474의 `product_id`를 스스로 채운다.
