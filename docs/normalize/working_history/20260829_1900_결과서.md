## 스키마 변경 (중대 등급)

```sql
ALTER TABLE sb_market_registration ADD COLUMN IF NOT EXISTS unsync_reason VARCHAR(32);
```

추가·nullable 이라 가역적이다. `ddl-auto: update` 이므로 배포 시 자동 생성도 되지만, 결정성을 위해 **수동 선행**했다.

백필은 확실히 판별 가능한 행만 했다.

| 구분 | 건수 |
|------|------|
| `is_synced=false` 전체 | 2,024 |
| ↳ `NEVER_SYNCED` 백필(식별자 없음 + 동기화 이력 없음) | 3 |
| ↳ **미분류(NULL) 유지** | **2,021** |

2,021건을 추측으로 채우지 않았다. **틀린 사유는 사유 없음보다 나쁘다** — `DELETED_ON_MARKET` 으로 오판하면 D-223 가드가 그 상품의 중복 등록을 허용해 정확히 막으려던 사고를 부른다.

## 핵심 결정과 이유

**1. 사유 미분류 행에 게시 가드를 적용하지 않았다.**
막는 쪽이 안전해 보이지만 2,021건의 재등록이 전부 불가능해진다. 통과시키되 경고 로그를 남긴다. 실피해가 큰 `is_synced=true` 는 확실히 막히므로 D-223 의 목적은 달성된다.

**2. 분류 실패를 `TRANSIENT_ERROR` 로 떨어뜨렸다.**
마켓이 에러 문구를 바꾸면 삭제 감지를 **놓치는** 방향으로 새고, 살아있는 상품을 삭제로 **오판하는** 방향으로는 새지 않는다. 오판 비용이 비대칭이라 안전한 쪽으로 기울였다.

**3. 식별자를 지우지 않고 보존했다.**
`replaceIdentifiersArchivingPrevious` 가 이전 값을 `previousIdentifiers` 배열에 쌓는다. 원장 D-222 의 원칙("식별자는 지우지 않는다 — 지우면 해결이 아니라 안 보이게 되는 것")을 게시 경로에도 적용했다.

**4. `MarketRegistrationResponse` 에 필드를 추가했다.**
계약 테스트(`ResponseDtoContractTest`)가 엔티티↔DTO 바이트 동일성을 검사해 정확히 이 누락을 잡았다. 결과적으로 D-222(배지 분리)의 재료가 프론트까지 이미 내려간다.

## 라이브 검증에서 잡힌 자책 결함 (중요)

배포 후 실제 데이터로 확인하다 **이번 수정이 만든 결함**을 발견했다. 단위 테스트 14건이 전부 통과했는데도 빠져나간 종류다.

**증상**: 실패 사유를 기록하려고 catch 에서 `markSyncFailed(reason)` 을 불렀는데, 이 메서드는 사유만 쓰는 게 아니라 `is_synced` 도 뒤집는다. 쿠팡 `"해당 상품은 심사가 진행중입니다"` 로 실패한 8건이 미동기로 전환됐다 — **상품은 마켓에 멀쩡히 있는데도.**

**파급**: ① 배지 미등록 표시 ② D-225 스킵 로직이 영구 제외 → 바코드가 영영 안 들어감 ③ **D-223 가드 무력화** — 미동기는 가드를 통과하므로 유령 리스팅 생성 가능. **같은 커밋에서 만든 가드를 같은 커밋의 다른 변경이 뚫었다.**

**수정**: 바코드 경로에서 `is_synced` 를 뒤집는 것은 `DELETED_ON_MARKET`(마켓에 없다는 증거가 있을 때) **뿐**. 검증 실패·일시 오류는 응답·로그로만 보고한다.

**데이터 복구**: 훼손된 8건(상품 1·43·45·46·52·53·56·59 쿠팡행)을 `is_synced=true`, `unsync_reason=NULL` 로 되돌렸다. 확인 결과 사유 기록은 백필한 `NEVER_SYNCED` 3건만 남았다.

**왜 테스트가 못 잡았나**: 내가 쓴 테스트는 "삭제 실패 시 사유가 기록되는가" 만 물었고 **"삭제가 아닌 실패에는 무엇이 일어나면 안 되는가"** 를 묻지 않았다. 부정 명제를 빠뜨렸다. 회귀 2건 추가(`transientFailure_doesNotFlipIsSynced`, `validationFailure_doesNotFlipIsSynced`).

**교훈**: `is_synced` 는 "마켓에 있는가", `unsync_reason` 은 "없다면 왜". **후자를 쓰겠다고 전자를 건드리면 판정이 오염된다.** 사유를 남기는 것과 존재를 부정하는 것은 다른 일이다.
