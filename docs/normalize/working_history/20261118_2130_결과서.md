## 핵심 결정
- 대상은 `sbshop` DB 하나. `canagent`는 읽지도 않는다. 그래서 전역 `pg_read_all_data` 대신 DB 단위로 권한을 줬다.
- cron 00:55 — 주문 동기화가 매시 :00~:50(5분 간격)에 돌아 :55만 비고, 일일 작업 02:00~05:00과 OS 타이머 00:00·00:07을 피한다.
- 보관은 파일 개수가 아니라 날짜로 센다(같은 날 여러 번 뜨면 이전 날짜가 밀려나던 문제를 같은 날 보완).
- `sbshop_ro`는 실수 방지 장치다. 읽기 전용 기본값은 세션이 끌 수 있지만 쓰기 권한이 없어 운영 데이터는 못 바꾼다. 관리 계정(`goottjason`)도 서버 안에서는 비밀번호 없이 접속되므로 일부러 쓰는 것은 막지 않는다 — 그건 쓰기 도구(04 §14 계층 2)의 몫.

## 사용자 결정 (2026-11-18)
- 서버 밖 사본은 사용자 PC 내장 HDD(외부 클라우드 안 씀). 보관 용량은 충분 — 11개 이상 둬도 된다.
- 가격·배송비·최종가 반영이 가장 중요하지만, 판매 뒤 주문마다 마진을 계산하고 진행하므로 가격 실수는 어느 정도 만회 가능하다 → 가격 반영 경로 전수 검토는 급하지 않음.
- 보관 규칙 보완 승인. 원장 커밋 푸시 승인.
