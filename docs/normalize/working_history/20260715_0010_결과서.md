## 핵심 결정과 이유
- **상태 기록 REQUIRES_NEW**: sync 본체 트랜잭션이 롤백돼도 FAILED 상태가 독립 커밋으로 보존 → 재시도/모니터링 근거 유지.
- **자기기록으로 이동**: @Async 경계 때문에 상태는 반드시 async 스레드 안(서비스 본문)에서 찍어야 진실됨. 스케줄러(호출자)에서 찍으면 조기/무효.
- **ddl-auto=update (사용자 결정)**: 수동 DDL 위험을 2회 고지했으나 편의 위해 사용자가 자동반영 선택. `update`로만 설정(추가만; create/create-drop=데이터삭제라 금지). `DDL_AUTO` env로 오버라이드 가능. → `sb_market_sync_status`는 배포 시 자동 생성(수동 DDL 불필요). [[user-working-style]] 갱신함.
