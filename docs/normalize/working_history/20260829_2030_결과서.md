## 착수하자마자 진단이 뒤집혔다

딥다이브 §6.1 에 "백엔드는 제대로 내려보낸다" 고 써 두었는데 **틀렸다.** `MarketBadgeState.of(synced, url)` 의 **선언만 보고 호출부를 안 봤다.**

```java
// ProductController.buildMarketMap
boolean synced = reg.hasIdentifiers();   // is_synced 가 아니다
```

`is_synced` 는 배지 판정에 아예 참여하지 않고 있었다. 상품 44 증상의 직접 원인이다. 문서 §6.5 에 정정을 남겼다.

## 배지 판정 규칙

| 조건 | status | 배지 | 클릭 |
|------|--------|------|------|
| `DELETED_ON_MARKET` | `DELETED` | 빨강(#fee2e2/#dc2626) | **재등록** (D-223 가드가 통과시킨다) |
| `VALIDATION_FAILED`/`TRANSIENT_ERROR` | `FAILED` | 주황 + 사유 툴팁 | 마켓 페이지 열기 |
| 사유 없음 + 식별자 있음 | `SYNCED` | 기존 | 마켓 페이지 열기 |
| 사유 없음 + 식별자 없음 | `PENDING` | 기존 | 없음 |

**사유 없는 미동기 행은 건드리지 않았다.** 기존 테스트가 "레거시 임포트 행을 거짓 미완료로 경고하지 않는다"는 의도적 결정을 박아 두었고, 미분류 2,021건이 여기 해당한다. 다 경고로 칠하면 화면이 뒤덮이고 그 대부분이 거짓이다.

## 배지만 고쳐선 아무것도 보이지 않았다

다 만들고 데이터를 보니 `DELETED_ON_MARKET` 보유 행이 **0건**이었다. 두 수정이 맞물린 함정이다.

```
D-225: is_synced=false 는 전송에서 건너뛴다   (죽은 등록에 API 낭비 방지 — 옳다)
  → 죽은 등록은 마켓 응답을 받을 기회가 없다
  → "이미 삭제된 상품입니다" 를 들을 수 없다
  → DELETED_ON_MARKET 이 기록될 수 없다
  → 배지가 영원히 갈리지 않는다
```

**건너뛰기가 옳고, 그 옳음이 분류를 막는다.** 그래서 `MarketRegistrationProbeService` 를 함께 만들었다 — 미분류 미동기 행을 마켓 단건 조회로 확인해 **삭제가 확정된 것만** 기록한다. 살아 있으면 아무것도 쓰지 않고, 판정 불가는 `INCONCLUSIVE`. **한 방향으로만 쓴다.**

`POST /internal/registrations/probe?market=&limit=&throttleMs=&dryRun=`

요청 범위(배지 시각 분리)를 넘는 판단이었다. 이것이 없으면 D-222 가 **작동하지 않는 기능**이 되기 때문이다. [[D-227]] 의 축소판임을 원장·문서에 명시했다.

## 라이브 프로브가 잡아낸 분류기 버그

첫 프로브 결과가 `DELETED 1 / ALIVE 5 / INCONCLUSIVE 14` 였는데 **15건의 응답 메시지가 완전히 동일**했다(`Product(...) data not found.`). 같은 입력에 다른 판정 — 비결정적이다.

원인: `DELETED_MARKERS` 의 `"404"`. 상품번호 `14813281404` 에 우연히 404 가 들어 있었다. **숫자 상태코드를 문자열로 매칭했는데 그 메시지가 상품번호를 품고 있었다.**

오판의 대가가 크다 — `DELETED_ON_MARKET` 은 D-223 가드를 **통과**하므로 중복 리스팅을 만든다. D-224 에 "틀린 사유는 사유 없음보다 나쁘다"고 적은 경로가 실제로 열렸다.

**수정**: 맨 숫자 마커 제거 → `"400 Bad Request"`·`"404 Not Found"` 로 이유구까지 포함. 쿠팡의 실제 삭제 신호 `"data not found"` 를 DELETED 마커에 추가(쿠팡 API 직접 조회로 5/5 실재 부재 확인 후 반영). 회귀 3건 추가.

**재실행 결과: `DELETED 25 / ALIVE 5 / INCONCLUSIVE 0`.**

## 검증을 가로막은 것 — D-230

배포 후 화면이 안 바뀌어 한참을 헤맸다. 서버 번들에는 새 코드가 있는데 브라우저는 낡은 청크를 로드하고 있었다.

- 브라우저: `index-DaQUVVX_.js` / `ProductGrid-CrHr8p82.js`
- 서버: `index-DFHcJhpE.js` / `ProductGrid-BMleJyAz.js`

`curl -I` 로 확인하니 `index.html` 응답에 **`Cache-Control` 헤더가 없다.** 브라우저가 `Last-Modified` 기반 휴리스틱 캐싱으로 index.html 을 재사용하고, 그 index 가 옛 해시를 계속 가리킨다.

**이건 이번 검증만의 문제가 아니다.** 프론트를 배포해도 기존 사용자에게 강제 새로고침 전까지 반영되지 않는다. D-230 으로 등재했고, 인프라(repo 밖) 수정이라 사용자 승인 대기.
