## 결함 진단 (D-103)

**증상:** 오랜만에 접속하니 Cafe24 리프레시 토큰 만료/무효. 리프레시 토큰이 유효할 때도 자동 갱신이 안 됐던 것으로 의심.

**근본 원인 (확정):** 토큰 갱신이 **주문동기화 API 트래픽의 부산물로만** 일어남 — 트래픽 독립적 안전망 부재.
- `Cafe24TokenManager.getValidAccessToken()`(`:49-78`)은 `isTokenValid()`로 **액세스 토큰(2h) 만료 임박만** 검사 → 이때만 `doRefresh()`가 리프레시 토큰을 회전.
- Cafe24 전용 토큰 갱신 스케줄러 부재(스케줄러 인벤토리 확인 — 30분 주문동기화 외 없음).
- Cafe24 리프레시 토큰은 유효 2주·refresh 때마다 회전/연장 → **API 호출 공백 ≥2주면 만료→재인증 외 복구 불가**.
- 부차: `refresh_token_expires_at` 추적 전무(엔티티/파서/응답) → 2주 시한을 시스템이 모름.

**관련 코드:** `Cafe24TokenManager.java:49-110` · `OrderSyncScheduler.java`(유일 트리거) · `MarketCredential.java`(만료추적 필드 부재) · `Cafe24OAuthTokenHttpClient.java`(refresh_token_expires_at 미파싱).
