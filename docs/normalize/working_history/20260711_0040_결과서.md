## 진단 요약 (Explore ×2 병렬)

- **주문-상품 매핑**: 백엔드 조인은 정상(`OrderRepositoryImpl.searchOrderGrid`가 productId로 Product 조회). 상품코드가 화면에 뜨므로 `product`는 null 아님 → **원인은 프론트 접근 경로**. `Product.productName`/`originalName`은 flat String인데 프론트 `ProductDto`가 중첩 객체로 오정의, `product.productName.productName`으로 접근해 undefined. 소싱 URL도 `sourceUrl`인데 `url`로 접근.
- **시간대**: 모든 시간 필드가 zone 없는 `LocalDateTime` + 컨테이너 UTC → JSON에 zone 미포함 직렬화. 프론트 `new Date()`가 UTC 벽시계값을 그대로 표시(9h 이른 "미국시간"). `spring.jackson.time-zone`은 LocalDateTime에 무효 → 프론트에서 UTC 간주·KST 변환이 가장 견고(기존+신규 데이터 일괄 교정).

## 핵심 결정과 이유

1. **시간대 수정 범위를 서버감사시간에 국한**: ProcessStatus.startedAt·ActionLog.createdAt(서버 `LocalDateTime.now()`=UTC 컨테이너)만 KST 변환. **주문일시(orderDate)는 제외** — `CoupangOrderAdapter.java:198` 등 마켓 어댑터가 한국 마켓 API의 KST 문자열을 `LocalDateTime.parse`로 naive KST 저장하므로 이미 정확. 일괄 변환 시 마켓주문시간이 +9h 어긋남. (서버시간 UTC vs 마켓시간 KST의 의미 혼재를 구분.)
2. **호버는 React state → DOM 이벤트위임**: state 방식은 매 호버마다 전 그리드 리렌더가 지연 원인. ref+클래스 토글로 리렌더 제거, 다른 주문 그룹 진입 시에만 querySelectorAll(같은 그룹 early-return). frozen 셀 인라인 배경은 `> td { !important }`로 덮음.
3. **상품그리드 디자인**: 기존 ag-grid 오버라이드가 미사용 테마(`.ag-theme-alpine`)에 걸려 무효였음 → 실제 테마 `.ag-theme-quartz`에 `.sb-product-grid` 스코프로 재적용(타 그리드 무영향).
