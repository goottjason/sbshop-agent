## 3. 이번 세션에서 확인한 사실
- **서버 접속:** 이 PC에서는 Git에 들어 있는 `C:\Program Files\Git\usr\bin\ssh.exe`/`scp.exe`와 저장소 루트의 키 파일로 접속합니다. 키 파일은 `.gitignore`의 `*.key`로 제외돼 있습니다. 호스트 주소는 PC 홈 폴더의 `ops-backup\sbshop-db-pull.ps1`에 있는 `$Server`에 있습니다. Windows 기본 OpenSSH는 키 파일 권한 문제로 접속을 거부합니다.
- **원격 heredoc 함정:** `ssh … 'bash -s' <<EOF` 안에서 `docker exec -i … psql -c …`를 쓰면 psql이 heredoc의 나머지를 stdin으로 먹어서 스크립트가 중간에 끊깁니다. `-c` 호출에는 `</dev/null`을 붙입니다.
- **배치 상태 컬럼:** `sb_supplier_batch_run`의 상태 컬럼 이름은 `state`입니다. 인계서 `0030`의 "`RUNNING`·`PAUSING`" 조회는 `WHERE state IN (…)`으로 씁니다.
- **api 헬스 확인:** 8080 포트는 호스트에 노출돼 있지 않습니다. 확인은 `docker exec projects-sbshop-api-1 curl … localhost:8080/internal/health`로 합니다.
- **`mkdir -m 700 -p a/b`:** 권한 700은 `b`에만 적용됩니다. README 설치 명령에 `chmod 700 ~/ops-write`를 추가했습니다.
- **서버 상태:** 디스크 여유 26G(73% 사용). 같은 서버에 `fortunecannele-postgres`와 `nextlisting-postgres` 컨테이너가 있는데, 이 프로젝트 것이 아니니 건드리지 않습니다.

## 5. 함정
- **이 인계서 커밋은 푸시하지 않았습니다.** 문서만 들어 있어 배포는 일어나지 않지만, 푸시는 승인 사항이라 다음 세션에서 승인을 받거나 다음 푸시에 같이 올립니다.
- **도구 파일을 고치면 해시가 바뀝니다.** 그때는 단위 게이트, 서버 임시 DB 통합 시험(원장 D-364에 절차가 있음), 서버 재설치, 해시 대조를 다시 해야 합니다. 이 폴더의 줄 끝은 `.gitattributes`로 LF로 고정돼 있습니다. CRLF로 바뀌면 서버 설치본과 해시가 달라집니다.
- **고정 결정(K1~K14)을 바꾸지 않습니다.** 실제로 써 보다가 설계가 맞지 않는 상황이 나오면 고쳐 쓰지 말고 멈춥니다. 그때는 페이블이 필요합니다.
- **하위 에이전트:** 넘기기 전에 스테이징하고, 에이전트마다 전용 임시 폴더를 쓰게 하고, 삭제하는 코드는 경로를 assert로 확인하게 합니다. 서버 접속은 주 세션만 합니다.
- **`_workspace/`는 이 PC에만 있습니다.** git에는 없습니다.
