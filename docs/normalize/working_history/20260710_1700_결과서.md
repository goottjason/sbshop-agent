## 처리 결함

### D-052 (P1) — 상품 그리드 마켓별 연동코드가 쿠팡만 표시 · 나머지 '미확인' [수정완료, 검증대기]

- **근본원인**: `ProductController.buildMarketMap`이 **모든 마켓**의 코드를 쿠팡 전용 `MarketRegistration.extractVendorItemId()`(marketIdentifiers의 `vendorItemId` 키)로 읽음. 스토어(`originProductNo`)·11번가(`elevenstId`)·카페24(`product_no`)는 그 키가 없어 상시 null→`productId` 폴백→프론트 '미확인' 배지.
- **수정(행위)**: `MarketRegistration.extractMarketCode()` 신설 — marketType별 실제 키 분기(코드로 각 마켓 클라이언트 저장키 확인: Coupang=vendorItemId→sellerProductId, Smartstore=originProductNo, Elevenst=elevenstId, Cafe24=product_no→product_code, ESM+=goodsNo→itemNo→goodsCode). `buildMarketMap`이 이를 사용. 프론트 '미확인' 툴팁 일반화(D-046 한정 문구 제거).
- **테스트**: `MarketRegistrationExtractMarketCodeTest`(마켓별 키 + 스토어 코드가 vendorItemId 조회로는 null이나 extractMarketCode로는 해결되는 회귀 재현).
- **판정**: 리더 게이트 PASS. 라이브 표시 확인은 사용자 대기(4마켓 키는 소스 확인 완료).

### D-045c (P1, 진단강화) — ESM+ 로그인 실패 원인 확정용 HTML/캡차 힌트 로깅 [배포됨]

- **라이브 결과**: 사용자 재동기화 시 힌트 "캡차 미감지 — 자격증명 오류 가능성" 노출됨.

## 라이브 진단 결과 (사용자 협조 — DB 읽기·브라우저 로그인)

### (1) ESM+ 로그인 — 자격증명은 유효, 원인 미확정
- 사용자 브라우저로 `shouldbeshop`/`Mimi1570!!` 로그인 **성공** → 자격증명 자체는 유효.
- 따라서 Selenium 실패 원인은 **(a) DB에 저장된 값이 다름(stale)** 또는 **(b) ESM+ 봇 감지** 중 하나로 좁혀짐. `loginFailureHint`의 "자격증명 오류 가능성"은 캡차 미감지 기반 휴리스틱이라 (b)와 구분 불가.
- **결정적 테스트(사용자 대기)**: 설정→G마켓·옥션 탭에 자격증명 **재저장** 후 재동기화. 그래도 같은 실패면 (b) 봇 감지 확정 → Selenium 우회조치(navigator.webdriver 제거 등) 필요.

### (2) 지마켓/옥션 상품코드 — "매핑 실패"가 아니라 "데이터 부재" (확정)
- 라이브 DB 조회: `sb_market_registration` 마켓별 건수 = **CAFE24 3185 / SMART_STORE 3183 / ELEVEN_STREET 2286 / COUPANG 1261, GMARKET·AUCTION 0건**.
- 전체 테이블 11개 확인 — 마켓코드 저장처는 `sb_market_registration`뿐, 레거시 매핑 테이블 없음. `sb_product`에도 마켓별 코드 컬럼 없음.
- 코드상 **ESM+ 상품 연동 경로 부재**(발행 클라이언트 4개뿐, ESM+는 주문 스크래핑 전용) → 지마켓/옥션 상품 등록이 생성된 적이 없음.
- **사용자 가설(유력)**: 카페24 호스팅의 원본 `market_registration` 테이블이 진짜 소스인데 **이 DB로 마이그레이션 누락**. 사용자가 원본 확인 후 회신 예정 → 확인되면 GMARKET/AUCTION 임포트 스크립트 작성.
