## 1. F-BATCH-6 — 크롤 배치 쿠폰율 미적용 (`cfb8fa9`)

**버그:** `crawlAndUpdatePriceStock`가 couponRate를 받고도 판매가 계산에 미적용 → 실매입가를 낮추지 못해 판매가 과대.
**수정:** `MarginCalculator.calculateSalePrice(...couponRate...)` 오버로드 — 실매입가=구매가×(1-쿠폰%)로 판매가 산정.
**효과(구매가 10,000·쿠폰20%·마진10%·최소마진3,500):** 판매가 22,400 → **19,600**. couponRate 0·null이면 종전과 동일(하위호환).
**⚠️ 배포 영향:** 배치 실행 시 판매가 하락. 기본 couponRate=20% 전상품 일괄. (상품별 쿠폰율은 미구현 — 필요 시 후속.)

## 2. F-SYNC-4/F-ORD-32 — 마켓별 정산 수수료율(FeePolicy) + 이중차감 제거 (`d58a8c1`)

**버그 A(이중차감):** 정산액이 sync(총액×0.89) → ship(×0.89 재적용) 두 번 곱해져 쿠팡·Cafe24는 ~21% 차감.
**버그 B(요율 뭉뚱그림):** 전 마켓에 flat 0.89(쿠팡 11%) 적용 → 스토어(8%)·11번가/G마켓/옥션/Cafe24(18%) 무시.

**수정:**
- 신규 `MarketFeeService`: 정산액=총액×(1-요율/100)을 **FeePolicy(`sb_fee_policy`) 조회**, DB에 없으면 `SettlementPolicy` 코드 기본값 폴백.
- 정산을 **sync에서 마켓별 1회만** 적용(4개 sync 서비스). `OrderShipService`의 ship-time 재적용(이중차감) **제거**.
- 쿠팡 실정산 API 값 override(`applySettlement`)는 보존. `FeePolicyRepository` 신규.

**사용자 확정 요율:** 쿠팡 11 · 스마트스토어 8 · 11번가·G마켓·옥션·Cafe24 18 (%). (Cafe24는 G마켓/옥션 동기화 매개체라 동일 18%.)

**⚠️ 배포 영향 — 신규 동기화되는 주문 정산액 변동 (10,000원 라인 기준):**

|------|:---:|:---:|:---:|:---:|
| 쿠팡 | 11% | 7,921 (이중) | **8,900** | +979 ↑ |

- 소급 아님: 이미 저장된 주문 정산액은 그대로. 재동기화되는 주문부터 적용.
- 11번가만 정산액 하락(종전 11%→실제 18%). 나머지는 이중차감/과대수수료 해소로 상승.
