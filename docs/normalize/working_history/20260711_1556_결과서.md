## 핵심 결정과 이유
1. **INV-3 직렬화 가설 기각**: Spring Boot 기본 Jackson(JavaTimeModule, write-dates-as-timestamps=false)이 LocalDate를 ISO 문자열로 직렬화하므로 직렬화는 원인 아님. 남은 원인은 크롤 파싱 실패 또는 null 소거 → 안전한 null-guard(D-065)로 대응, 크롤 파싱은 라이브 근거 없이 미변경.
2. **scout 스마트스토어 상태코드 환각 정정**: scout가 제시한 `PLACE_ORDER_COMPLETED`/`IN_PROGRESS` 등은 네이버 표준 productOrderStatus 아님. 실재 확인된 표준 2코드(PAYMENT_WAITING, CANCELED_BY_NOPAYMENT)만 추가하고 default UNKNOWN+warn 유지로 이명동 실코드 라이브 노출 경로 보존(D-068).
3. **11번가 실경로 확정**: SyncService는 fetchOrders만 호출 → 배송중 주문은 parseShippingElement 경유(psnCscUniqNo 없던 곳). getElementText가 태그부재 시 ""를 반환하는 계약 발견 → emptyToNull 정규화로 기존 통관번호 빈값 덮어쓰기 회귀 차단(D-066).
4. **D-061 정정 재확인**: 배송 전파 배선은 코드상 존재(정정 맞음). 사용자 재신고 주원인은 D-068(UNKNOWN→400 차단), 부차는 D-069(마켓 실패 예외전파→롤백). D-069는 예외를 결과로 표면화해 배송정보 저장을 마켓 전송과 분리.
5. **Cafe24 PCCC 필드명 미확정**: 문서가 JS SPA라 텍스트 확정 불가 → 방어적 다중필드 + 미검출 시 노드키 debug 로깅으로 라이브 확정 경로 마련(D-067).
