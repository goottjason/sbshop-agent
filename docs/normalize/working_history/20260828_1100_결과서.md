## 3. D-220 수정 (표준 → 스키마 변경으로 중대)

`docs/normalize/defect-ledger.md`의 D-220 항목 참조. 요지:

- `MarketSyncStatus` + `processed_count`·`new_count`·`last_new_at`
- `SyncCounts(processed, created)` 신설 — 5개 마켓 전부 처리/신규 분리 집계
- 액션로그 `동기화 성공 — 처리 N건, 신규 M건`, 신규 0건이 임계 초과 지속 시 `{MARKET}_SYNC_STALE` + `ActionStatus.WARNING`
- `SyncFreshnessPolicy` 마켓별 임계 — G마켓/옥션 10일, 쿠팡·스토어 2일, 11번가 7일, 기본 7일

### 핵심 결정과 이유

- **신규 0건 회차는 `lastNewAt`을 갱신하지 않는다.** 덮으면 공백 측정 기준선이 사라져 경고가 영원히 안 뜬다.
- **임계를 마켓별로 갈랐다.** G마켓/옥션은 전체 16건뿐인 저volume 채널이라 단일 짧은 임계는 정상 무판매에도 상시 경고를 낸다. 상시 경고는 아무도 안 본다.
- **건수 없는 1-arg `markCompleted`는 기존 건수를 지우지 않는다.** 쿠팡 정산 경로가 이 오버로드를 쓴다.
- **갱신 전용 모드에서 건너뛴 주문은 처리·신규 어느 쪽에도 세지 않는다.** false 성공 방지.

구현 후 **행위만 되돌려** 측정(성공 메시지 상수화 + stale 조기 return + created를 false로) → `11 tests completed, 3 failed`. 컴파일 에러가 아니라 단언 실패로 확인.
