# 2026-07-18 14:48 결과서 — 이메일 수집 효율화(라우팅+SEARCH) + 내부트리거 보안회귀 수정

## 개요
30분 스케줄러 이메일 수집이 "대기주문 N × 계정 9 = N×9회 IMAP 접속, 각 접속마다 최근 1000통 헤더 다운로드 후 앱에서 제목 필터"로 비효율이었다. **소싱계정 라우팅(③) + 서버측 IMAP SEARCH(②)**로 재작성해 접속·조회량을 대폭 줄였다. 검증 중 발견한 Spring Security의 `/internal` 403 회귀도 수정했다. 관련 [[email-accounts-expansion]] · [[iherb-email-tracking-pipeline]].

## 처리 내용
| 구분 | 내용 |
|------|------|
| perf(③ 라우팅) | `EmailFetcherService.buildSearchPlan/resolveTargetAccounts` — 주문의 `sourcing_account`로 검색 메일함을 좁힘. Gmail 소싱분→중앙(자동전달), 비-Gmail→해당 제공자, 미상·미설정→전계정 폴백. N×9 접속→계정별 1회. |
| perf(② SEARCH) | 최근 1000통 다운로드 대신 `SubjectTerm(주문번호)`로 서버가 매칭 메일만 반환(숫자=ASCII, charset 무관). 발송/확인 경로 모두 적용. 스캔창(INBOX_SCAN_WINDOW) 및 테스트 제거. |
| fix(security) | `SecurityConfig`가 `/api/v1·/api/admin·docs`만 permitAll하고 `anyRequest().authenticated()`라 `/internal/**` 무인증 트리거가 403 회귀(마켓인증 도입 여파). `/internal/**` permitAll 추가 — `InternalAccessGuard` 토큰 가드에 위임. 사용자 승인. |
