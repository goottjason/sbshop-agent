## 근본원인·수정
- **D-075**: `Cafe24TokenManager.getValidAccessToken()`이 refresh 실패에도 null 반환 → `Cafe24RestClient`가 "Bearer null"로 호출 → 401 → `RuntimeException("Cafe24 API 호출 실패")` 래핑으로 원인 은폐. 수정: (CF24-2) 토큰 null이면 즉시 IllegalStateException("재인증 필요") throw. (CF24-3) RestClient가 HTTP status/본문을 메시지에 포함 + SyncService가 root cause chain을 errorMessage에 결합 → 진행현황에 실제 사유 노출.
- **D-076**: 활동로그 인프라(ActionLog/ActionLogService/ProcessStatusPage) 존재하나 4개 마켓 동기화만 커버. 미커버 24 엔드포인트(통관검증·재고·구매/배송정보수정·주문확인/취소/발송/삭제·상품수정/이미지/삭제/등록/게시·소싱·배치·자격증명·Cafe24재인증)에 `record()` 삽입. 신규 `ActionLogConstants`(26 상수 단일출처). 동기 수정=결과만, 비동기/장시간=STARTED+결과. **FAILED 기록 후 예외 재throw로 기존 에러 응답 보존**. S1~S4 이중기록 금지. 프론트 ProcessStatusPage에 한글 라벨 맵 추가.
