## SP-A — 마켓 연동·인증 (Cafe24 토큰)

- [ ] **설정 페이지**: 탭이 쿠팡/스마트스토어/11번가/카페24 4개만, ESM+ 탭 없음.
- [ ] **Cafe24 탭 상태 배지**: "정상 연동 중" 또는 "재인증 필요"가 정확히 표시.
- [ ] **토큰 유실 무재발(핵심)**: G마켓/옥션 주문 동기화 스케줄러(10/30분 주기)를 수 사이클 관찰 → `invalid_access_token` 오류가 **재발하지 않아야** 함. (worker 로그에서 `❌ Cafe24 토큰 갱신 실패`가 반복되지 않는지.)
- [ ] **재시작 시 refresh 회전 최소화**: 컨테이너 재시작 로그에 `✅ Cafe24 자격증명 확인됨 — 토큰은 최초 사용 시…`가 뜨고, 두 JVM이 startup에 강제 refresh를 안 하는지(로그에 refresh 호출이 기동 즉시 2번 찍히지 않음).
- [ ] **DB 확인(선택)**: `sb_market_credential`의 CAFE24 행에 `access_token`·`token_expires_at`이 채워지는지(이전엔 인메모리만).

## SP-B — 가격/재고·품절

- [ ] **상품관리 → 가격/재고 수정 모달**: 수량 입력칸 대신 **판매중/품절 토글**(Switch)이 있고, 판매가 min=0.
- [ ] **품절 처리(핵심)**: 한 상품을 품절로 토글·저장 → 진행현황/토스트에 마켓별 결과. **어떤 마켓에도 수량 0이 전송되지 않아야** 함(수량은 품절 시 1, 판매중 999).
  - 쿠팡: 판매중지 API(`/sales/stop`) 호출됐는지 — **라이브 미검증 항목**(실 엔드포인트 확인).
  - 스마트스토어: `status:OUTOFSTOCK`로 반영됐는지.
  - 11번가: `stopdisplay` 호출.
  - Cafe24: `selling:F` 반영됐는지 — **라이브 미검증 항목**.
- [ ] **판매중 복귀**: 다시 판매중 토글 → 각 마켓 판매재개.
- [ ] **실패 표면화**: 실패한 마켓이 진행현황에 사유와 함께 뜨는지(조용한 성공 위장 없음).

## SP-C — 이미지 파이프라인

- [ ] **소스이미지 크롤 버튼(iHerb 상품 상세)**: 클릭 시 **확인 다이얼로그**(Popconfirm) → 진행 시 크롤→R2 업로드→마켓 반영이 **원클릭**으로 일어남(예전의 "URL로 등록" 2단계 불필요).
- [ ] 결과 토스트에 마켓별 성공/실패.
- [ ] **스마트스토어 다중이미지(최우선 라이브 확인)**: 실제 스마트스토어 상품에 대표+추가이미지(optionalImages)가 **반영되는지**. ⚠️ 필드 형태(문자열 vs `{url}` 객체)가 틀리면 API가 200을 주면서 **조용히 무시**할 수 있음 — 스마트스토어 관리자에서 이미지가 실제로 바뀌었는지 눈으로 확인.
- [ ] **11번가**: 상세설명(HTML) 이미지가 `updateProductDetailCont`로 반영되는지(대표이미지 prdImage01은 범위 밖).
- [ ] **쿠팡**: 이미지 변경이 승인요청(재심사)로 걸리는지 — 쿠팡 정책상 즉시반영 아님(정상).

## SP-D — 신규 상품 등록 위저드

- [ ] **신규등록 페이지**: antd **4단계 Steps**(크롤 → 보정·가격 → 마켓 등록 → 완료).
- [ ] **Step1 크롤**: iHerb URL 입력 → 크롤 결과 테이블.
- [ ] **Step2 보정**: 원산지·중량·카테고리·묶음·**마진율(수동)**·**공급처(VendorType 드롭다운)** 편집 가능(하드코딩 20%/IHB 아님).
- [ ] **Step3 저장**: 선택 상품 저장 → productId 반환되어 다음 단계로.
- [ ] **Step4 마켓 등록**: 마켓 다중선택 → 상품×마켓 등록. **마켓별 성공/실패가 개별 표면화**(백엔드 사유 포함).
  - ⚠️ **카테고리 매핑 미구현(범위 밖)**: 마켓이 카테고리 코드를 필수로 요구하면 등록이 **실패로 표면화**됨 — 정상(정직한 미완성). 카테고리 매핑은 별도 작업.
- [ ] **sbCode 연속 채번**: 같은 날 여러 번 등록해도 sbCode가 기존 뒤로 연속(중복·건너뜀 없음).

## SP-E — 발주확인/취소 (Cafe24 전환)

- [ ] **G마켓/옥션 발주확인**: 통합주문관리에서 G마켓/옥션 주문 발주확인 → **Selenium 없이** Cafe24 API로 처리되고 성공/실패 표면화.
- [ ] **G마켓/옥션 취소**: 취소 시 로컬 CANCELED + **Cafe24로 전파**(예전엔 로컬만).
- [ ] **⚠️ Cafe24 상태코드 라이브 확정(핵심)**: 발주확인=`N20`, 취소=`C40`은 **best-known 추정값**. 실제로 원마켓(G마켓/옥션)에 반영되는지 확인하고, 4xx 실패나 미반영이면 `Cafe24OrderApiClient`의 `ACCEPT_STATUS`/`CANCEL_STATUS` 상수를 실제 값으로 교정.
- [ ] **쿠팡·스마트스토어 취소는 현행(로컬)**: 이들 마켓 취소는 마켓 전파 안 함(의도).
- [ ] **Selenium 잔재 0**: 컨테이너에 Selenium/Chrome 없이도 발주확인/취소 동작(예전 실패 원인 해소). 디버그 엔드포인트 `/esmplus/test`·`/esmplus/scrape` 404.

## SP-F — 관측성 (배치 완료로그 + SSE)

- [ ] **진행현황 페이지 자동갱신(핵심)**: 페이지를 열어둔 채 수동 배치(B1 크롤/가격재고 갱신 등) 실행 → **새로고침 없이** 활동로그가 갱신되고 배치 완료가 **SUCCESS/FAILED**로 뜸(예전엔 STARTED로만 남고 수동 새로고침 필요).
- [ ] **실패 표면화**: 일부러 실패 유도(잘못된 productId·소싱 URL 없는 상품) → 배치가 **FAILED**로 기록되고 SSE `BATCH_FAILED` 수신(예전엔 항상 성공으로 위장).
- [ ] **B4 by-supplier 라벨 정합**: 공급처별 배치의 완료 로그가 `BATCH_BY_SUPPLIER`로 남음(STARTED와 동일 라벨).
- [ ] **worker 스케줄 배치(새벽 cron)**: 활동로그엔 남지만 SSE는 없음(설계상 정상 — 그 시각 관찰자 없음).

## AI가 자율로 할 수 있는/없는 것 (참고)

- ✅ **가능**: 서버 도달 확인, read-only GET API 헬스체크(suppliers/orders/action-logs), 로그 관찰.
- ⚠️ **재배포 필요**: 위 전 항목은 서버가 `90eecf6`로 재배포된 후에만 유효.
- ❌ **AI 자율 불가**: 브라우저 UI 흐름 구동(자동화 도구 없음), 실 마켓 쓰기(게시/취소/가격변경 — 되돌릴 수 없는 외부 작업, 건당 허가 필요). 이 항목들은 사람 또는 브라우저 뷰어로 실행.

## 발견 시 조치
- 라이브에서 실패한 항목은 `docs/normalize/defect-ledger.md`에 D-번호로 기록하고 `sbshop-normalize` 하네스로 후속 수정.
- 미검증 API 상수(Cafe24 N20/C40, 쿠팡 sales stop/resume, 스마트스토어 optionalImages 필드형태)는 실측값으로 교정 후 재배포.
