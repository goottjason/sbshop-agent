# 통합 주문 관리 밀도 개선 설계 (2026-07-30)

## 목표

한 화면에 보이는 주문 건수를 최대화한다. 현재 약 3.7건 → 목표 7건 이상.
기능·컬럼 구성은 그대로 두고 크롬(chrome, 비데이터 영역)과 행 높이만 압축한다.

## 현황 진단

viewport 높이 ~1030px 기준 세로 예산:

| 영역 | 현재 |
|------|------|
| 탑바 | 70px |
| `.page-content` 패딩 | 32px (16 × 2) |
| 페이지 제목줄 | 52px |
| 동기화 상태줄 | 30px |
| 필터 패널 | ~270px |
| 테이블 헤더 | 33px |
| **주문 1건** | **146px** (48px 행 × 3 + 경계선 2px) |
| 화면당 주문 | **약 3.7건** |

주문 1건이 3행을 차지하는 구조(`rowType`: order / product / fulfillment)이므로
행 높이 절감은 3배로 증폭된다.

3행 구조의 실체:
- `LINEITEM_SPANNED_COLUMNS` (상품코드·재고·수량·유니패스·구매상태·배송정보·구매정보) → `rowSpan=3`
- `TWO_ROW_COLUMNS` (주문자·통관·배송·상품명·정산) → 행1·행2만 렌더, 행3은 셀 없음
- 즉 **3번째 행은 rowSpan=3 셀에 세로 공간을 주기 위해서만 존재한다.**

따라서 주문 블록 높이의 하한을 결정하는 것은 `구매 정보` 컬럼(`SourcingEditCell`)이다 —
계정·공급처·구매주문번호·할인코드 4개 컨트롤을 세로로 쌓는다.

- 현재: 필드 4 × 25px + gap 3 × 3px + 셀 패딩 12px = **121px** ≤ 3 × 48 = 144 ✓
- 개선: 필드 4 × 21px + gap 3 × 2px + 셀 패딩 6px = **96px** ≤ 3 × 36 = 108 ✓ (여유 12px)

**행 높이 축소는 인라인 입력 크기 축소와 반드시 세트로 가야 한다.** 행만 줄이면 컨트롤이 잘린다.
32px 아래로 내려가면 여유가 사라지므로 36px을 하한으로 둔다.

## 설계

### 1. 세로 예산 재배치

| 영역 | 현재 | 개선 | 방법 |
|------|------|------|------|
| 탑바 | 70px | 44px | nav 패딩 8/16→5/9, 아이콘 18→15, 폰트 14→12.5, 아바타 36→26, 검색창 300→200 |
| 페이지 패딩 | 16/24 | 8/12 | `.page-content` |
| 제목줄 + 동기화줄 | 82px | 34px | 한 줄로 병합 (제목 + 동기화 점 + 액션 버튼) |
| 필터 패널 | 270px | 34px (접힘) | 요약칩 바 + 펼침 토글 |
| 테이블 헤더 | 33px | 26px | th 패딩 8/12 → 4/8 |
| 주문 1건 | 146px | 110px | 행 36px × 3 + 경계선 2px |
| **화면당 주문** | **3.7건** | **약 7.8건** | **2.1배** |

### 2. 밀도 토큰화

밀도 수치가 인라인 스타일 수십 곳에 흩어져 있어 재조정이 불가능한 것이 현재의 근본 문제다.
`index.css`의 `:root`에 토큰을 두고 한 곳에서 조절한다:

```css
--topbar-h: 44px;
--row-h: 36px;         /* 주문 행 높이 */
--cell-pad: 3px 6px;   /* td 패딩 */
--head-pad: 4px 8px;   /* th 패딩 */
--field-pad: 2px 5px;  /* 인라인 입력 패딩 */
--field-fs: 11px;      /* 인라인 입력 폰트 */
```

인라인 스타일에서 `padding: 'var(--cell-pad)'` 형태로 참조한다.
밀도 재조정이 필요하면 이 블록만 고친다. 사용자 토글 UI는 만들지 않는다(YAGNI).

### 3. 필터 패널 접힘

- **기본 접힘.** 상태는 `localStorage['sbshop.orderFilter.open']`에 기억.
- 접힌 바 구성: `▸ 필터` + 요약칩 + 검색어 입력 + 검색 버튼
  - 요약칩: `06.30~07.30` · `마켓 전체` · `상태 7` · `구매 전체` · `재고 전체` · `소싱 전체`
  - **비기본값 조건은 강조색**으로 표시 — 접힌 상태에서도 필터가 걸린 걸 알 수 있어야 한다.
  - **검색어와 검색 버튼은 접힌 상태에서도 노출** — 가장 잦은 조작이므로 펼칠 필요가 없어야 한다.
- 펼치면 기존 패널 그대로. 내부 여백만 압축(패딩 14/20 → 10/14, 행간 8 → 6).

### 4. 영향 범위

| 파일 | 변경 |
|------|------|
| `frontend/src/index.css` | 밀도 토큰, 탑바·nav·검색·아바타·page-content 압축 |
| `frontend/src/layouts/MainLayout.tsx` | 아이콘 크기 18 → 15 |
| `frontend/src/components/ui/Table.tsx` | th/td 패딩을 토큰 참조로 |
| `frontend/src/pages/OrderGrid.tsx` | 툴바 병합, 필터 접힘, 행 높이·셀 패딩·인라인 입력 토큰화 |

탑바 축소는 **전 페이지에 영향**이 간다 — 의도된 범위다(사용자 확인 완료).

### 5. 검증

- `tsc -p tsconfig.app.json` + `npm run build` 통과
- 로컬 dev 서버 + 운영 API SSH 터널로 실데이터 렌더, 동일 뷰포트에서 Before/After 캡쳐
- 확인 항목: 구매정보 4필드 미절단 · 배송정보 3컨트롤 미절단 · frozen 컬럼 정렬 유지 ·
  sticky 헤더 동작 · 필터 펼침/접힘 상태 유지
- **배포(push)는 캡쳐 승인 후에만.**
