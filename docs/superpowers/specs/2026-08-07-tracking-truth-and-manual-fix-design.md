# 송장의 진실과 "마켓 수동수정" 안내 — 설계

2026-08-07 · 발단: 쿠팡 `23102043923068` 송장 미반영 신고(D-144) → 추적 중 드러난 구조 문제

## 1. 문제

마켓이 송장 수정을 거부하는 상황에서 우리 시스템이 **세 번 거짓말한다.**

1. **거짓 성공(D-145)** — N스토어 발송 API가 HTTP 200 본문에 실패를 담아 주는데
   (`data.failProductOrderInfos`) 최상위 `code`만 검사해 성공으로 기록한다.
2. **원복** — 마켓 반영에 실패한 교정을 다음 동기화가 **마켓 값(가송장)으로 되돌린다.**
   실측: 이메일 교정 11:34 → 스토어 동기화 11:38 원복 · 11번가 11:50 원복.
3. **침묵** — 되돌아가면 우리 값 = 마켓 값이 되어 `⚠ 마켓 미반영` 배지도 꺼진다.
   **고쳐야 할 일이 있다는 사실이 화면에서 사라지고**, 화면·엑셀·고객 응대는 가송장을 진짜처럼 안내한다.

## 2. 확정된 외부 제약 (실물 확인)

- **네이버는 발송된 주문의 송장 수정 API를 제공하지 않는다.** 커머스API 메인테이너 공식 답변 2건
  (#3192 "이미 발송처리한 주문건을 다시 발송처리 API 하시면 오류를 반환합니다" · #2450 "가까운 시일 내
  제공 계획이 없습니다"). 라이브 직접 시험에서도 올바른 택배사 코드로 재호출 시 `9999` 거부, 마켓 값 불변.
- **발송처리 취소·상태 되돌리기도 없다.** 공식 「주문 상태 변경 흐름도」의 모든 화살표가 단방향이고,
  주문처리 액션은 발주확인·발송지연·발송처리 셋뿐이다. 발송처리 즉시 `DELIVERING`이 된다.
- **네이버의 롯데 택배사 코드는 `HYUNDAI`다.** 근거: 네이버가 우리 주문에 돌려주는
  `delivery.deliveryCompany` 분포(CJGLS 14 · EPOST 4 · HYUNDAI 2, `LOTTE` 없음). 쿠팡과 같은 관례.
- 결론: **수정은 사람이 스마트스토어센터에서 해야 한다.** 시스템의 역할은 *대신 고치는 것*이 아니라
  **고쳐야 할 건을 정확히 짚어 주는 것**이다.

## 3. 규율 하나

> **송장의 진실은 발송처(iHerb 발송메일)다. 마켓 값은 "마켓이 알고 있는 값"일 뿐이다.**

지금은 "마켓이 진실 원본"이라 우리가 아는 진짜를 마켓의 가송장이 이긴다. 이 규율을 뒤집되
**마켓 값도 버리지 않는다** — 그래야 배지가 정확해지고 스스로 꺼진다.

## 4. 데이터 모델

`sb_shipment`에 컬럼 하나를 더한다.

| 컬럼 | 의미 |
|---|---|
| `tracking_no` (기존) | **실제 송장** — iHerb 발송메일이 진실. 동기화가 덮지 않는다 |
| `market_tracking_no` (신설) | **마켓이 알고 있는 값** — 동기화가 매번 갱신한다 |

- 두 값이 **다르면** = 마켓 미반영. 이것이 배지 판정의 유일한 근거다
  (`trackingSentToMarket` 플래그에 의존하지 않는다 — D-147에서 드러났듯 그 플래그는 실패해도 참으로 남는다).
- 이메일이 준 송장이 없으면 `tracking_no`는 종전대로 마켓 값을 따른다(마켓이 유일한 출처).

## 5. 세 상태

| 배지 | 조건 | 관리자 행동 |
|---|---|---|
| `✓ 마켓 반영됨` | `market_tracking_no == tracking_no` | 없음 |
| `⚠ 마켓 전송 대기` | 아직 전송 못 함, **재시도 가능한 실패** | 기다린다(30분마다 자동 재시도) |
| `🔒 마켓 수동수정` | 마켓이 **영구 거부** | 마켓 판매자센터에서 직접 수정 |

"영구 거부"의 정의는 `MarketplaceShippingService.isNonRetryableMarketState` 한 곳이 소유한다.

## 6. 화면 (설계 §7 확장)

배송정보 셀은 지금과 같은 높이를 유지한다 — 배지를 **전송 버튼과 같은 줄**에 둔다.

```
[택배사        ▾]
[315399497965  ]
🔒 마켓 수동수정   [전송]      ← 한 줄
마켓 363092185283              ← 수동수정일 때만, 회색 취소선
```

- 복사·딥링크 버튼은 두지 않는다(셀만 커지고 실익이 적다 — 2026-08-07 사용자 판정).
- 마켓 보유값 한 줄은 **정보**다: 입력칸의 값이 "바꿀 값", 취소선이 "지금 마켓에 잘못 들어가 있는 값".
- 상단 툴바에 필터 칩 `마켓 수동수정 필요 N` · `마켓 전송 대기 N`. 190건 사이의 5건은 배지만으로 놓친다.
- **완료 체크 버튼은 두지 않는다.** 사람이 마켓에서 고치면 다음 동기화가 `market_tracking_no`를 갱신하고
  두 값이 같아져 배지가 스스로 꺼진다. 눌러놓고 실제로는 안 고친 상태를 만들지 않는다.

## 7. 구현 순서 (앞이 뒤의 전제)

1. **D-145 백엔드 정직성** — 거짓 성공 제거 · 택배사 코드 교정 · `9999` 영구 거부 분류
2. **D-148 데이터 보존** — `market_tracking_no` 신설 · 동기화가 실제 송장을 덮지 않게
3. **D-149 화면** — 배지 3종 · 필터 칩

1이 없으면 2·3이 표시할 "실패"가 없고, 2가 없으면 3이 표시할 "실제 송장"이 사라진다.

## 8. 범위 밖

- 11번가·Cafe24의 송장 수정 API 유무는 따로 확인하지 않았다. 지금 규율은 마켓 무관하게 동작한다
  (거부되면 수동수정으로 넘긴다).
- D-146(11번가 문구 분류)·D-147(플래그 정직성)은 별도 항목으로 남긴다.
