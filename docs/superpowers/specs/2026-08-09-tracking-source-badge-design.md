# 송장 출처 표시 (📧 이메일 / ✍ 수동) — 설계

작성 2026-08-09 · 사용자 요청: "지금 기입한 송장이 가송장인지 이메일 동기화로 들어온 진짜 송장인지
구분하기 어렵다. 배지를 하나 더 추가해 보여달라."

## 문제

송장은 세 경로로 들어오는데 모두 같은 칸(`sb_shipment.tracking_no`)에 쓰이고, **출처를 기록하지 않는다.**
그래서 화면에 있는 송장이 iHerb 발송메일이 준 진짜 송장인지, 마감을 맞추려 넣은 가송장인지 알 수 없다.

기존 배지(`✓ 마켓 반영됨` 등)는 **마켓 반영 여부**라는 다른 축을 말한다 — 출처와 무관하다.

## 설계

### 데이터

`sb_shipment`에 `tracking_source` 한 칸을 추가한다.

| 값 | 쓰는 경로 |
|---|---|
| `EMAIL` | `EmailFetcherService` — iHerb 발송메일에서 송장을 기록할 때 |
| `MANUAL` | `OrderService.updateShippingInfo` — 관리자가 화면에서 입력할 때 |
| `MARKET` | 동기화가 마켓 값을 채택할 때(우리가 송장을 모를 때만, D-148) |

값이 없으면(`null`) **출처 미기록** — 이번 변경 이전에 기록된 과거 데이터가 여기 해당한다.

### 화면

저장은 3종으로 정확히 하되 **표시는 두 가지로 접는다.**

| 표시 | 조건 | 뜻 |
|---|---|---|
| 📧 | `EMAIL` | iHerb 메일이 준 진짜 송장 |
| ✍ | `MANUAL` · `MARKET` | 사람·마켓이 넣은 값 — 진위 불명(대개 가송장) |
| (없음) | `null` | 과거 데이터. 불확실하므로 표시하지 않는다 |

위치는 **송장 입력칸 왼쪽**이다. 기존 배지 줄(배지 ↔ 전송 버튼)은 건드리지 않는다 —
2026-08-07에 셀 높이를 늘리지 않으려 한 줄로 합친 결정을 유지한다.

```
│ [ CJ대한통운             ▾ ] │
│ 📧 [ 424438293101         ] │   ← 이 자리만 추가
│ ✓ 마켓 반영됨       [ 전송 ] │   ← 그대로
```

**아이콘 자리는 고정폭으로 예약한다.** 아이콘이 없어도 입력칸 시작 위치가 흔들리면 안 된다
(사용자 요구). 툴팁으로 뜻을 설명한다.

### 가송장 체크박스를 두지 않는 이유

처음에는 관리자가 입력할 때 "가송장" 여부를 체크받는 안을 검토했으나 **불필요하다**.
관리자 입력은 어차피 ✍로 표시되고, iHerb 메일이 도착하면 자동으로 📧로 바뀐다.
사람이 따로 표시할 이유가 없다 — 입력 단계를 늘리지 않는다.

### 자동 교정이 성립하는 근거 (코드 확인)

이 설계는 "가송장은 언젠가 진짜로 덮인다"에 기댄다. 확인 결과 이미 그렇게 동작한다:

- 이메일 처리 대상은 상태가 `PREPARING`·`DISPATCHED`·`SHIPPED`인 iHerb 라인아이템이고
  (`OrderLineItemRepositoryImpl.shipmentEmailNeeded`), 매 사이클 주문번호로 메일함을 **다시 검색**한다
  (읽은 메일도 다시 찾는다).
- 송장이 다르면 `EmailFetcherService`가 교정한다 —
  주석 그대로 *"취소 방지용 가짜 송장을 진짜 송장으로 교정하고 마켓 수정 반영"*.

따라서 ① 가송장 입력 후 메일 도착 → 덮임, ② 실수로 진짜를 가송장으로 덮어써도 다음 사이클에 복구된다.

**한계**: 상태가 `DELIVERED`로 넘어가면 큐에서 빠져 더는 복구되지 않는다. 배송완료 후의 수정은 그대로 남는다.
실무상 그 시점에는 송장을 손댈 일이 없으므로 감수한다.

### 과거 데이터

소급 판정하지 않는다. 배송완료 건을 `EMAIL`로 간주하는 안도 검토했으나, 그 값이 실제로 메일에서 왔는지
확인하지 않고 📧를 붙이는 셈이라 **표시하지 않는 쪽**을 택했다(사용자 결정: "과거 데이터니 불확실하니
아이콘 없이 두자"). 현재 분포상 미표시로 남는 건 배송완료 212 · 종결 4 · 배송중 10건이다.

## 범위 밖

- 출처별 필터 칩 — 필요해지면 그때. 지금은 아이콘만으로 충분하다.
- 출처 변경 이력 추적 — 현재 값만 보관한다.
- 마켓 유래(`MARKET`)를 별도 아이콘으로 분리 — 사용자 결정으로 ✍에 합쳤다.

## 테스트

- 이메일 경로가 기록하면 `EMAIL`, 관리자 입력은 `MANUAL`, 동기화 채택은 `MARKET`
- 가송장(`MANUAL`)이 이메일 도착으로 `EMAIL`로 덮이는 회귀 — 이 설계의 핵심 전제
- 과거 데이터(`null`)는 아이콘 없이, **입력칸 정렬이 흔들리지 않는지**
- 기존 마켓 반영 배지 판정(D-156)에 영향이 없는지 — 두 축은 독립이다
