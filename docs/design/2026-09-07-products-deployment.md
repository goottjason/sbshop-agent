## 스키마 검증과 전환 경과

운영 DB 복사본에서 9개 DDL의 최초/재실행, 기존 상품 3,195행과 연결 9,920행의 값 보존을 검증했다. 그러나 최초 이미지 `6388eecf`는 Hibernate가 `cafe24ProductCode`를 `cafe24product_code`로 변환하여 운영 DDL의 `cafe24_product_code`와 달라 기동에 실패했다. 자동 스키마 변경을 허용하지 않은 `DDL_AUTO=validate`가 이를 차단했다.

새 앱이 기동하지 않았고 새 변경/점검/등록/가격/관측 작업 행이 모두 0건임을 확인한 뒤 기존 이미지로 화면을 복구했다. 이어 두 카페24 식별자 열의 `@Column(name=...)`을 명시했다. DB 열을 임의로 추가하거나 검증을 끄지 않았다.

`backend/tools/ValidateProductSchema.java`는 Spring·스케줄러·마켓 클라이언트를 시작하지 않고, PostgreSQL 세션을 읽기 전용으로 강제해 릴리스 JAR의 엔티티를 검증한다. 잘못된 이미지에서 동일 오류가 검출됨을 먼저 확인했고, 수정 이미지에서는 **엔티티 32개 전체 검증이 통과**했다. 앱의 모든 상품 테이블·시퀀스 접근 권한도 확인했다. 이후 수정본으로 다시 전환했다.

## 계정 설정과 백업

실제 DOM에서 쇼핑몰 `younzara`, shop 1, G마켓 `younzara`, 옥션 `shouldbe2480`을 확인했다. 운영에 판매 계정 환경변수와 읽기 전용 수집 상태 볼륨을 연결했다.

이미 새 점검/연결 이력이 생성되었으므로 **이제 구버전으로 단순 이미지 교체하면 안 된다.** 복구는 우선 새 버전의 수정 배포를 사용한다. 구버전이 필요한 경우 마켓 쓰기와 자동 점검을 중지하고 미확인 등록·연결 해제·작업 임대를 검토해야 한다. 신규 이력/식별자/작업을 삭제하거나 DB 전체를 덮어쓰지 않는다. 최초 기동 실패 때의 복구는 새 작업 0건을 확인한 별도 상황이었다.

이미 수동 운영 배포·검증을 완료했으므로 마지막 기록 커밋의 `[skip ci]`로 동일 push의 중복 자동 배포를 방지한다. [GitHub 공식 동작](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/skip-workflow-runs)에 따르며, 자동 CI가 이 배포를 검증했다고 기록하지 않는다.
