# 상품 관리 개편 — 백엔드 데이터·API 계약안

2026-09-06. Q1~Q17의 확정 정책을 구현하기 위한 **검토용 내부 설계**다. 여기에 적힌 새 테이블·API는 아직 구현하거나 운영에 적용하지 않았다. 실제 구현 현황은 [구현 기록](2026-09-06-products-implementation-progress.md)을 따른다. 외부마켓 필드와 상태 판정은 [근거표](2026-09-05-products-field-rules-and-sync-design.md)를 사용한다.

## 1. 저장 구조

| 구성 | 주요 데이터 | 제약·책임 |
| --- | --- | --- |
| 시스템상품 | 기존 업무값, `revision`, `salesStockQuantity` 기본 300 | 모든 편집 경로에서 동일한 버전·편집 정책 검사. 기존 `stock`과 판매용 수량 분리 |
| 상품 변경 이력 | 상품 ID, 변경 버전, 필드별 전후값, 변경 출처, 작업자, 시각 | 불변 이력. 상세 HTML·이미지의 큰 원본은 버전별 저장 객체를 참조 |
| 마켓 리스팅 | 상품·마켓·판매계정, 외부 식별자, 연결 세대, 활성 여부, 시작/종료 시각, 해제 사유·근거 | 동일 상품·마켓·계정에는 활성 연결 하나. 과거 리스팅과 주문 참조 보존. 카페24와 하위 마켓은 개별 리스팅으로 연결 관계 기록 |
| 마켓 관측 이력 | 리스팅 ID, 관측 시각, 존재 상태, 판매 상태·원인, 관측 필드, 원문 참조, 오류 | 조회 실패를 기존 관측값에 덮어쓰지 않음. 삭제/영구 금지는 확인 근거 필요 |
| 마켓 목표 스냅샷 | 상품 버전, 리스팅 세대, 가격/이름/템플릿 정책 버전, 필드별 목표값·지문 | DB값과 외부 변환값 구분. 사용자가 심사 요청에 동의한 스냅샷 고정 |
| 소싱 수집 스냅샷 | 소싱처·원본 URL, 시도/완료/성공 시각, 가격·판매 가능 상태, 원본 이미지·설명, 항목별 결과 | 실패·빈 결과를 적용 가능한 최신 정보로 취급하지 않음. 가격·재고와 콘텐츠 수집 결과 분리 |
| 콘텐츠 적용 이력 | 수집 스냅샷 ID, 선택한 이미지/본문, 생성 템플릿 버전, 적용 상품 버전·시각 | 최신 소싱 수집과 시스템 반영을 구분. 변경 없음 확인도 수집 성공 시각을 기록 |
| 작업 및 항목 결과 | 작업 ID, 요청자·요청 출처, 상품·리스팅 세대·목표 버전, 필드 그룹, 상태, 다음 시도, 결과 | 수동·일괄·스케줄러가 공통 작업 경로 사용. 외부 호출 중 DB 트랜잭션을 계속 열어두지 않음 |
| 전송 시도 | 작업 항목, 시도 번호, 시작/종료, 외부 요청 ID, 접수 결과, 반영 확인, 오류 원문 | HTTP 상태와 업무 결과를 따로 보존. 일부 성공을 전체 성공으로 승격하지 않음 |

외부 식별자는 숫자처럼 보여도 문자열로 관리한다. 소싱처 상품번호와 마켓 상품번호는 별도 검색용 식별자 행으로 정규화하여 JSON의 필드명·무관한 값이 검색되는 문제를 피한다. 소싱처 상품번호 추출은 해당 소싱처의 확인된 규칙이 있는 경우만 수행한다.

## 2. 판매용 재고 300의 의미

`salesStockQuantity`는 판매 가능할 때 외부에 반영할 **설정 수량**이다. 기본은 300개이며 상품별 변경값을 보존한다. 소싱처 재고 실수량을 크롤로 확보한 것과 같은 의미가 아니다.

| 상황 | 설정 수량 | 목표 동작 |
| --- | --- | --- |
| 소싱처 판매 가능, 기본 상품 | 300 유지 | 해당 마켓의 검증된 재고 API로 설정 수량 반영 |
| 사용자가 판매용 수량을 120으로 변경 | 120 저장 | 이후 해당 상품은 120 기준으로 반영 |
| 소싱처 일시 품절 | 기존 120 보존 | 판매를 중지. 0 재고/정지 API 등 실제 표현은 마켓 계약에 따름 |
| 소싱처 재입고 확인 | 기존 120 유지 | 판매용 수량 120으로 복구 |
| 크롤 실패·판매 가능 여부 불명 | 설정 수량 유지 | 실패를 품절 또는 재입고로 해석하지 않음 |
| 마켓 영구 금지·삭제로 연결 해제 | 설정 수량 유지 | 해제된 리스팅에는 판매 복구·동기화 전송 금지 |

현재 신규 등록 경로도 마켓마다 기준이 다르다. 스마트스토어는 상수 999, 11번가는 `product.stock`/999, 카페24는 문서 근거가 부족한 `supply_quantity`를 사용한다. 따라서 동기화의 999 상수만 300으로 바꾸면 신규 등록과 수정이 다시 어긋난다. 새 수량 모델을 도입할 때 **신규 등록·수정·재입고·수동 반영 모두 같은 재고 계산기를 사용**하고, 카페24 재고 계약을 검증한 뒤 전환한다.

## 3. 마켓 상태를 세 축으로 표현

| 축 | 값 예시 | 의미 |
| --- | --- | --- |
| 연결 | `ACTIVE`, `DETACHED`, `NEVER_LINKED` | 현재 관리 대상인지, 과거 이력만 있는지 |
| 판매 | `SELLING`, `TEMPORARILY_OUT_OF_STOCK`, `PERMANENTLY_PROHIBITED`, `DELETED`, `UNKNOWN` | 실제 판매 상태와 원인. 마켓별 근거 있는 코드에서만 매핑 |
| 정보 반영 | `MATCHED`, `DIFFERENT`, `AWAITING_USER_REVIEW`, `AWAITING_MARKET_REVIEW`, `AWAITING_VERIFICATION`, `FAILED`, `UNKNOWN` | 목표 버전과 확인한 외부 데이터의 관계 |

예: 품절 상품도 연결은 ACTIVE이며 재고 상태가 마켓에 반영되었다면 정보 반영은 MATCHED일 수 있다. 영구 금지 상품은 DETACHED와 금지 이력을 표시한다. 조회 실패는 기존 연결을 유지하고 실패 사유·최근 성공 관측 시각을 함께 표시한다.

`MATCHED`는 현재 리스팅 세대와 현재 목표 버전의 필수 반영 필드가 모두 확인됐을 때만 표시한다. 가격만 성공하고 이미지가 실패했다면 FAILED/부분 반영 상태다. 검증할 수 없는 필드는 접수 완료 또는 검증 불가로 남긴다.

## 4. 편집과 잠금

1. 상품 및 현재 활성 연결 목록의 버전을 읽는다.
2. 입력한 필드 외에 파생되는 상품명·옵션명·상세 HTML 등도 계산한다.
3. 활성 마켓별 상품 유형/상태/필드 제한을 판정한다. 불변 필드와 그 필드로 우회되는 변경은 차단한다. 미확인 매핑을 전송 가능한 것으로 간주하지 않는다.
4. 모든 연결이 해제되었다면 마켓의 과거 제한으로 편집을 막지 않는다(Q15). 과거 상품값·상품번호·사유는 이력에서 유지한다.
5. 사용자가 검토한 상품 버전과 연결 버전이 그대로인지 쓰기 트랜잭션에서 다시 검사한다. 다르면 충돌로 반환하고 재검토한다.
6. DB 변경, 변경 이력, 자동 반영 작업 생성은 하나의 로컬 트랜잭션으로 저장한다. 심사 변경은 사용자 확인 대기로 기록한다.

등록 예약과 편집도 같은 잠금을 사용한다. 사용자가 편집하는 동안 새 리스팅 등록이 시작되거나, 등록 중 외부에서 상품이 생성된 경우를 ‘활성 연결 없음’으로 오인하여 이름을 바꾸지 않도록 한다. 등록 결과 불명 상태를 해소한 후 편집 가능 여부를 재평가한다.

수치 처리는 원래 값→단위 확인→연산→필드별 반올림/정수 처리→범위·파생 변경 검사 순으로 설계한다. 검토 토큰과 변경 이력에는 적용한 수치 정책 버전과 처리 전후 값을 포함한다. Q18에서 판매가 100원 단위 반올림(HALF_UP), 재고·묶음수량의 비율 계산 후 소수 부분 버림, 무게·용량의 단위별 정수/소수 첫째 자리 표시 선호를 확정했다. 판매가는 값 지정·증감·비율 연산 결과에 한 번 반올림하고, 수량 직접 지정·증감은 정수로 받는다. 반올림 후에도 범위를 검사하며 묶음수량 1개 미만을 임의로 1개로 올리지 않는다. 용량의 `measureUnit`은 배송 무게 단위의 증거로 사용하지 않는다. 표시 자릿수를 맞추기 위해 기존 무게·용량을 일괄 반올림하거나 원가·환율까지 판매가 정책으로 처리하지 않는다.

Q20에서 최소마진을 우선 보장하고 하한을 충족하는 100원 단위로 보정·사유 표시하는 정책을 확정했다. 반올림가 12,300원 / 하한 12,340원이면 최종가는 12,400원이다. 자동 계산·마켓별 등록가·배치에 공통 규칙을 적용하고, 결과에는 반올림가·최소마진 하한·최종가·보정 여부·사유를 제공한다. 기존 최소마진 정의인 판매가에서 쿠폰 적용 총 매입가와 국내 배송비를 뺀 금액을 기준으로 하며, 마켓 수수료는 기존 비율 산식에 반영한다. 배치의 소싱처별 국내 배송비와 무료배송 기준을 마켓 계산에도 전달한다. 수치 미리보기 통과만으로 수익성·마켓 편집 허용·실제 저장을 보장하지 않는다.

`GET /products/{id}/price-preview`는 현재 저장된 상품과 정책으로 마켓별 등록가를 재계산하는 읽기 전용 API로 구현했다. 실제 마켓 조회는 하지 않는다. 원가·마진 부족 시 기준가 반올림 결과는 최소마진 미검증, 계산 실패는 가격 없이 사유로 표시한다. 상품이 없거나 폐기됐으면 404다. 과거 실행 시점의 가격 정책·보정 근거를 재현하는 영속 스냅샷과는 별개다.

Q19에서 무게 kg 표준과 출처 확인 후 기존 값 변환을 확정했다. 새 입력은 kg로 받고, g를 사용하는 소싱 초안은 경계에서 정확히 1000으로 나눈다. 저장 열은 `numeric(13,5)`로 확장하여 기존 정수 범위와 초안의 g 소수 2자리를 모두 보존한다. 기존 값은 조회 시 자동 변환하지 않는다. 향후 확인 이력에는 이전 값·확인된 단위·kg 결과·근거 자료·작업자·시각을 보존하고, 현재 값·버전이 검토 당시와 같은 경우에만 적용한다. 새 표준 선언만으로 기존 상품 전체에 kg 확인 상태를 부여하지 않는다. [전환 기록](2026-09-06-products-weight-normalization.md).

## 5. 제안 API

아래 경로는 새 편집·작업 흐름의 계약안이다. 기존 수정 API를 대체할 때 요청마다 이 정책을 공통으로 적용한다.

| API | 응답·행동 |
| --- | --- |
| `GET /products/{id}/workspace` | 시스템상품, 버전, 필드별 편집 가능 여부·잠금 사유, 마켓별 목표/관측/이력, 콘텐츠 최신성 |
| `POST /products/changes/preview` | 상품별 전후값, 파생 변경, 영향 마켓, 잠금/검토 필요 항목, 검토 토큰 |
| `POST /products/changes/commit` | 검토 토큰·현재 버전 검증 후 DB 저장. DB 저장 결과와 생성된 반영 작업 ID 반환 |
| `POST /products/source-refresh` | 가격·재고 또는 콘텐츠 수집 작업 접수. 수집 결과 스냅샷 ID 제공 |
| `POST /products/content/preview` | 기존/최신 이미지·본문 비교, 선택 항목으로 최신 템플릿 생성 결과 제공 |
| `POST /products/content/apply` | 검토한 콘텐츠·상품 버전 확인 후 적용. 수집 성공과 DB 적용 시각 따로 기록 |
| `POST /products/market-sync/preview` | 상품·마켓별 변경 필드, 심사 필요 여부, 전송 가능/제외 사유 |
| `POST /products/market-sync` | 검토한 목표 스냅샷으로 작업 접수. 202와 작업 ID 반환 |
| `POST /products/registration-candidates` | 최초 미등록·과거 삭제 후보, 과거 사유, 필수 정보, 금지/조회불명 등 제외 사유 |
| `POST /products/registrations` | 사용자가 선택한 상품×마켓 후보의 새 등록 작업 접수. 현재 연결·등록 예약 중복 검사 |
| `GET /product-operations/{id}` | 전체·상품별·마켓별·필드별 진행 및 최종 결과, 사유·다음 재시도 시각 |
| `POST /product-operations/{id}/retry` | 재시도 가능한 실패 항목만 재검증·접수. 접수만 된 등록 요청을 무조건 재생성하지 않음 |

운영 기본 경로 `/sbshop-agent/api/v1` 아래에 배치한다. 요청의 상품·마켓 ID, 필드명, 연산은 서버 허용 목록으로 검사한다. 검토 토큰은 검토 당시 상품 버전·연결 세대·선택 필드·목표값과 결합하며 클라이언트가 값을 바꾸어 재사용할 수 없다.

## 6. 큐와 실패 처리

작업은 상품×리스팅 세대×목표 버전×필드 그룹을 참조한다. 가격/재고/콘텐츠/심사 변경의 상태를 분리한다. 단일 필드 API와 전체 상품 API의 요청 조립 방식은 어댑터가 담당하고, 결과는 같은 필드 결과 형식으로 반환한다.

- 스케줄러는 영속 작업을 임대하여 처리하고, 중단된 작업은 임대 만료 후 회수한다. 전송 중 DB 트랜잭션을 열어두지 않는다.
- 같은 마켓 계정의 공통 호출 제한을 수동 작업·스케줄러·등록·조회가 공유한다. 제한 수치는 문서와 실제 응답 근거를 확보한 뒤 설정한다.
- 429는 `Retry-After` 등 제공된 안내와 지수 지연·무작위 분산을 적용한다. 연속 권한 오류나 잘못된 요청은 무한 반복하지 않고 필요한 조치를 표시한다. 구체적인 최대 재시도/알림 주기는 별도 결정한다.
- 생성 요청 타임아웃은 결과 불명이다. 외부 식별자/상관 키로 생성 여부를 확인할 수 없다면 수동 확인으로 남기고 재등록을 막는다.
- API 전체 객체를 수정해야 한다면 최신 외부 원본을 읽어 검토된 변경만 합성한다. 자동 가격 작업에 아직 확인받지 않은 상품명이 섞이지 않게 한다.
- 완료 직전 현재 리스팅 세대와 목표 버전을 검사한다. 이전 리스팅의 지연된 성공 응답이 새 등록을 성공으로 표시하거나, 이전 재고 작업이 재입고 상태를 덮어쓰면 안 된다.

## 7. 목록 조회 구조

상품 목록의 기본 정보와 마켓별 요약·콘텐츠 시각은 페이지 단위 일괄 조회한다. 행마다 외부 API를 호출하지 않는다. 최신 확인은 별도의 조회 작업으로 수행하고 확인 시각을 반환한다.

- 단일 검색축 내부 선택은 OR, 소싱처·브랜드·재고 등 서로 다른 축은 AND다. 특정 마켓 등록과 다른 마켓 미등록 조건도 AND다.
- 등록 조건은 활성 연결에 대해 판정한다. 과거 이력만 있는 상품을 현재 등록으로 세지 않는다. 조회불명 상태를 미등록으로 바꾸지 않는다.
- 이미지·HTML의 성공 수집 확인일, 시스템 적용일, 템플릿 버전을 분리한다. 성공 이력이 없는 값은 미확인으로 표시하고 현재 시각으로 채우지 않는다.
- 기본 정렬은 조치 필요 우선→오래된 정보 순(Q3). 서로 다른 조치 사유의 세부 우선순위와 미확인 정보의 위치는 검토안으로 남기며, DB에서 정렬 후 페이지 처리한다. 동률에는 SB코드/상품 ID를 사용해 페이지 순서를 안정화한다.
- 대량 선택은 검색 조건과 선택 대상의 스냅샷을 고정한다. 일부 페이지를 보지 않은 상태의 작업 범위·전체 결과 선택은 UI에서 명시한다. Q16에 따라 사전 검토 후 수정 가능한 상품만 적용하고 제외·실패 사유를 보존한다. Q17에 따라 필드에 맞는 값 지정·증감·비율 연산과 결과 미리보기를 제공한다. 상품 하나의 조합 필드 중 일부만 조용히 적용하지 않도록 상품별 원자성을 유지하는 구현안을 사용한다.

## 8. 전환 순서

1. 기존 상품·등록 식별자·주문 참조 관계를 읽기 전용으로 조사한다. 조회 실패와 영구 금지/삭제 확정 근거를 분류한다.
2. 새 열과 이력/작업 저장소를 추가하는 마이그레이션을 준비한다. 기존 테이블을 삭제하거나 과거 식별자를 덮어쓰지 않는다.
3. 기존 등록을 새 리스팅으로 옮길 때 오래된 `isSynced=true`를 현재 필드 일치의 증거로 사용하지 않는다. 관측 시각·검증 상태는 알 수 있는 값만 이관한다.
4. 판매용 수량 300을 별도 열에 초기화하고, 신규 등록과 수정의 모든 어댑터가 같은 계산기를 사용하게 한다. 기존 `stock`은 보존한다.
5. 외부 호출 없는 변경 미리보기와 잠금 검사를 먼저 연결한다. 검증된 어댑터·필드부터 새 작업 흐름으로 전환한다.
6. 새로운 작업과 기존 배치가 같은 상품을 동시에 쓰지 않게 전환 범위를 고정한다. 기존 경로의 자동 쓰기는 해당 범위 전환 시 함께 정리한다.
7. 실패·429·심사·삭제·재등록·작업 중단 회복을 검증한 구체적 변경을 배포 검토 대상으로 제시한다.
