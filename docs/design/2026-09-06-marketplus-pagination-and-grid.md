# 마켓플러스 여러 페이지 수집·재개와 목록 표시

2026-09-06. [단일 페이지 수집·저장](2026-09-06-marketplus-transmission-import.md)의 후속 단계. **로컬 구현·검증이며 운영 미배포다.** 외부 상품 수정·전송·중지해제, 운영 DB 변경은 실행하지 않았다.

## 수집 범위와 재개

라이브 Chrome의 상품관리이력에서 검증한 페이지 버튼(`Go to next page`, `aria-current`)만 누른다. URL을 추정해 사설 API를 호출하지 않는다. 탭·조회 조건·URL 페이지·화면 페이지·행 순서를 함께 검사한다. 새 이력이 끼어들어 페이지 경계가 달라졌거나 조건이 변경되면 그 페이지를 저장하지 않고 중단한다.

파일에는 `MARKETPLUS_COLLECTION`, 각 페이지의 기존 저장용 `Batch`, 조회 조건, 읽은 페이지 번호, 중단 사유가 들어간다. 페이지별로 임시 파일 작성·fsync·원자적 교체를 하며 같은 출력 파일의 동시 실행은 잠금으로 차단한다.

- `PARTIAL / PAGE_LIMIT`: 지정한 페이지 수까지 읽었다. 전체 수집 완료가 아니다.
- `PARTIAL / 오류 사유`: 읽기·로그인·경계 검사에서 중단했다. 이미 저장한 페이지는 보존한다.
- `REACHED_LAST_PAGE`: 해당 조회 조건에서 마지막 페이지까지 도달했다. 시작 페이지보다 앞의 이력, 다른 탭·기간·계정, 현재 마켓 상품 상태의 전수 검증을 뜻하지 않는다.
- `RUNNING` 상태에서 프로세스가 종료되어도 가져오기 화면에서는 부분 수집으로 표시한다.

첫 수집 예시:

```sh
python3 tools/browser/collect-marketplus-transmissions.py \
  --mall-id 'younzara' --max-pages 10 --output /tmp/marketplus-failures.json
```

마지막 저장 페이지를 같은 조건으로 연 상태에서 재개한다. 시작점이나 마지막 페이지 내용이 바뀌면 새 파일로 수집해야 한다.

```sh
python3 tools/browser/collect-marketplus-transmissions.py \
  --mall-id 'younzara' --max-pages 10 --resume --output /tmp/marketplus-failures.json
```

한 번에 1~100페이지, 파일당 최대 2,000페이지를 허용한다. UI가 제공하는 분 단위 시각·행 순서는 원격 작업의 고유 ID가 아니며, 페이지를 순회하는 동안의 원자적 스냅샷도 보장하지 않는다. 동일 관측의 저장 중복 방지와 별도로 수집 범위를 명시한다.

실제 Chrome에서는 실패 1~3페이지 60행 수집 후 같은 파일로 재개해 **1~5페이지 100행**을 확보했다. 최종 상태는 `PARTIAL / PAGE_LIMIT`이다. [수집 파일](evidence/2026-09-06-marketplus-failure-pages-1-5.json). 운영 DB로 업로드하지 않았다.

## 상품 목록·상세 화면

- 목록 조회 시 현재 페이지의 연결들을 한꺼번에 넘겨 최근 관측을 조회한다. 상품마다 이력 API를 별도로 호출하지 않는다.
- 같은 계정·상품 식별자·전송 종류에 대해서만 최근 완료 시각을 비교한다. 늦게 가져온 오래된 실패가 더 최근 결과를 덮지 않는다. 다른 종류의 전송 성공으로 상품수정 실패를 지우지 않는다.
- 같은 분, 같은 전송 종류에 성공·실패가 모두 있으면 수집/저장 ID로 순서를 만들어 내지 않는다. `CONFLICT`로 반환하고 목록에서는 주황색 ‘미확인’으로 표시한다.
- 실패는 `TRANSFER_FAILED`, 성공 관측은 여전히 `UNVERIFIED`이며 파란색 ‘전송됨’으로 표시한다. 툴팁에 원문과 전송·수집 시각을 보여 준다. 성공 관측을 전체 필드 동기화 또는 현재 판매 상태 정상으로 표시하지 않는다.
- 연결 해제·영구 금지는 관측 결과보다 우선한다. 계정이나 상품번호가 달라진 관측은 새 연결의 배지에 반영하지 않는다.
- 관측 배지를 누르면 해당 상품의 전송 이력 창을 연다. 자동 등록·재전송을 호출하지 않는다. 상품 상세의 이력 패널도 유지한다.
- 여러 페이지 수집 파일을 선택하면 페이지 범위·부분 수집 여부·총 행 수를 먼저 표시한다. 서버의 기존 행별 저장 API에 페이지를 순서대로 보낸다. 진행 표시와 현재 페이지 처리 후 중단을 제공한다. 창을 닫으면 다음 페이지 처리를 중지한다.
- 응답을 확인한 저장/중복/제외 수만 합산한다. 요청 실패 시 남은 페이지를 성공 처리하지 않는다. 다시 같은 파일을 가져오면 서버에서 중복을 방지한다. 제외 사유는 페이지와 행 번호를 함께 구분한다.

[검증 화면](2026-09-06-marketplus-pagination-grid-preview.png). 실제 컴포넌트에 가상 응답을 주어 검사한 화면이며 운영 화면 캡처는 아니다.

## 오류 원인 조사

수집한 이력에는 **2026-09-05 14:03·14:05**에도 `진열/판매 상태일 때만 판매중지를 해제할 수 있습니다` 오류가 있다. 이 오류 유형은 오늘의 테스트·API 버전 변경 이후 처음 생긴 것이 아니다. 오늘 특정 상품의 16:02 작업이 어떤 경로로 생성되었는지는 이 사실만으로 확정하지 않는다. 사용자의 수동 실행 여부는 ‘기억나지 않음’으로 유지한다.

가격 설정 API를 기존 운영 토큰으로 **GET 1회** 재조회하여 HTTP 403의 원문을 확보했다:

```text
The permission necessary for access tokens is not included. (insufficient_scope)
```

이 403은 접근 토큰의 권한 부족이다. [상품 설정 조회 공식 문서](https://apidocs.cafe24.com/docs/admin/get-products-setting)의 READ_STORE와 앞서 추가한 `mall.read_store`를 기준으로 앱 권한과 재인증을 확인한다. 개발자센터 세션은 로그아웃 상태라 로그인 화면을 열고 사용자에게 로그인을 요청했다. 토큰 발급·권한 설정 변경은 실행하지 않았다. [응답 기록](evidence/2026-09-06-cafe24-settings-scope-error.json).

## 검증·배포 전 남은 항목

- 백엔드 78건(Core 15, API 63) 통과. 최근 관측 쿼리, 같은 분의 충돌, 전송 종류 분리, 계정/상품 교체, 해제 우선, 기존 상품 컨트롤러 회귀를 포함한다.
- Python 수집기 12건, 프론트 파일 파서 4건 통과. 사용자 중단 시에도 저장 페이지를 보존하고 부분 수집으로 기록하는 경우를 포함한다.
- Chrome에서 배지 폭 320px, 실패/성공/충돌/해제, 이력 열기, 조회 오류와 재조회, 두 페이지 파일의 부분 수집 안내·순차 저장·페이지별 제외 사유·외부 쓰기 미호출을 검증했다.
- TypeScript·변경 파일 ESLint(오류 0, 기존 TanStack Table 경고 1)·Vite 빌드와 변경 Java 파일 Spotless 검사 통과. 기존 번들 크기 경고는 남는다.

전송 이력 DDL에 `(registration_id, market, completed_at)` 인덱스를 추가했다. 선행 미배포 DDL과 함께 PostgreSQL 적용·통합 배포 검증이 필요하다. 일반 코드에는 실계정 기본값을 넣지 않았으므로 운영 배포 시 확인된 MarketPlus 계정 환경변수도 전달해야 한다.

후속 진행: [카페24 권한 확인·재인증과 가격 설정 403 해결](2026-09-06-cafe24-reauthorization-scope.md)은 20:31 KST 완료했다. [G마켓·옥션 전송 실패·결과 충돌 검색](2026-09-06-marketplus-issue-search.md)도 로컬 구현·검증했다.
