# 상품 관리 개편 — 구현 진행 기록

기준: 2026-09-06. [Q&A 결정 기록](2026-09-05-products-redesign-discovery.md), [필드·동기화 설계](2026-09-05-products-field-rules-and-sync-design.md), [백엔드 데이터·API 계약안](2026-09-06-products-backend-contract.md), [클릭 가능한 전체 화면 시안](2026-09-05-products-workspace-preview.html).

전체 개편 진행 중이다. 검색·목록·숫자 미리보기·가격 설명·무게 정밀도 확장은 2026-09-06 운영 배포했다(`02142157`). 운영 Chrome·읽기 전용 API 검증도 완료했다. 상세한 버전·백업·검증·복구 절차는 [운영 배포 기록](2026-09-06-products-deployment.md)을 따른다.

**이후 실제 편집 저장·필드별 제한·변경 이력·미반영 대상 기록과, 확정 삭제/영구 금지의 연결 해제까지 로컬 구현·검증했으며 아직 배포하지 않았다.** 단건 및 숫자 일괄 변경을 검토 후 DB에 저장하며 충돌·중복 재시도를 보호한다. 스마트스토어 상태 조회와 판매자 확인 근거를 연결 해제에 반영하고, 마켓별 해제 이력·쓰기를 차단하는 조건·Q15 편집 잠금 해제를 연결했다. 카페24와 G마켓·옥션은 상태를 구분한다. 선택 상품의 스마트스토어 일괄 조회·DB 작업 복구·429 재시도도 후속 구현했다. 스마트스토어의 전체 활성 연결 정기 접수와 계정 확인 저장도 후속 구현했다. 이후 [후속 구현](2026-09-06-products-followup-workflows.md)에서 쿠팡·11번가·카페24의 명시적 상태 판정, 스마트스토어·쿠팡·카페24의 가격 전용 전송/재조회 큐, 스마트스토어 선택 등록/재조회와 판매용 설정 수량을 추가했다. 전체 필드·전체 마켓의 전환은 진행 중이며 이 후속 코드도 운영 미배포다.

현재 구현 범위와 제약은 [편집 저장](2026-09-06-products-edit-save.md), [Q21·Q22 및 금지 사례](2026-09-06-products-market-presence.md), [연결 해제 구현 기록](2026-09-06-products-connection-lifecycle.md)을 따른다. 연결 단계 458건에 이어 [선택 상품 조회 작업](2026-09-06-products-inspection-jobs.md)의 핵심·회귀 검사 164건과 Chrome 실제 React 가상 응답 검증을 통과했다. 두 검사 집계는 범위가 다르다. Q23은 하루 1회 + 선택 즉시 확인, Q24는 현재 연동된 한 계정으로 확정했다. [정기 확인·계정 저장](2026-09-06-products-daily-inspection.md)을 추가해 최신 관련 검사 173건 및 Chrome 검증을 통과했다. 저장한 확인 계정과 일치하는 정확한 404 `NOT_FOUND`만 삭제로 판정하며, 계정 변경 시 정기 확인과 부재에 의한 해제를 보류한다. 이 단계도 운영 미배포다. 새 연결 보호를 모르는 구버전과의 혼합 운영·롤백 시 쓰기 중지가 필요하므로 운영 반영은 해당 기록의 전환 조건을 따른다.

최신 후속으로 [복합 마켓 검색과 라이브 API 확인](2026-09-06-products-composite-search-and-live-api.md)을 추가했다. 등록/미등록 마켓 AND, 미반영 DB 변경 필터와 빠른 조건을 구현하고 백엔드 51건·임시 PostgreSQL 16·실제 React 크롬 검증을 통과했다. 검색용 8번째 DDL을 포함해 이 단계도 운영 미배포다. 라이브 크롬에서 11번가 가격 수정 문서는 확보했으며 재고 문서 대조와 가격 인상 시 협의 혜택 처리 Q28은 확인 중이다.

이후 사용자 라이브 크롬에서 [카페24 최신 문서 대조](2026-09-06-cafe24-live-api-contracts.md)를 수행했다. 품목 GTIN 수정·조회, 품목 재고수량, 이미지·HTML 및 세금 계산별 가격 요청 필드를 확인했다. 새 가격 작업에 세금 계산·상품 설정 검사를 추가해 잘못된 가격 필드 전송을 보류하며 관련 38건과 형식 검사를 통과했다. 이후 사용자 승인으로 카페24 `younzara` 앱의 API 버전 설정을 **2021-09-01 → 2026-09-01**로 변경하고 새로 고침·앱 재선택으로 저장을 확인했다([변경 기록](2026-09-06-cafe24-api-version-upgrade.md)). 외부 앱 설정 변경은 완료했으며, 앞서 구현한 상품 관리 후속 코드의 운영 배포와는 별개다. 무옵션 품목·G마켓/옥션 계약은 확인 중이고 후속 코드는 계속 운영 미배포다.

이후 [카페24 재고·GTIN 보완](2026-09-06-cafe24-inventory-and-gtin-verification.md)에서 운영 상품 3개를 GET 12회로 대조해 실제 응답 버전 2026-09-01과 무옵션 단일 품목 재고 구조를 확인했다. 기존 재고의 잘못된 필드 전송·바코드의 첫 품목 선택·재조회 없는 성공·일부 필드 성공의 전체 완료 처리를 보완했고 관련 180건이 통과했다. 샘플 3개는 모두 마켓플러스 연동 T이므로 별도 전달 계약 확인 전 새 전송 경로에서 보류한다. 재고용 영속 큐·시스템 품절 중지 이력 기반 자동 복구·무옵션 GTIN 쓰기 검증은 남아 있으며 이 단계도 운영 미배포다.

사용자 지적에 따라 [마켓플러스 자동 전송을 재조사](2026-09-06-marketplus-auto-forwarding-recheck.md)했다. 공식 도움말에서 카페24 수정 → 마켓플러스 → 연동 마켓의 자동 반영 구조를 확인했다. Q25의 별도 공개 API 문서 요구는 철회하고, 현재 계정의 자동 전송·필드별 상속 설정과 API별 전달·전송 결과 확인으로 범위를 정정했다. `market_sync=F`인 상품만 허용하는 현재 로컬 제한은 검증 전 임시 제한이며 이번에는 실행 코드를 바꾸거나 배포하지 않았다.

[마켓플러스 실제 설정·전송 이력](2026-09-06-marketplus-live-settings-and-results.md)을 이어서 확인했다. 자동전송과 품절 전송은 사용 중이고 두 계정 모두 카페24 진열/판매상태를 연동한다. 카페24 품절 저장 성공 후 두 마켓 전송이 실패한 표본, 옥션 이미지만 별도 관리인 표본을 확인했다. 상품번호만으로 G마켓·옥션을 정상 표시하던 배지를 ‘반영 미확인’으로 보완하고 API 검사 20건·프론트 정적 검사·빌드·Chrome 검증을 통과했다. 가격 설정 조회의 실제 403도 확인했다. 결과 자동 수집·재시도·권한 보완·새 필드 전달 검증과 운영 배포는 남아 있다.

이어 [마켓플러스 전송 이력 가져오기](2026-09-06-marketplus-transmission-import.md)를 로컬 구현했다. 라이브 Chrome의 현재 페이지 수집 파일 → 계정·상품 식별자 교차 확인 → 행별 중복 방지 저장 → 상품 상세 전송 이력 표시를 연결했다. 실제 완료/실패 각 20행을 파일로 수집했으며 운영 DB에 업로드하지 않았다. 백엔드 24건·수집기 5건·React Chrome 상호작용·프론트 정적 검사/빌드를 통과했다. 카페24 인증 URL에 `mall.read_store`를 추가했으나 실제 재인증과 403 재검증은 남아 있다. 여러 페이지의 정기 수집·그리드 실패 필터·자동 재전송과 운영 배포는 후속 범위다.

다음 단계에서 [마켓플러스 여러 페이지 수집·재개 및 목록 배지](2026-09-06-marketplus-pagination-and-grid.md)를 연결했다. 실패 5페이지 100행을 읽고 부분 수집으로 기록했으며, 최신 관측/같은 분의 충돌/과거 연결 구분을 목록까지 전달한다. 백엔드 78건·Python 12건·프론트 파서 4건과 Chrome 상호작용을 검증했다. 가격 설정 403은 `insufficient_scope`로 확인했고 개발자센터 로그인 요청을 남겼다. 이 후속 단계도 운영 미배포이며 정기 수집·실패 검색·자동 재전송은 남아 있다.

사용자 로그인 후 [재인증 경로와 가격 설정 권한 표시](2026-09-06-cafe24-reauthorization-scope.md)를 보완했다. 프론트의 별도 인증 URL에서 권한이 누락되는 경로를 제거하고, 저장된 계정의 서버 URL·가격 설정 실제 조회·실패 시 과거 정상 표시 제거를 연결했다. 백엔드 56건, 실제 설정 컴포넌트의 가상 응답 Chrome 상호작용 6가지, 정적 검사·빌드를 통과했다. 개발자센터의 Store 읽기 권한을 추가·저장·새로 고침으로 확인했고, 사용자 쇼핑몰 로그인 후 **20:31 KST 운영 재인증과 가격 설정 403 해결을 완료했다.** 기존 12개 + Store 읽기 권한이 있는 토큰을 DB에 저장했으며 권한·가격 설정·상품·주문 GET 6회가 모두 200이었다. 실제 가격 기준 S와 표본 상품의 수동 세금 M도 확인했다. 이 인증정보 갱신과 별개로 후속 코드는 계속 운영 미배포다. 운영 자격증명의 `is_active=false`와 새 마켓플러스 이력의 활성 조건이 불일치하는 점을 발견해 추가 배포 점검 사항에 기록했다.

이어 [마켓플러스 전송 실패·결과 충돌 검색](2026-09-06-marketplus-issue-search.md)을 구현했다. 여러 SB코드·소싱처·재고·등록/미등록 조건과 함께 G마켓/옥션의 현재 전송 이슈를 DB에서 필터링하며, 목록 배지와 같은 최신 관측·충돌 판정 기준을 사용한다. 계정 설정 누락/비활성을 조회 0건으로 숨기지 않는 준비 상태 API와 화면 안내도 추가했다. 백엔드 107건, 실제 PostgreSQL JPA 23건 재검증, Chrome 상호작용 8개 묶음과 프론트 검사를 통과했다. 이 단계 역시 운영 미배포다. 전수 정기 수집·서버 업로드·자동 재전송과 통합 배포는 남아 있으며, 카페24 재인증/403 해결은 이미 완료된 상태다.

다음으로 [서버 전용 마켓플러스 수집기·저장 재개](2026-09-06-marketplus-server-observer.md)를 구현하고 브라우저/수집기 두 서비스만 서버에 설치했다. 페이지별 저장 기록·응답 유실 재개·전역 429 대기·제외/재시도 구분과 동작 중단을 표시하는 상태 API·목록 화면을 추가했다. 설치 당시 백엔드 38건·Python 39건 및 Chrome 상태 표시 8개 묶음을 검증했다. 기존 API·프론트와 DB는 이 설치에서 변경하지 않았다.

**2026-09-07 [로그인 후 실제 수집·통합 배포 사전 검사](2026-09-07-marketplus-login-and-release-check.md):** 서버 브라우저 로그인·계정 대조 완료. 완료 탭 기본 주소와 가변 아이콘 표기에 대응해 완료·실패 각 200행을 수집했고, 누적 중복 제거 관측 402건 모두 운영 상품 연결과 읽기 전용 대조가 일치했다. 자동 수집은 사용 중이고 DB 업로드는 중지다. 운영 DB 복사본에 9개 DDL을 두 번 적용해 상품 3,195행·연결 9,920행의 기존 값 보존을 확인했다. 전체 앱 기동 검사에서 상품 저장소 중복 빈을 발견해 수정했다. 통합 배포·DB 업로드와 마켓 자동 재전송은 아직 남아 있다.

아래는 최초 운영 배포 범위와 각 구현 당시 검증 기록이다. 전체 개편 완료나 시안 전체의 구현을 뜻하지 않는다.

## 실제 코드에 반영한 범위

- `POST /api/v1/products/search`: 읽기 전용 검색. JSON으로 여러 SB코드를 받아 긴 URL과 쉼표가 포함된 브랜드명 분할 문제를 피한다. 기존 GET 목록은 유지한다.
- SB코드의 쉼표/LF/CRLF 분리, 공백·중복 제거, 대소문자 정규화, 정확 일치 검색. 다른 필터와 AND로 결합하고 DB에서 필터링한 뒤 페이지 처리한다.
- 브랜드 다중 필터, 전체 활성 상품에서 조회하는 브랜드 선택지 API. 빈 브랜드와 폐기 상품은 선택지에서 제외한다.
- 통합검색에 DB 바코드 추가. 선행 0을 유지하고 검색어의 `%`, `_`, `!`를 SQL 와일드카드로 취급하지 않는다.
- 검색 패널 재구성: 통합검색, SB코드 붙여넣기, 소싱처·브랜드·재고 선택, 추가 조건 펼치기, 초기화.
- 목록에 DB 묶음수량과 재고 수량 표시. 상품명은 소싱처의 HTTP(S) 원본 URL을 새 탭으로 열고, 상세 편집은 별도 버튼으로 제공한다.
- 촘촘한 행 간격 기본값과 넓게 보기 전환. 조회 실패와 검색 결과 없음 구분, 검색 조건 변경 시 선택 초기화, 이전 조건의 임시 결과에서는 선택·일괄 작업 차단.

프론트는 새 검색 API를 사용하므로 배포 시 프론트·백엔드를 함께 반영해야 한다. 실제 목록의 기존 마켓 필터는 연결 기록 ANY 조건이다. 아래 새 동기화 모델의 등록/미등록 AND 조건과 혼동하지 않게 표기했다.

## Q18 확정 및 미리보기 반영

판매가는 100원 단위 반올림, 재고·묶음수량은 비율 계산 후 소수 부분 버림으로 확정했다. 300원·900원은 예시이며 끝자리 제한으로 구현하지 않는다. 무게·용량의 단위별 정수/소수 첫째 자리 표시 선호도 기록했다. Q19 무게 단위는 kg로 확정했고, 아래와 같이 저장 정밀도 확장 코드를 준비했다. 운영 상품값은 변경하지 않았다.

미리보기 숫자는 천 단위 구분을 표시하면서 API의 정확한 소수 문자열을 유지한다. 판매가 반올림·수량 버림이 있으면 계산 원값과 처리 후 값을 별도로 표시한다. 제외된 결과는 `변경 예정값 없음`으로 표시하고 계산 원값·제외 사유를 제공한다.

- 판매가: 값 지정·증감·비율 연산 후 100원 단위 HALF_UP을 한 번 적용. 12,345→12,300 / 12,650→12,700. 12,349.5를 원 단위로 먼저 반올림하지 않아 이중 반올림 오류를 피한다.
- 수량: 비율 계산 4.5→4. 직접 지정·증감은 정수 입력을 요구한다. 묶음수량 1개 미만·음수·저장 범위 초과는 제외한다.
- 다른 수치 필드는 저장 정밀도를 초과하면 제외한다. 일반 `ROUND`로 원가·무게·용량까지 일괄 반올림하는 요청은 제거했다.
- 서버 기본값과 프론트는 `APPLY_FIELD_RULES`를 사용한다. 엄격 검사용 `REJECT`는 반올림·버림이 필요한 값을 제외할 수 있으며, 미승인 범용 반올림을 허용하지 않는다.
- 이 수치 미리보기 자체는 원가·수수료를 포함한 최소마진 보장 검사가 아니다. Q20 확정 후 자동 가격 계산과 마켓별 등록가·배치에는 아래의 별도 계산·설명 경로를 연결했다. 일괄 변경의 실제 저장은 아직 제공하지 않는다.

Q18 규칙 적용 검증: Core 50건(계산기 45·유스케이스 5), API 9건 통과. 100원 반올림의 양방향·중간값·이중 반올림 방지·이미 정렬된 가격·반올림 후 범위 초과·수량 버림·다른 필드의 정밀도 보존을 포함한다. TypeScript·수정 파일 ESLint·Spotless 통과. 실제 React 미리보기를 Chrome에서 가상 응답으로 검증해 12,345→12,300 / 12,650→12,700 및 두 수량 필드의 4.5→4 표시, 입력 계약, 입력 변경 후 이전 결과 제거, 범위 초과·조회 오류·재시도를 확인했다. 브라우저 검증 자료는 `/private/tmp/sbshop-numeric-browser`, 화면은 `/private/tmp/sbshop-numeric-preview-react.png`에 보존했다.

초기 숫자 표시 변경 당시에는 정밀도 보존 테스트 2건, TypeScript, 해당 TS/TSX 파일 ESLint, `git diff --check`를 통과했다. 이후 Q18 계산 규칙과 Chrome 검증은 위 항목에 기록했다. Q18 브라우저 자료는 `/private/tmp/sbshop-numeric-browser/q18-source-harness.tsx`, `q18-result.html`, `q18-preview.png`에 별도로 보존했다.

## Q19 확정 후 — kg 표준과 신규 입력 보완

- 소싱 초안의 g를 상품 생성 전에 kg로 정확히 변환한다. 잘못된 무게는 초안을 등록 중으로 바꾸거나 마켓 작업을 시작하기 전에 거부한다.
- 상품 무게 열의 정밀도를 `numeric(10,2)`에서 `numeric(13,5)`로 확장하는 엔티티 변경과 검토용 DDL을 준비했다. 125.01g를 0.12501kg로 보존하며 기존 정수 8자리 범위도 유지한다.
- 생성·수정 커맨드는 kg 기준 저장 범위와 정밀도를 검사한다. 수치 미리보기에도 같은 저장 정밀도를 적용한다. Q18의 표시 선호를 이유로 실제 중량을 반올림하지 않는다.
- 신규 상품 화면은 중량 입력 단위를 kg로 표시하고, 기존 상세 화면에는 kg 입력 예시와 기존 값의 단위 확인 안내를 넣었다.
- 기존 값·연결된 초안의 g/kg 값·원본 URL·수정 시각을 대조하는 읽기 전용 SQL을 준비했다. 일치 여부는 조사 단서이며 변환 확정이 아니다. 기존 값의 변환·확인 이력 저장·상품별 확인 상태 API는 아직 구현/실행하지 않았다.

적용 순서와 남은 범위는 [무게 단위 전환 기록](2026-09-06-products-weight-normalization.md)을 따른다. 운영 DB에 DDL·값 변환을 실행하거나 새 코드를 배포하지 않았다.

검증: Core 68건·API 16건 통과. 신규 무게 경로 9건과 H2 기반 정밀도/입력 검사 6건을 포함한다. 프론트 TypeScript·수정 파일 ESLint, 변경 Java 파일 Spotless, 문서 링크 검사 통과. PostgreSQL SQL 실행 검증과 운영 데이터 조사는 미수행이다.

## Q20 확정 후 — 자동 가격과 최소마진 보정

확정 정책: 100원 반올림가가 최소마진 하한보다 낮으면 그 하한을 충족하는 100원 단위로 조정하고 사유를 표시한다. 예: 반올림가 12,300원 / 하한 12,340원 → 최종가 12,400원.

- `SalePriceRounding`을 공통 계산기로 추가했다. 가격 산식의 나눗셈도 원 단위를 거치지 않고 100원 자리에서 직접 반올림해 이중 반올림을 피한다. 기존 정수 변환으로 인한 큰 금액의 오버플로와 이미 100원 단위인 값에 다시 100원을 더하던 계산을 제거했다.
- `MarginCalculator`의 기존 호출 방식은 유지하며 결과를 공통 규칙으로 계산한다. 최소마진 하한은 기존 정의(쿠폰 적용 매입가 × 묶음수량 + 국내 배송비 + 최소마진)를 사용한다. 0원으로 반올림되는 자동 판매가와 분모가 0 이하인 계산은 오류로 처리한다.
- `MarketSalePriceResolver`에 마켓별 반올림가·하한·최종가·보정 사유 설명을 추가하고 등록가/동기화 계산과 공유한다. 기준가 대체 계산도 100원 반올림하지만 원가 자료가 없으므로 최소마진 확인 완료로 취급하지 않는다.
- 배치에서 계산한 가격에 소싱처별 국내 배송비·무료배송 기준을 함께 전달하여 마켓 계산에서 기본 6,000원으로 되돌아가지 않도록 했다. 상품 등록 시 마진·쿠폰·최소마진을 모두 지정해도 소싱처 배송비 규칙은 유지한다.
- 배치 작업의 결과 메시지에는 최소마진으로 가격이 올라간 경우 반올림가·하한·최종가와 사유를 남긴다.
- `GET /api/v1/products/{id}/price-preview`와 상품 상세의 ‘마켓별 가격 계산 근거’ 버튼을 연결했다. 지원하는 직접 연동 마켓의 현재 DB·정책 기준 등록가를 계산한다. 외부 API 호출 없이 금액을 정확한 소수 문자열로 반환하며, 마켓별 계산 실패·최소마진 미검증을 구분한다. 재조회 중/실패 시 이전 성공 결과를 숨기고 상품 전환 시 이전 상품 가격을 사용하지 않는다.
