# 마켓플러스 전송 실패·결과 충돌 검색

2026-09-06. [전송 이력 수집과 목록 배지](2026-09-06-marketplus-pagination-and-grid.md)의 후속 구현이다. **로컬 구현·검증이며 운영 미배포다.** 이번 단계에서 운영 상품 수정, 재전송, 운영 DB 변경은 실행하지 않았다.

## 화면과 검색 범위

상품 관리의 ‘G마켓·옥션 전송 이슈’ 빠른 조건과 상세 조건의 ‘전송 실패 / 성공·실패 결과 충돌’을 추가했다. 여러 SB코드, 소싱처·브랜드·재고, 등록/미등록 마켓 등 기존 조건과 AND로 결합한다. 조건을 적용하면 첫 페이지로 이동하고 상품 선택을 해제한다. 전송 조건 태그만 닫으면 나머지 조건은 유지한다.

이 필터는 현재 연결과 일치하는 **수집된 마켓플러스 이력**을 대상으로 한다. 전체 마켓의 실패 필터나 미수집 상품의 정상 판정이 아니다. 해당 범위를 화면에 표시한다. 실패 배지에서 기존 상품 전송 이력 창을 열어 원문 사유·시각을 확인할 수 있다.

[검증 화면](2026-09-06-marketplus-issue-search-preview.png)은 실제 React 컴포넌트에 검증용 API 응답을 준 Chrome 화면이다.

`POST /api/v1/products/search`의 선택 필드:

| `marketPlusIssue` | 의미 |
| --- | --- |
| 생략·`null`·`ALL` | 전송 결과로 제한하지 않음 |
| `ANY_ISSUE` | 최근 실패 또는 성공·실패 충돌 |
| `FAILURE` | 해당 마켓의 목록 요약이 전송 실패인 상품 |
| `CONFLICT` | 해당 마켓의 목록 요약이 결과 충돌인 상품 |

G마켓과 옥션 사이는 OR다. 한 마켓에 충돌과 다른 종류의 실패가 함께 있으면 그 마켓은 충돌로 분류한다. 다른 마켓에 별도의 실패가 있으면 그 상품은 실패와 충돌 양쪽 검색에 포함될 수 있다.

## 서버 판정

- 카페24와 해당 하위 마켓이 모두 현재 연결이어야 한다. 쇼핑몰, shop 1, 판매 계정, 연결 ID, 시스템 상품 ID, 카페24 상품번호·코드, 하위 마켓 상품번호가 정확히 일치해야 한다.
- 계정 범위는 서버 설정과 저장된 카페24 계정에서 결정한다. 검색 요청에서 판매 계정을 지정하지 않는다. 조회 전후 계정 범위가 바뀌면 다시 조회하도록 오류를 반환한다.
- 같은 연결·계정·상품·전송 종류 안에서 원격 완료 시각이 가장 최근인 이력을 사용한다. 수집/저장 시각으로 최신을 판정하지 않는다. 다른 전송 종류의 성공은 실패를 해소하지 않는다.
- 같은 완료 시각에 성공과 실패가 함께 있으면 수집 순서로 성공을 선택하지 않고 충돌로 표시한다.
- 이 조건을 DB의 EXISTS/NOT EXISTS로 평가한 뒤 건수 계산과 페이지 처리를 한다. 현재 페이지에서 걸러 내거나 전체 상품 ID를 메모리로 가져오지 않는다.
- 과거 연결, 다른 shop·계정·시스템 상품, 바뀐 상품 식별자의 관측은 현재 목록·검색에 사용하지 않는다. JSON 배열·객체·참/거짓 값을 상품번호로 인정하지 않는다. 가져오기·목록·이력의 식별자 검사도 맞췄다.

## 조회 불가와 운영 설정

`GET /api/v1/marketplus/transmissions/readiness`는 사용 가능 여부와 설정 확인 사유만 반환한다. 카페24 계정의 부재/비활성 또는 G마켓·옥션 판매 계정 설정 누락을 화면에서 확인하고 재조회할 수 있다. 인증정보는 응답에 포함하지 않는다.

설정이 준비되지 않은 전송 이슈 검색은 HTTP 400과 사유를 반환한다. 일반 상품 검색은 계속 사용할 수 있다. 화면은 실패 시 이전 상품의 선택·일괄 작업과 페이지 이동을 막고, 헤더와 하단에도 ‘조회 실패’를 표시한다. 오류를 검색 0건이나 수집 이력 없음으로 표시하지 않는다.

[재인증](2026-09-06-cafe24-reauthorization-scope.md)과 가격 설정 403 해결은 이미 완료했다. 하지만 운영 카페24 자격증명의 `is_active=false`는 이번에 바꾸지 않았다. 기존 상품/주문 경로와 새 이력 경로의 활성 조건 차이는 여전히 통합 배포 전 확인 항목이다. 이 경고를 숨기거나 활성화 사유를 추정하지 않는다.

배포 준비에는 기존 미배포 DDL들과 함께 다음 두 파일의 최신 내용이 필요하다. 새 DDL 개수는 늘지 않고 기존 8·9번째 파일을 확장했다.

- `backend/docs/ddl/2026-09-06-market-search-identifiers.sql`: 현재 최상위 식별자 정확 비교 함수 `sb_market_identifier_equals` 추가.
- `backend/docs/ddl/2026-09-06-marketplus-transmissions.sql`: `(registration_id, market, transfer_type, completed_at DESC)` 인덱스 추가.
- API 프로세스의 `MARKETPLUS_GMARKET_ACCOUNT`, `MARKETPLUS_AUCTION_ACCOUNT` 설정과 카페24 계정 확인이 필요하다. 일반 코드의 실계정 기본값은 비워 둔다.

## 검증

- 백엔드 **107건** 통과: Core 66, API 41. 최신 시각/전송 종류/충돌 우선순위, 현재 연결·계정·식별자, 복합 조건·페이지별 총수, 준비되지 않은 계정, API 바인딩/오류, 기존 목록 배지를 검증했다.
- 임시 PostgreSQL 16에서 실제 JPA 통합 검사 **23건**을 재실행했다. 위 Core 검사와 중복되므로 107건에 더하지 않는다. 별도로 식별자 존재 15경우·정확 비교 17경우 및 상품 10,000개 복합 조건 SQL 검증을 수행했다. 도구는 임시 컨테이너를 종료·제거하며 운영 DB에 접근하지 않는다.
- 실제 React를 실행한 Chrome에서 8개 검증 묶음 통과: 일반 조회와 설정 경고, 복합 조건·붙여넣기·페이지/선택 초기화, 설정 확인 후 검색 복구, 충돌 조건·배지, 태그 해제, 설정 조회의 통신 실패·재시도, 상품 이력 오류·재조회, 외부 쓰기 미호출.
- TypeScript, 변경 파일 ESLint 오류 0, Vite 빌드, 변경 Java Spotless 검사, diff 공백 검사. 기존 TanStack Table 호환 경고와 번들 크기 경고는 남는다.

[검증 집계](evidence/2026-09-06-marketplus-issue-search-checks.json). 재현 자료는 `/private/tmp/sbshop-marketplus-search-browser`, 서버 검사 로그는 `/private/tmp/sbshop-mp-search-final-tests.log`와 `/private/tmp/sbshop-mp-search-final-postgres.log`에 있다. PostgreSQL 검사는 `python3 backend/tools/verify-market-search-postgres.py --marketplus-jpa`로 실행한다.
