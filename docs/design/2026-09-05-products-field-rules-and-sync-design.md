작성일: 2026-09-05. 요구사항 결정 기록은 [Q&A 문서](2026-09-05-products-redesign-discovery.md)를 기준으로 한다.

이 문서는 현재 코드, 확보한 API 원문, 사용자 설명을 구분해 기록한 조사 작업물이다. 전체 필드의 운영 검증을 완료한 지원표가 아니다. 미확인 값이나 쓰기 경로를 구현에 추측으로 채우지 않는다.

## 3. 자동 이름·규격에 대한 의존성

기존 코드에는 `Product.assembleMarketName`과 `ProductNameComposer.compose`의 다른 이름 조합 경로가 있다. 전자는 용량을 정수화하고 후자는 소수 표현을 유지한다. 새 설계에서는 조합 규칙과 버전을 명시하고, 기본명·브랜드·용량·단위·묶음수량 변경이 상품명·규격·옵션·상세·단위가격에 미치는 영향을 함께 계산한다.

쿠팡의 `unitCount`는 재고 수량이 아니라 구성품 수에 따른 단위가격 계산을 위한 값이다[S1]. 스마트스토어의 단위가격 총용량은 판매 상품의 총 용량/수량을 뜻한다[S2]. 현재 `SmartstoreUnitCapacity`는 DB 용량을 직접 사용하므로 DB 용량이 단품 기준인지 묶음 총량인지 확인 없이 곱셈을 추가하거나 현행 값을 옳다고 확정하지 않는다.

## 4. 수정 잠금 정책의 표현

필드 지원은 하나의 boolean으로 두지 않고 다음 정보로 표현하는 안이다.

- 어느 마켓·계정·상품 유형·현재 상태에 적용되는 규칙인지.
- 수정 가능 / 심사 후 가능 / 등록 후 불변 / 내부 전용 / 근거 미확인의 구분.
- 요청 필드와 검증할 조회 필드, 필요한 선행 값·파생 필드.
- 제한 근거·문서 버전·조사 시각, 사용자에게 보여줄 잠금 사유.

규칙 적용 제안:

1. 현재 활성 연결된 관련 마켓이 해당 필드의 변경을 금지하면 시스템상품에서도 잠금한다. 상품명 조합 필드로 우회하는 변경도 같은 판정을 적용한다. 모든 연결이 해제되면 편집을 허용하고 과거 값·해제 사유·상품번호를 보존한다(Q15 확정). 조회 실패는 연결 해제가 아니다.
2. 심사 후 가능한 변경은 Q5대로 DB 편집을 허용하고, Q6대로 수동 확인 후 전송한다.
3. 필드가 마켓에 존재하지 않는 경우와, 마켓에 값이 있으나 수정할 수 없는 경우를 구분한다. 전자는 내부 업무값으로 관리할 여지가 있고 후자는 불일치 방지를 위한 잠금 대상이다.
4. 카페24 바코드는 쓰기 지원으로 가정하지 않는다. 외부에 보존된 바코드 값이 있는지까지 확인하기 전 ‘해당 없음’ 또는 ‘수정 가능’을 일괄 확정하지 않는다.
5. 개별 편집·일괄 편집·크롤 반영·배치·신규 등록이 같은 정책을 사용해야 한다. 조회 실패를 이용해 잠금 검사를 통과시키지 않는다.

## 6. 백엔드 구성 제안

### 상품 변경과 외부 작업 분리

시스템상품 변경 저장, 변경 이력, 자동 반영 대상 기록을 하나의 DB 트랜잭션으로 처리하는 안이다. 외부 API 호출은 해당 트랜잭션 밖의 작업자가 실행한다. 워커 재시작·중복 실행에 대비한 작업 소유권과 복구 정보가 필요하다.

| 구성 | 책임 |
| --- | --- |
| 상품 편집 정책 | 현재 연결·상품 유형·마켓 상태·파생 필드를 기준으로 편집 가능 여부와 사유 반환 |
| 상품 변경 기록 | 상품 버전, 변경 필드·전후값, 변경 출처, 사용자가 확인한 변경 스냅샷 보존 |
| 마켓별 목표 정보 | 상품 정보와 가격·이름·템플릿 정책으로 해당 마켓에 반영할 값 산출 |
| 마켓 관측 정보 | 마켓이 실제 반환한 값·존재·판매상태·시각·확인 실패 근거 보존 |
| 마켓 작업 | 상품×마켓×요청 종류×변경 스냅샷, 필드별 실행/접수/심사/검증/실패 기록 |
| 수집 결과 | 소싱처 원본, 수집 시도/성공, 변경 내용, 이미지별 결과, 시스템 적용 이력 |
| 등록 이력 | 활성 연결과 과거 삭제/영구금지된 리스팅·상품번호·사유 보관 |

### 필드별 결과가 필요한 이유

가격과 상품명을 같은 시점에 저장해도 어떤 마켓에서는 가격만 자동 반영되고 상품명은 사용자 확인·심사 대기가 남을 수 있다. 결과에는 최소한 다음을 구분한다.

- 실제로 반영을 확인함 / 조회 결과 이미 같았음.
- 요청 접수 / 심사 대기 / 반영 확인 대기.
- 사용자 확인 대기 / 잠금 / 근거 미확인 / 미지원.
- 재시도 가능한 실패 / 데이터 수정 필요 / 정책 차단 / 조회로 확인 불가.

가격 한 필드의 성공이 다른 필드의 실패·미반영 상태를 지우면 안 된다. 마켓별 목표 데이터는 원시 DB값과 다를 수 있으며, 이미지 호스팅 URL·HTML 정규화·가격 정책으로 생기는 정상적인 차이도 고려한다.

### 자동·수동 요청의 합류

Q6에 따라 심사 없는 변경은 자동 대기열에 들어간다. 심사 변경은 사용자가 마켓과 전후값을 확인한 스냅샷으로 수동 시작한다. 수동 클릭과 스케줄러가 같은 작업을 중복 생성하지 않도록 설계한다.

전체 JSON/XML 요청이 필요한 마켓에는 새로 읽은 외부 원본을 기준으로 허용된 변경만 병합한다. 자동 가격 반영에 아직 사용자가 확인하지 않은 상품명 변경이 섞이지 않도록 한다. 필수 필드 보정이 필요한 경우도 어떤 변경이 추가되는지 결과에 남긴다.

작업 중 상품이 다시 수정되면 과거 버전의 성공은 과거 버전에만 기록한다. 등록·편집·마켓 작업이 동시에 실행될 때 잠금 판정과 변경 버전이 서로 어긋나지 않도록 동시성 제어가 필요하다.

### 호출 제한·실패·재시도

- 마켓·계정·엔드포인트 범위의 제한을 조사해 같은 제한을 공유하는 작업끼리 조절한다. 구체적인 호출 수치는 현재 확정하지 않는다.
- 429와 일시 장애는 서버의 재시도 안내가 있으면 준수하며 대기·재시도 상태와 다음 시각을 표시한다.
- 데이터 거절과 영구 판매금지는 무조건 반복 전송하지 않는다. 필요한 조치와 실행 중지 사유를 표시한다.
- 등록 요청 타임아웃은 ‘등록 실패 확정’이 아니다. 외부 생성 여부를 확인하기 전 같은 상품을 다시 생성하지 않는다.
- 조회 실패는 삭제·영구금지·품절의 증거가 아니다. 쓰기와 조회의 성공·실패를 각각 보존한다.

### 연결 해제와 재등록 — Q8·Q9 반영

| 원인 | 활성 연결 | 자동 쓰기 | 등록 후보 |
| --- | --- | --- | --- |
| 일시 품절 | 유지 | 정상 재고 관리 대상. 소싱처 품절 시 판매 중지·재입고 시 판매용 수량으로 복구(Q10 확정) | 이미 연결된 마켓이므로 신규 등록 대상으로 오인하지 않음 |
| 규칙 위반 등에 따른 영구 판매금지 확정 | 해제 | 제외 | 금지 이력과 사유 보존. 연결 해제만으로 등록 가능 판정하지 않음 |
| 삭제 확정 | 해제 | 기존 리스팅 동기화 제외 | 과거 삭제 사유와 함께 후보 포함, 사용자가 선택 재등록 |
| 원인 미확인 / 일시 조회 실패 | 해제하지 않음 | 현재 근거와 오류 유형에 따라 대기·확인 | 미등록/삭제로 추측해 재등록하지 않음 |

과거 상품번호와 주문 참조를 지우지 않고 새 등록 시 새로운 리스팅 이력을 추가하는 안이다. 삭제 사유가 API에 없다면 ‘마켓에서 사유 미제공’으로 표시하며 추측으로 채우지 않는다. 카페24와 G마켓·옥션은 각 상태와 전송 결과를 별도로 기록해야 한다.

## 7. 현재 남은 확인 항목

1. Q10~Q15 확정. 판매용 수량 기본값 300. 기존 stock은 그대로 보존하고 별도 판매용 수량 도입·전환을 설계한다. 상품명은 소싱처 원본 링크, 상세정보는 최신 공통 템플릿 비교·선택 반영.
2. 카페24 GTIN은 지원 근거 미확보로 보류. 품목 재고·추가 이미지·제조사 코드의 최신 쓰기/조회 계약 대조.
3. 11번가 company의 정확한 구조·상품 유형 적용, 재고/무게 변경 문서, 상품 유형별 카테고리 제한.
4. 스마트스토어의 상품 유형별 요청 스키마, 채널명·카탈로그 연계·옵션 재고·용량/총량 정의.
5. 쿠팡의 필드별 승인·옵션·노출명 반영 확인과 제한, 일시 품절/영구금지 판정 코드.
6. 카페24→G마켓/옥션 자동 전송 경로·권한·확인 가능한 결과와 각 마켓 상태의 근거. 기존 수동 안내나 과거 스파이크를 최신 API 근거로 대체하지 않음.

확인되지 않은 부분은 해당 기능의 구체 설계·구현 전에 필요한 자료를 좁혀 요청한다. UI의 전체 필드 편집 요구를 충족하려면 내부 전용, 외부 대응값 있음/수정 불가, 미확인 필드를 구분한 최종 정책표가 필요하다.

## 8. Q14/Q15에 따른 구현 계약

아래 저장 구조는 확정 정책을 구현하기 위한 설계안이며 아직 마이그레이션하거나 운영에 적용하지 않았다.

- `sales_stock_quantity`: 상품의 판매용 설정 수량. 초기 기본값 300. 기존 `logisticsInfo.stock`의 999를 실제 소싱처 확보 수량으로 해석하지 않는다.
- 소싱처 판매 가능 여부와 판매용 설정 수량을 분리한다. 일시 품절일 때 마켓 목표는 판매 불가이며 설정 수량은 보존한다. 재입고되면 해당 설정 수량을 사용한다. 0 전송·판매중지 API 등 표현 방식은 각 마켓의 검증된 계약을 따른다.
- 품절·재입고 전환도 상품 버전과 마켓 작업 버전으로 기록한다. 지연된 품절 처리나 과거 재입고 작업이 더 최신 상태를 덮어쓰지 않게 한다. 영구 금지·삭제로 해제된 마켓에는 복구 요청을 보내지 않는다.
- `listing_history`: 과거 등록 ID, 등록 당시 상품값, 종료 시점, 해제 사유와 판정 근거를 보존한다. 주문 참조는 유지한다. `active_link`와 과거 이력의 존재를 구분하여 편집 잠금을 판단한다.
- 모든 마켓이 해제된 상품을 편집하는 트랜잭션과 새 마켓 등록 예약이 경쟁하지 않게 한다. 등록 작업은 확인한 상품 버전의 스냅샷을 참조하고, 예약 중 변경 발생 시 재검토한다. 이 동작은 Q15의 편집 허용과 외부 불일치 방지를 함께 만족해야 한다.
