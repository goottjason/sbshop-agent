# 소싱처 전체 배치 개편 구현·검증 기록

승인 기준: [화면·상세 동작](2026-09-08-batch-redesign-approved.md). 운영 상품의 배치 실행 없이 로컬 코드와 격리된 테스트 DB에서 검증한다. 상품 관리 화면 개편은 이번 범위에 포함하지 않는다.

## 핵심 구조

- `ProductSupplierBatchService`: 전체 활성 대상 ID와 실행 정책·마켓 계정 고정, 요청 중복 방지, 서버 페이징·집계, 일시정지/재개/재시도.
- `ProductSupplierBatchRunner`: 소싱 수집 → DB 저장 → 마켓별 가격·수량 작업을 영속 단계로 연결. 성공 단계 재사용. 실제 외부 호출은 기존 수집·마켓 작업자가 수행한다.
- `ProductSupplierBatchSource`: 배치 전용 검토를 거쳐 수집 증거와 가격 정책을 같은 상품 변경에 저장한다. 일반 소싱 저장 경로와 검토 형식을 분리한다.
- `BATCH_MANAGED` 변경 대상: 일반 자동 디스패처가 배치의 일시정지·선택 마켓 범위를 우회하지 않게 한다. 선택하지 않은 마켓의 미반영 이력도 보존한다.
- 수집과 마켓 작업자의 대기 후보 조회 및 실행 직전 검사를 통해 일시정지된 배치의 새 호출을 막는다. 이미 시작한 호출은 결과를 저장한다.
- 프론트: 코발트 블루 실행 폼, 배치별 펼침 표, 가격·수량별 상태와 확인값, 실패 원인·재시도, 가격 계산 근거·이력.

## 검증 근거

- [PostgreSQL 스키마·대상 보존](evidence/2026-09-08-supplier-batch-schema-check.json)
- [마켓 수량 일시정지·일반 작업 분리](evidence/2026-09-08-supplier-batch-stock-postgres.json)
- [로컬 Chrome 기본 화면](evidence/2026-09-08-supplier-batch-browser-main.png), [기본 화면 검사 결과](evidence/2026-09-08-supplier-batch-browser-main.json)
- [로컬 Chrome 상품 상세](evidence/2026-09-08-supplier-batch-browser-drawer.png), [상세 검사 결과](evidence/2026-09-08-supplier-batch-browser-drawer.json)

화면 검사는 예시 데이터와 격리된 HTTP 응답을 사용한다. 운영 마켓 반영 성공의 증거로 해석하지 않는다. 전체 백엔드 회귀 2,206건(core 1,742 / API 385 / worker 79)과 Chrome 18개 사용 흐름이 통과했다. 이후 일부 수집 전체 실패 정책을 확정하고 배치 29건(H2) 및 소싱/DB 22건(PostgreSQL)을 추가 검증했다. 운영 반영은 실행하지 않았다. [검증 집계](evidence/2026-09-08-supplier-batch-verification.json).

## 적용 정책과 지원 범위

- 사용자 확정 정책: 가격+재고 중 하나라도 수집되지 않으면 해당 상품 수집 전체 실패. SB 상품값 저장과 마켓 전송은 실행하지 않으며, 재시도 시 두 항목을 함께 새로 수집한다. 가격만/재고만 모드는 선택한 항목의 수집 성공을 기준으로 한다.
- 11번가 가격 변경·0개 품절 전환은 기존 검증된 API 범위에 없으므로 보류한다. 판매 중 단일 상품의 양수 수량 조정만 기존 경로로 처리한다.
- 카페24 확인 완료를 G마켓·옥션 최종 반영 완료로 표시하지 않는다.

## 배포 순서

1. 진행 중인 기존 작업과 서비스 버전을 확인하고 DB를 백업한다.
2. `backend/docs/ddl/2026-09-08-supplier-batch-orchestration.sql`을 API·작업자 교체 **전에** 적용한다. 새 작업자는 다섯 배치 테이블과 `sb_product_change_target.batch_managed`를 조회한다.
3. 검증한 동일 커밋의 API·작업자·프론트를 배포한다. 이 기록 작성만으로 운영 배포를 완료했다고 간주하지 않는다.
4. 로그인·옵션·기록 조회와 작업자 구동 상태를 확인한다. 실제 소싱처 전체 실행은 별도 사용자 실행 지시에 따른다.

롤백할 때 작업의 진행/일시정지 상태와 이미 접수된 마켓 요청을 확인한다. 배치 기록과 확인되지 않은 요청 참조를 삭제하지 않는다. 구버전은 새 배치를 처리하지 못하므로, 구버전으로 복귀했다고 미완료 작업을 성공 또는 취소로 간주하지 않는다.

사용자 안내: [새 배치 업데이트 사용법](../manual/supplier-batch-update.ko.md).
