# 카페24 → 마켓플러스 → G마켓·옥션 자동 반영 재확인

2026-09-06. 사용자가 별도 마켓플러스 API의 존재 여부와 카페24 상품 수정에 따른 자동 전송 구조를 재확인하도록 요청했다. 카페24 공식 도움말과 공개 개발자 문서를 다시 조사했다. 이 기록은 설계 정정이며, 운영 상품 수정·설정 변경·코드 배포 기록이 아니다.

## 조사 결론과 이전 요청 정정

**기존 연동 상품의 수정은 카페24 상품 → 마켓플러스 자동 전송 → G마켓·옥션을 기본 경로로 설계한다.** 별도 마켓플러스 수정·결과 조회 API 문서를 필수 자료로 요청했던 Q25는 정정한다. [공개 API 안내](https://developers.cafe24.com/docs/api/)와 현재 Admin API 문서에서 외부 개발자가 마켓플러스 전송과 결과를 직접 제어하는 별도 공개 API를 확인하지 못했다. 공개 문서에서 발견하지 못한 것과 모든 제휴·비공개 인터페이스가 존재하지 않는다는 주장은 구별한다.

| 구분 | 공식 근거로 확인한 내용 | 아직 확인하지 않은 내용 |
| --- | --- | --- |
| 상품 수정 자동 전송 | [공통설정](https://support.cafe24.com/hc/ko/articles/13688456354969-공통설정)의 마켓상품 자동전송을 사용하면 쇼핑몰 상품 수정이 연동 마켓 상품에 반영된다. | 현재 운영 계정의 설정, 실제 대상 계정·상품 연결, API별 자동 전송 발생 여부 |

[카페24 PRO 글로벌 서비스 설정 안내](https://docs.channel.io/cafe24global/ko/articles/글로벌-마켓-서비스-관련-설정-9ef188ab)는 재고관리 메뉴에서 바꾼 재고는 마켓으로 전송되지 않지만 상품 수정창의 옵션/재고 변경은 전송된다고 설명한다. 이 자료의 직접 적용 범위는 해당 서비스 안내다. **이를 근거로 특정 Admin API의 재고 PUT이 전송된다거나 전송되지 않는다고 단정하지 않는다.** 가격·재고·GTIN·이미지·HTML의 호출 경로별 확인이 필요하다.

## 수정한 화면·백엔드 설계

1. 카페24 본상품의 저장과 재조회 일치, 마켓플러스 전송, G마켓·옥션 각각의 반영을 별도 단계로 기록한다. 카페24 API의 HTTP 성공이나 `market_sync=T`만으로 두 마켓을 ‘반영 완료’로 표시하지 않는다.
2. 카페24 재조회만 끝났으면 ‘카페24 반영 확인 / G마켓·옥션 전송 확인 대기’로 표시한다. 전송 접수 근거가 있을 때에만 ‘전송 중’, 작업별 성공 근거가 있으면 ‘전송 성공’을 표시한다. 실제 마켓 값의 재조회까지 맞아야 해당 필드·변경 버전의 ‘반영 확인’으로 구분한다. 전송 이력 성공만으로 상품 전체의 현재 상태를 확정하지 않는다.
3. 작업에는 시스템 변경 버전, 필드별 목표값, 카페24 상품번호, 마켓·계정·상품번호, 전송 근거와 시각을 연결한다. 이전 변경의 성공이나 다른 계정의 결과를 현재 작업의 성공으로 사용하지 않는다. 일괄 작업은 마켓별 일부 성공·실패를 유지한다.
4. 하위 마켓의 실패만 발생한 경우 성공한 카페24 쓰기를 무조건 반복하지 않는다. 먼저 해당 마켓 전송 이력과 최신 값을 확인하고, 검증한 재전송 경로로 실패 대상만 처리한다. 현재 설정에서 마켓별 선택 전송이 가능한지 확인하기 전 단일 마켓 버튼이 카페24 공통 수정으로 모든 마켓에 전달되게 만들지 않는다.
5. 자동 전송의 대상이 G마켓·옥션 외에도 있는지 확인한다. 같은 마켓을 직접 API와 마켓플러스가 동시에 수정하면 이전 값으로 덮어쓸 수 있으므로 계정·필드별 수정 경로를 하나로 정한다. 이 경로 선택은 현재 설정 확인 후 구체화한다.
6. 영구 판매금지·삭제로 시스템 연결을 해제한 대상은 마켓플러스의 연결·자동 전송 대상에서도 제외되는지 확인해야 한다. SB DB의 연결 해제만으로 외부 연결까지 끊긴 것으로 기록하지 않는다. 정상 품절은 연결을 유지하고 시스템이 품절 처리한 근거가 있을 때 복구한다.
7. [마켓 상태·수량 불일치 안내](https://support.cafe24.com/hc/ko/articles/7556234549017-마켓플러스와-오픈마켓의-판매-수량-상품-개수-이-다릅니다)에 따르면 마켓이 자체적으로 상품을 중지하는 등의 변경을 마켓플러스가 알지 못할 수 있다. 전송 이력은 전송 결과의 근거이며 현재 삭제·영구 금지 여부는 계정과 마켓 상품번호를 기준으로 별도 확인한다. Q22의 부재 판정 원칙은 유지한다.

## 현재 구현과 구분

현재 로컬 카페24 가격·재고·GTIN 보완 경로는 여전히 `market_sync=F`에 한정되어 있다. 이 조건은 전달 범위와 결과 확인을 검증하기 전의 **임시 구현 제한**이며, 마켓플러스 연동 상품이 원천적으로 수정 불가능하다는 업무 규칙이 아니다. 이번 조사만으로 제한을 제거하거나 실제 운영 상품에 쓰기를 실행하지 않았다.

앞 단계의 운영 GET 12회에서 샘플 3개 모두 `market_sync=T`였던 사실은 유지한다. 이는 연동 여부만 보여 주며 자동 전송 설정·대상 계정·필드 상속·최종 마켓 반영까지 증명하지 않는다. 전체 구현 범위는 [진행 기록](2026-09-06-products-implementation-progress.md), 직전 보완은 [재고·GTIN 검증](2026-09-06-cafe24-inventory-and-gtin-verification.md)을 따른다.

## Q25의 새 확인 범위와 다음 검증

- 라이브 크롬의 ‘마켓플러스 → 기본 → 설정 → 공통설정’에서 자동전송과 품절 설정을 읽는다.
- 대상 계정의 판매/진열 동기화, 상품별 기본/별도 필드와 G마켓·옥션 매핑을 확인한다.
- ‘이력 → 이력조회 → 상품관리이력’에서 기존 작업의 성공·실패와 식별 가능한 근거를 확인한다. 공개 API가 있다고 가정하여 내부 화면 호출을 공식 API처럼 구현하지 않는다.
- 위 확인 후 정상 연결된 표본, 변경 전후 값, 대상 필드와 전송 경로, 실패 시 복구 방법을 구체화한다. 실제 API 수정 → 카페24 재조회 → 마켓플러스 이력 → 마켓별 최종값을 대조하는 파일럿으로 필드별 자동 전달을 검증한다. 이 파일럿은 아직 실행하지 않았다.

최초 읽기 도구의 탭 미발견 결과는 빈 선택자 처리 문제로 재검토했다. 후속으로 사용자 Chrome에서 **자동전송·품절 전송 사용, 두 계정의 진열/판매 연동, 표본별 상속과 실제 성공·실패 이력을 확인했다.** 상세 증거와 남은 범위는 [라이브 설정·전송 이력 확인](2026-09-06-marketplus-live-settings-and-results.md)을 따른다. 위 표의 미확인 항목은 최초 조사 시점 기준이며 후속 기록으로 보완한다. 별도 마켓플러스 API 문서 확보를 전제 조건으로 다시 요구하지 않는다.
