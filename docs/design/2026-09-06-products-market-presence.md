# Q21·Q22 확정 및 상품 부재 판정 — 2026-09-06

## 확정한 정책

- **Q21:** 마켓 연결이 없는 상품에서 브랜드·기본명·용량·단위·묶음수량을 변경하면 상품명을 함께 재조합한다. 변경 전후 이름을 검토 화면에 표시한 뒤 함께 저장한다. 사용자 수락에 따라 임시 기능 플래그와 확인 대기 잠금을 제거했다. 기존 연결이 있는 상품의 수정 제한은 유지한다. HTML 재생성은 콘텐츠 비교 기능에서 별도로 진행한다.
- **Q22:** 삭제 상품을 사용자에게 건별로 확인받지 않는다. 해당 판매 계정과 마켓의 올바른 상품번호로 조회하고 **상품 부재를 명확하게 확인한 응답**을 삭제 판단 근거로 사용한다. 삭제 사유를 제공하지 않으면 `사유 미제공 · 마켓 상품번호 조회로 부재 확인`으로 보존한다.
- 조회 권한 오류·인증 실패·호출 제한·서버 장애·잘못된 API 경로·응답 파싱 실패는 `미확인`이다. 공개 상품 페이지가 열리지 않거나 검색 목록에서 보이지 않는 것만으로 삭제를 확정하지 않는다.
- 품절은 연결을 유지한다. 영구 판매금지는 사용자 확인 또는 확정 가능한 마켓 근거를 별도로 보존하며 삭제와 구분한다. 금지 이력이 있는 상품을 단순 삭제 재등록 후보로 자동 바꾸지 않는다.
- 연결 해제는 활성 쓰기 대상에서 제외하는 처리다. 시스템상품 자체·과거 마켓 상품번호·금지/삭제 사유·주문 연결 이력을 물리 삭제하지 않는다.

## API 및 기존 코드 조사

### 스마트스토어

[공식 원상품 조회](https://apicenter.commerce.naver.com/docs/commerce-api/current/read-origin-product-product)는 `GET /v2/products/origin-products/:originProductNo`이며 404의 업무 코드는 `NOT_FOUND`다. 401/403/500은 별도 오류다.

[공식 FAQ](https://github.com/commerce-api-naver/commerce-api/discussions/980)는 잘못된 경로·HTTP 메서드에서도 HTTP 404와 `GW.NOT_FOUND`가 나올 수 있음을 설명한다. 따라서 HTTP 404 문자열 단독을 삭제로 처리할 수 없다.

[원상품 구조체](https://apicenter.commerce.naver.com/docs/commerce-api/current/schemas/%EC%9B%90%EC%83%81%ED%92%88-%EC%A0%95%EB%B3%B4-%EA%B5%AC%EC%A1%B0%EC%B2%B4)의 `statusType`에는 `SALE`, `OUTOFSTOCK`, `SUSPENSION`, `PROHIBITION`, `DELETE` 등이 있다. 이번 존재 판정은 `DELETE`와 부재 오류를 구별한다. `PROHIBITION`은 상품이 존재하는 금지 상태이지 삭제가 아니다. 존재 판정의 `PRESENT`는 판매 정상이나 동기화 완료를 의미하지 않는다. 후속 [연결 모델](2026-09-06-products-connection-lifecycle.md)에서 금지 상태를 별도로 기록하고 쓰기 차단·활성 연결 해제에 반영했다.

### G마켓·옥션

프로젝트와 다운로드 폴더에서 상품 부재·영구 금지 판정의 공식 ESM API 계약은 찾지 못했다. 다만 [기존 ESM 실측 기록](../normalize/esm-ghost-listings-20260812.md)에 로그인된 판매자센터의 `POST /api/ea/goods/search` 전수 조회와 판매상태 `11`/`21`/`22` 관찰 기록이 있다. 이는 당시 실측이며 현재 공식 API 계약이나 모든 `22` 상태가 영구 금지라는 증거는 아니다.

[마켓플러스 조사](../normalize/working_history/20260813_marketplus_스파이크.md)에는 마켓(계정)·마켓상품코드·판매상태 열이 기록되어 있다. 이 경로를 사용한다면 현재 로그인 계정·상품번호 검색 조건·응답 구조·전체 페이지 처리를 재검증해야 한다. 카페24 상품번호 조회 결과만으로 G마켓·옥션 존재 여부를 추정하지 않는다. 카페24 본상품은 존재하고 하위 마켓 상품만 금지 또는 삭제될 수 있다.

## 이번 코드 변경

1. Q21 임시 기능 플래그를 제거해 합의한 상품명 재조합을 기본 동작으로 활성화했다. 기존 H2 통합 테스트를 별도 플래그 없이 실행한다.
2. 공통 오류 분류에서 일반 `404 Not Found`, `data not found`, `does not exist`, 대상을 특정하지 않은 `삭제되었습니다`를 삭제 근거에서 제외했다. 기존에 확인한 쿠팡 `Product(숫자) data not found` 등 상품 단위 신호는 유지한다. 기존 문자열 호환 분류를 모든 마켓의 최종 연결 해제 근거로 바로 사용하지 않는다.
3. 스마트스토어 전용 존재 조회를 추가했다. 올바른 원상품 조회의 HTTP 404 및 정확한 `NOT_FOUND` 업무 코드, 또는 정상 상품 응답의 `DELETE`를 부재로 판정한다. `GW.NOT_FOUND`, 401/403/429/5xx, 빈/잘못된 JSON, 필수 상품 정보 누락, 다른 상품 ID, 알 수 없는 상태는 미확인이다.
4. 쿠팡 응답의 `data`가 누락되거나 비어 있을 때 삭제로 처리하던 경로를 미확인으로 수정했다. 기본 클라이언트도 상품 추출 결과가 null이면 존재로 판정하지 않는다.
5. `삭제대기`나 `상품삭제실패` 같은 상태명에 `삭제`가 포함되었다는 이유만으로 삭제를 확정하지 않는다.

## 후속 연결 모델 구현 결과

단건 상태 확인·판매자 영구 금지 확인, 마켓별 활성 연결 해제, 과거 식별자·판정 근거 보존, 해제 후 쓰기 차단, Q15 편집 잠금 해제를 로컬 구현했다. 조회 중 연결이 바뀌면 이전 판정을 적용하지 않는다. 카페24·G마켓·옥션 상태는 각각 보존한다. 구현·검증·계정 및 동시 쓰기 제약은 [연결 해제 구현 기록](2026-09-06-products-connection-lifecycle.md)을 따른다.

사용자가 제공한 금지 사례는 기존 API 원문과 대조할 검증 표본이다. 운영 데이터에 일괄 금지 플래그를 넣거나 연결을 해제하지 않았다. 선택 상품의 스마트스토어 일괄 조회·429 재시도는 [후속 작업 단계](2026-09-06-products-inspection-jobs.md)에 구현했다. 전체 상품 정기 접수, 하위 마켓 계정별 API 조회와 선택 재등록은 남아 있다. 계정 귀속이 미확인인 404는 연결을 유지하도록 보호했다. Q22가 사용자 건별 확인 대기로 막혀 있는 상태는 아니다.
