# 소싱처 전체 가격·재고 배치 실행

## 구현 범위

`/api/v1/supplier-batches`에서 소싱처의 활성 상품 전체를 실행 시점에 고정한다. 예를 들어 2,114개 대상은 한 번의 실행 요청으로 2,114개 상품 행과 각 수집·DB 단계를 보관한다. 이후 추가된 상품은 이미 시작한 실행에 섞이지 않는다. 상품 관리의 기존 검토 기능은 유지한다.

실행 정책은 마진율, 소싱 구매 쿠폰율, 최소마진이다. 구매 쿠폰율은 소싱 매입 원가 계산에 사용하는 기존 의미이며 마켓 소비자 할인 설정이 아니다. 가격 모드는 해당 정책과 관측 원가·환율을 같은 변경 이력으로 저장한다. 기존 쿠팡 수수료 기준 DB 판매가 및 마켓별 수수료·최소마진·100원 반올림 계산을 재사용한다. 재고 모드만 선택하면 가격 정책은 변경하지 않는다. 관측하지 못한 실재고 수량과 판매용 설정 수량은 유지한다.

가격·재고 동시 모드는 두 항목이 모두 정상 수집되어야 해당 상품을 저장한다. 가격만 또는 재고만 확인되면 수집 단계와 해당 상품 전체를 실패 처리하며 상품 값·가격 정책을 일부 적용하거나 마켓 작업을 접수하지 않는다. 실패 수집을 재시도하면 가격과 재고를 모두 새로 확인한다. 일부 값이 있는 미지원 표시도 이 상품 실패 규칙을 적용하며, 소싱처 전체가 미지원인 경우는 별도 보류한다. 이는 사용자가 승인한 확정 정책이다.

## 저장·복구

- `sb_supplier_batch_run`: 승인 정책, 전체 대상 수, 계정 참조, 실행·정지 상태, 짧은 작업 소유권.
- `sb_supplier_batch_item`: 고정 상품 대상, 현재 처리 결과, 소싱 수집·DB 검토·변경 이력 참조.
- `sb_supplier_batch_stage`: 수집, DB 저장, 마켓별 가격·수량 단계와 멱등 요청 ID. 마켓 가격과 수량은 별도 성공·실패를 보존한다.
- `sb_supplier_batch_attempt`: 단계 전환·시도 이력. API는 상품별 최근 100건을 반환한다.
- `sb_supplier_batch_retry`: 요청 ID와 재시도 범위를 영속 보관한다.

외부 호출과 하위 큐 서비스는 부모 실행 행 잠금 밖에서 처리한다. 수집은 기존 가격·재고 영속 큐에 한 상품씩 접수한다. 성공한 수집 → 고정 정책을 포함한 검토 기록 → 공통 DB 편집 저장의 순서이며, 검토 ID를 단계에 먼저 저장한 후 DB 저장을 실행한다. DB 저장과 변경 이력·미반영 대상은 공통 편집 서비스의 동일 트랜잭션으로 기록한다.

배치가 소유한 미반영 대상은 `batch_managed=true`와 `BATCH_MANAGED` 상태를 사용하여 기존 자동 접수기와 이중 접수되지 않도록 한다. 미선택 마켓의 미반영 이력도 보존하며 자동 전송하지 않는다. 마켓의 새 검토·접수 전에 배치 저장 이후 상품 리비전 및 승인 시점 계정 참조를 재확인한다.

일시정지는 이미 시작된 요청의 결과를 보존하면서 새 수집·마켓 요청을 막는다. 수집은 응답 유실로 단계의 collection ID가 아직 저장되지 않았어도 요청 ID로 배치 소유권을 확인한다. 일시정지된 첫 수집 행을 건너뛰므로 같은 소싱처의 일반 수집이 막히지 않는다. 진행 중인 하위 작업은 성공·실패로 단정하거나 참조를 제거하지 않는다.

재개 시 미커밋 검토만 만료되었다면 유효한 수집 증거·기존 실행 정책·현재 리비전 및 계정 검증으로 새 검토를 보관한다. 이미 커밋된 마켓 작업은 같은 참조로 결과를 조회한다. 수집 증거 자체가 24시간을 넘으면 DB 적용을 보류한다. 해당 저장 단계 재시도 시 아직 저장하지 않은 그 상품만 다시 수집한다. 이전 수집과 현재 상품의 리비전·URL·소싱처·연결이 같아야 하며, 이미 DB 저장 이력이 있으면 기존 이력으로 복구해 중복 수집·저장을 막는다.

실패한 수집/DB의 후속 미실행 단계는 건너뜀으로 마감하여 실행이 무한 진행 중으로 남지 않는다. 처리율 100%는 전체 단계의 처리가 끝났다는 뜻이며 성공률과 구분한다. 실패 단계 재시도는 성공 수집·저장·마켓 결과를 보존한다. 완료된 실행을 재시도하면 실행 상태로 돌아가고, 원래 일시정지된 실행은 재시도 접수 후에도 일시정지를 유지한다. 동일 소싱처의 다른 활성 실행이 있으면 과거 실행 재시도는 충돌로 거절한다.

## 현재 확인된 지원 범위

| 대상 | 가격 | 판매용 수량 | 제한 |
|---|---|---|---|
| 쿠팡 | 지원 | 지원 | 기존 정확 상품·계정·옵션 확인 및 조회 확인 계약 사용 |
| 스마트스토어 | 지원 | 지원 | 기존 상태 보류·정확 상품 확인 계약 사용 |
| 카페24 | 지원 | 지원 | 카페24 직접 상품 범위. G마켓·옥션 개별 직접 쓰기 아님 |
| 11번가 | 보류 | 제한 지원 | 가격은 검토형 계약 미확보. 수량은 판매중·단일 재고행의 양수 변경만 지원. 0개·품절 재개는 보류 |

소싱 수집은 기존 검증된 IHB, VTB, FTN, COK(코스트코 UK), OCD만 지원한다. 미확인 소싱처 응답이나 상품 부재를 품절·0개로 바꾸지 않는다. `sourceGone` 등 기존 수량 전송 보류는 그대로 적용한다.

## 검증과 배포 상태

`ProductSupplierBatchIntegrationTest`의 22건이 H2에서 통과했다. 실제 2,114개 제품으로 대상 고정·전체 건수·마지막 페이지를 검증했고, 가격/재고 각각 저장, 둘 다 정상 관측 시 단일 DB 변경, 실패 수집 재시도, DB 실패 후 같은 검토 재사용, 소싱처 변경 차단, 일시정지·응답 유실·일반 수집 진행, 만료된 검토 재생성 및 수집 증거 만료 차단을 확인했다. 실제 가격·수량 큐를 사용하는 마켓 통합 7건과 함께 총 29건이 통과했으며 기존 소싱 통합 26건도 통과했다. 같은 소싱/DB 22건은 격리 PostgreSQL 16에서도 통과했다. PostgreSQL 선택 검증은 `SBSHOP_BATCH_TEST_POSTGRES_URL=jdbc:postgresql://127.0.0.1:<port>/sbshop_batch_flow_check`로만 실행할 수 있다.

추가 정책 회귀는 가격만·재고만 관측된 두 경우를 각각 일반 일부 수집 상태 및 일부 값이 있는 미지원 상태로 검사한다. 상품 전체 실패, 저장·마켓 작업 미실행, 리비전·정책 불변, 재시도 시 두 항목 새 수집과 단일 저장을 확인한다. 최종 검증 및 배포 전까지 이번 실행 기능의 운영 완료로 표시하지 않는다. 이 작업 중 운영 배치를 실행하거나 상품·마켓 값을 변경하지 않았다.
