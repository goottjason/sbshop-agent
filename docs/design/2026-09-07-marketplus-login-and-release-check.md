## 통합 검사에서 발견한 사항

새 편집 서비스가 상품 저장소를 주입할 때 기존 `ProductRepository`와 이를 상속하는 `ProductJpaRepository`가 동시에 등록되어 앱 기동에 실패했다. 참조되지 않는 기존 별칭을 `@NoRepositoryBean`으로 표시해 실제 저장소 빈을 하나로 정리했다. PostgreSQL 기반 전체 앱 기동 검사에서 확인한 문제이며 단위 검사만으로는 발견되지 않았다.

기존 마켓 응답 DTO의 JSON 계약 검사는 엔티티에 추가된 연결 관리 내부 필드까지 DTO에 나오도록 잘못 기대했다. DTO 계약을 바꾸지 않고 기존 JSON 구조를 명시적으로 고정했다. HTML 직접 INSERT 시험 데이터에는 새 필수 버전·판매용 수량을 넣고, 실제 PostgreSQL 컨테이너가 종료되기 전에 Spring 컨텍스트가 닫히도록 시험 수명을 정리했다.

Python 46건과 수집 상태 API 7건을 통과했다. 프론트 빌드와 TypeScript도 통과했다. 전체 백엔드 재검사 결과는 후속 집계에 기록한다.

## 남은 전환

운영 카페24의 `is_active=false`는 유지했다. 원래 모델의 의미는 ‘해당 마켓 연동 계정의 활성화(사용) 여부’이며, 현재 코드에서 이를 검사하는 경로는 새 마켓플러스 이력 기능뿐이다. 과거 false 설정 사유는 알 수 없다. 계정 대조 완료와 토큰 권한 정상 확인을 근거로 배포 시 적용할 계정 설정을 명시해야 한다.

본 앱 통합 배포 및 이력 업로드 후 DB 저장 응답·상품 목록을 대조해야 한다. 이력 관측 성공이 전체 필드 동기화 확인을 뜻하지 않으며 `market_sync=T` 필드 쓰기 제한은 유지한다. 전체 이력 수집·보관 최적화, 필드별 전달 검증 및 자동 재전송은 후속 범위다.
