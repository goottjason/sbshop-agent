# 마켓플러스 전송 이력 수집·저장·표시

2026-09-06. 기존 [라이브 설정과 전송 결과 조사](2026-09-06-marketplus-live-settings-and-results.md)의 후속 구현이다. **코드·로컬 검증 완료, 운영 미배포.** 운영 DB에 이력을 넣거나 마켓 상품을 재전송하지 않았다.

아래는 단일 페이지 단계의 구현 기록이다. 이후 [여러 페이지 수집·재개와 목록 표시](2026-09-06-marketplus-pagination-and-grid.md)를 구현했고, 가격 설정 403의 `insufficient_scope` 원문도 확인했다. 현재 수집 도구·목록 동작과 최신 검증 범위는 후속 기록을 따른다.

## 구현한 동작

- 라이브 Chrome의 상품관리이력에서 현재 전송완료/전송실패 페이지를 읽어 저장용 파일을 만든다. 1초 간격으로 두 번 읽어 화면이 안정적인지 확인한다. 탭·URL 상태·결과 원문·상품번호가 맞지 않거나 로딩·빈 화면·100행 초과이면 파일을 생성하지 않는다. 로그인·설정 저장·상품 전송·페이지 넘김은 수행하지 않는다.
- `POST /api/v1/marketplus/transmissions/import`: 인증된 관리자의 수집 파일을 가져온다. 쇼핑몰 ID는 시스템 카페24 계정과, 판매 계정은 서버 설정과 대조한다. 카페24 상품번호와 상품코드, 지마켓/옥션 상품번호까지 모두 같은 연결이 정확히 하나일 때 저장한다. 후보 검색의 부분 일치를 확정 근거로 사용하지 않는다.
- 행별 별도 트랜잭션과 연결 잠금, SHA-256 고유 키로 재시도·동시 업로드 중복을 방지한다. 일부 행을 제외하거나 저장 결과를 확인하지 못하면 해당 행 번호·상품번호·사유를 반환한다. HTTP 응답을 잃어도 같은 파일로 다시 시도할 수 있다.
- `GET /api/v1/products/{productId}/marketplus-transmissions`: 상품별 최근 관측 최대 100건을 **실제 전송 완료 시각** 순으로 조회한다. 뒤늦게 가져온 오래된 이력이 최신 결과를 덮지 않는다. 계정·식별자가 달라졌거나 연결이 해제된 이력은 과거 연결로 표시한다.
- 상품 상세의 ‘지마켓·옥션 전송 이력’에서 결과 원문, 판매 계정, 상품번호, 요청·완료·수집 시각을 표시한다. 수집 파일은 여러 상품을 포함할 수 있으므로 저장 전에 범위를 안내한다. 저장/중복/제외·미확인 건수를 각각 표시한다.
- 품절 표본의 `진열/판매 상태일 때만 판매중지 해제 가능` 오류는 `SOURCE_STATE_REVIEW_REQUIRED`로 표시한다. 일시 품절을 영구 금지로 판정하거나 판매 재개하지 않는다. 원인 확인·재전송은 마켓플러스 화면 링크를 제공한다.

## 증거의 한계와 상태 처리

이 파일은 관리자 브라우저에서 읽은 전송 이력이며, 마켓 현재 상품 조회나 모든 필드의 일치 검증을 대체하지 않는다. 성공 관측은 `TRANSFERRED_UNVERIFIED`이다. 기존 등록 정보의 `isSynced`, 연결 상태, 재시도 큐, DB 상품값은 이력 저장으로 변경하지 않는다. 그리드 G마켓·옥션은 계속 ‘반영 미확인’을 유지하고 새 패널에서 전송 결과를 확인한다.

수집 범위는 `CURRENT_PAGE`로 한정한다. 전체 기간·상품 수를 수집 완료로 표시하지 않으며 누락 행을 삭제 상품으로 판단하지 않는다. 화면의 No는 탭 안의 순번이므로 작업 ID로 사용하지 않는다. 원격 작업의 고유 ID가 없어 **같은 분·동일 계정/상품·동일 전송 내용은 한 관측으로 합쳐질 수 있다.** 실제 전송 작업 수 통계로 사용하면 안 된다.

서버가 로그인 계정의 실제 Chrome 세션을 직접 증명하는 방식은 아니다. 인증된 관리자가 제출한 제한된 형식의 관측을 계정·상품 식별자로 교차 확인하는 단계다. 따라서 자동 연결 해제·전체 필드 성공 판정의 근거로 사용하지 않는다.

## 사용 및 배포 준비

1. 앞선 연결 관리 DDL 적용 후 [전송 이력 DDL](../../backend/docs/ddl/2026-09-06-marketplus-transmissions.sql)을 적용한다. 이번 턴에서는 적용하지 않았다.
2. 운영의 실제 카페24 계정과 일치하는 MarketPlus 판매 계정을 환경변수로 지정한다. 미설정이면 가져오기를 거부한다. 이번 라이브 확인값은 `MARKETPLUS_GMARKET_ACCOUNT=younzara`, `MARKETPLUS_AUCTION_ACCOUNT=shouldbe2480`이다. 일반 코드 기본값에 계정을 고정하지 않았다.
3. 백엔드·프론트를 함께 배포한다. 현재의 큰 미배포 변경과 선행 DDL을 포함한 별도 배포 검증이 필요하다.
4. 사용자가 연 라이브 Chrome의 상품관리이력에서 전송완료 또는 전송실패 페이지를 연 뒤 다음 명령을 실행한다. Chrome의 Apple 이벤트 JavaScript 허용이 필요하며 중복된 이력 탭이 있으면 하나를 남긴다.

```sh
python3 tools/browser/collect-marketplus-transmissions.py \
  --mall-id 'younzara' --output /tmp/marketplus-history.json
```

다른 쇼핑몰에 로그인한 경우 해당 쇼핑몰 ID를 사용한다. 파일은 덮어쓰지 않으므로 반복 수집 시 새 파일명을 쓴다. 상품 상세의 ‘수집 파일 가져오기’로 저장한다. 파일에 담긴 상품 전체가 대상이며 현재 상세 상품 하나로 한정하지 않는다.

실제 수집 결과는 [전송완료 첫 페이지 20행](evidence/2026-09-06-marketplus-success-import.json), [전송실패 첫 페이지 20행](evidence/2026-09-06-marketplus-failure-import.json)에 있다. 수집 시각은 파일 안의 `capturedAt`을 따른다. 저장용 파일을 만들었으며 운영에 업로드하지 않았다.

## 카페24 가격 설정 조회 권한

[상품 설정 조회 공식 문서](https://apidocs.cafe24.com/docs/admin/get-products-setting)는 `GET /api/v2/admin/products/setting`에 쇼핑몰 읽기 권한(READ_STORE)을 요구한다. 기존 인증 URL의 요청 범위에는 `mall.read_store`가 없어 이를 추가했다. `mall.write_store`는 요청하지 않는다. 기존 상품·주문·배송·분류 권한은 유지한다.

코드 수정만으로 기존 토큰 권한이 변경되지는 않는다. 개발자 앱의 해당 권한 허용 여부 확인 → 새 인증 범위로 재인증 → 가격 설정 GET 및 과세/가격 기준 확인이 남아 있다. 앞서 확인된 실제 403의 응답 원문을 확보하지 못했으므로 권한을 추가하면 반드시 해결된다고 단정하지 않는다. 현재 가격 전송의 검증 조건을 임의로 해제하지 않았다.

## 검증과 남은 작업

- 백엔드 24건: 저장·중복·동시 업로드·부분 제외·모호한 식별자·계정 변경·과거 연결·오래된 결과의 순서·품절 실패 비파괴성·거짓 성공 입력·인증 주체 고정·권한 범위.
- Python 수집기 5건: 한국 시간 변환, 로딩/탭/원점/빈 화면/잘림 차단, 모호한 마켓·상품번호, 오류 행을 조용히 버리지 않음, 잘못된 시각.
- 라이브 Chrome: 전송완료·전송실패 각 20행 수집. React 화면은 가상 응답으로 조회 실패→재조회, 성공/실패/과거 연결 표시, 파일 업로드 범위 확인, 부분 제외 사유 표시를 검증했다. [화면](2026-09-06-marketplus-transmission-preview.png).
- TypeScript·변경 파일 ESLint·Vite 빌드·변경 Java 파일 Spotless 통과. 기존 번들 크기 경고는 남아 있다. H2 기반 저장 검증이며 운영 PostgreSQL DDL 실행 검증은 미수행이다.

남은 범위: 여러 페이지·기간을 빠짐없이 수집하는 작업 상태/복구와 정기 실행, 그리드·검색에 최신 전송 실패 연결, 전송 작업 종류와 Cafe24 변경 버전의 상관관계 확정, 필드별 실제 반영 재조회, 429를 고려한 자동 재전송, 재인증 및 운영 배포. 사용자는 16:02 무렵 수동 작업 여부를 기억하지 못한다고 답했다. 이를 수동 실행 없음으로 가정하지 않고, 이미 확인한 서버 배치 기록과 마켓플러스 오류의 원인을 계속 구분해 조사한다.
