# 11번가 검토형 가격 반영 계약

## 근거와 범위

인증된 공식 API Center에서 확보한 apiSeq 1752는 상품 가격 변경을 **GET** `/rest/prodservices/product/price/[prdNo]/[selPrc]`로 정의한다. 요청 본문이나 할인율 필드는 없다. apiSeq 1620의 GET `/rest/prodmarketservice/prodmarket/[prdNo]`에서 `Product`의 `prdNo`, `sellerPrdCd`, `selStatCd`, `selPrc`를 별도로 확인한다.

`selPrc`는 현재 기본 판매가이며 `preSelPrc`나 즉시할인가로 대체하지 않는다. 정확한 상품번호·SB코드·계정을 확인하고 양의 정수 가격만 처리한다. 자동 반올림은 하지 않는다. 판매중(103), 품절(104), 전시중지(105)는 가격 변경 대상으로 사용하며 승인·판매금지·종료 및 미확인 상태는 보류한다. 가격 경로에서 수량·판매 상태·즉시할인 API를 호출하지 않는다.

공식 문서에는 기존 협의 쿠폰 또는 서비스 이용료 조정 혜택이 가격 인상에 따라 종료될 수 있다고 명시되어 있다. 사용자는 이 영향을 인정하고 설정한 판매가로 인상·인하 모두 자동 반영하도록 승인했다. 새 엔진은 `allowPriceIncrease=true`를 전달한다. 소싱 구매 쿠폰율을 11번가 `priceCoupon` 요청으로 변환하지 않는다.

## 쓰기와 검증

`ElevenstReviewedPrice`는 쓰기 직전에 상세를 다시 조회해 정확한 상품·계정·현재 가격과 상태를 확인한다. `ElevenstMarketRestClient.mutatePriceOnce`는 고정 계정과 실제 송신 직전의 `beforeWrite` 가드를 요구한다. 콜백 예외는 원래 객체 그대로 전달해 작업 소유권·일시정지 판단을 보존한다.

가격 변경 GET은 일반 읽기용 `requestStrict`를 사용하지 않는다. 설치된 OkHttp 4.12.0 소스에서 `retryOnConnectionFailure=false`만으로는 `503 Retry-After:0`의 자동 후속 요청이 막히지 않음을 확인했다. 전용 전송은 연결 재시도·리다이렉트를 끄고, 네트워크 인터셉터에서 비정상 HTTP를 즉시 예외로 반환하며 요청별 1회 송신 제한도 검사한다. 같은 전송기를 수량·판매 상태 PUT 전용 mutateStockOnce에서도 사용한다. 일반 strict 조회도 리다이렉트를 금지하고 캐시를 사용하지 않는다. 운영에서 HTTPS 접속이 확인되어 설정 기본값과 API 설정을 HTTPS로 전환한다.

HTTP 200도 업무 성공을 뜻하지 않는다. `ClientMessage.resultCode=200`, 정확한 `productNo`, 유효한 이전 가격 `preSelPrc`를 확인하되 이는 접수 응답이다. 최종 성공은 후속 상세 GET에서 현재 `selPrc`가 검토 목표와 일치할 때만 가격 큐가 기록한다. 명시 업무 오류는 `ELEVENST_BUSINESS_*`, 429는 서버 `Retry-After`를 보존한 `HTTP_429`, 응답 유실은 `TRANSPORT_ERROR`로 전달한다. 전송 결과를 모르면 같은 요청을 즉시 재전송하지 않고 실제 가격을 먼저 재조회한다.

## 검증

어댑터 회귀는 정확 식별·현재 판매가·상태 제한·숫자 정밀도·쿠폰 미전송·인상/인하·계정 변경·콜백 예외 보존·업무 오류·불명 응답·429를 검사한다. 전용 전송 회귀는 로컬 HTTP 서버에서 정상 GET, 301/302/307/308, 408, 429, `503 Retry-After:0`, 응답 유실의 실제 송신 횟수를 검사하고 가드 실패·계정 변경 시 송신하지 않는지 확인한다. 위 회귀 테스트는 로컬 서버와 fixture만 사용하며 운영 상품에 요청하지 않는다.
