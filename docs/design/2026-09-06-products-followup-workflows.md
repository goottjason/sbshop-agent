# 상품 관리 후속 구현 — 마켓 조회·판매가 반영·선택 재등록

2026-09-06 로컬 구현. 이 문서는 이번 후속 범위를 기록하며, 전체 개편 완료 또는 운영 적용 기록이 아니다. 운영에는 아직 이전 배포 `02142157`만 반영되어 있다. 외부 상품 생성·수정, 운영 DDL·데이터 변경은 이번 작업에서 실행하지 않았다.

현재 로컬 카페24 가격 반영은 본상품이 판매 중이고 `market_sync=F`인 경우만 진행한다. 이는 전달 범위 검증 전의 임시 제한이다. 이후 [공식 자동 전송 안내를 재확인](2026-09-06-marketplus-auto-forwarding-recheck.md)하여 카페24 수정 → 마켓플러스 → G마켓·옥션을 기본 경로로 정정했다. 현재 설정·필드 상속·API별 자동 전달·결과 확인을 검증한 뒤 연동 상품 지원을 확장한다. `market_sync` 값을 임의로 바꾸지 않는다. 해제된 하위 연결이 있으면 외부 전송 대상 제외가 확인될 때까지 보류한다. 쿠팡은 판매자·상품·단일 옵션 연결과 승인/판매 상태를 확인한다. 여러 옵션의 SB코드 대응이 불명확하면 전송하지 않는다. 쿠팡 강제 가격 제한 해제 옵션은 사용하지 않는다.

카페24 라이브 문서 대조 후 새 가격 작업에 세금 계산·상품 설정 검사를 추가했다. 자동 세금은 `price`, 수동 세금은 확인된 계산 기준을 검사하며 `price_excluding_tax`가 필요한 B 기준은 보류한다. 권한 오류와 429 대기를 유지하고 세금 설정 자체는 바꾸지 않는다. 관련 38건 통과, 운영 미배포다. [필드별 문서 근거와 남은 검증](2026-09-06-cafe24-live-api-contracts.md)에 품목 GTIN·재고·이미지, 앱 버전 확인과 마켓플러스 계약 누락을 정리했다.

판매용 수량의 기본 300은 기존 `stock=999` 등의 값을 변환한 것이 아니다. 새 열을 별도로 만든다. 기존 정상 재고 복구 서비스에서도 `salesQuantity`를 읽고 스마트스토어 등록 요청에도 적용한다. 품절 처리를 포함한 기존 가격·재고 동기화 전체를 검증된 새 큐로 전환한 것은 아니다.

## 가격 작업의 결과 의미

- 검토는 인증 사용자에게 귀속되며 30분 후 만료한다. 같은 검토 접수의 재시도는 같은 작업을 반환한다.
- 상품 버전, 마켓 상품번호 전체, 연결 상태, 계정, 현재 가격 정책을 접수·전송 전·결과 저장 시 확인한다. 변경된 작업은 최신 결과로 확정하지 않는다.
- 먼저 실제 가격을 읽는다. 이미 일치하면 전송하지 않는다. 쓰기 시작 기록을 DB에 커밋한 뒤 요청을 보낸다.
- 요청 반환은 `VERIFY`다. 응답 유실 또는 서버 재시작 후에도 재조회부터 수행한다. HTTP 200이나 로컬 캐시 변경만으로 완료 처리하지 않는다.
- `CONFIRMED_PRICE`는 해당 버전의 판매가 일치 증거다. 상품 전체 `isSynced=true`로 바꾸지 않는다. 조회값·시각·전송/조회 시도와 오류를 저장한다.
- 가격 쓰기는 최대 3회, 조회는 최대 9회다. 불일치·미확인·판매 중지·계정 변경은 구분해 표시한다. 사용자가 최신 가격으로 다시 검토할 수 있다.
- 이 작업들과 상태 확인 작업은 마켓별 DB gate를 공유한다. 가격 읽기 뒤 쓰기 직전에 임대를 갱신한다. 만료된 임대의 결과는 확정하지 않는다. 429의 `Retry-After`보다 이르게 재시도하지 않는다.
- 기존 동기화 경로 전체와의 API 요청 속도 통합, 전송 도중 발생한 외부 변경을 원자적으로 취소하는 기능은 아니다. 이미 전송 중인 요청의 외부 효과를 DB 잠금으로 되돌릴 수 없다. 변경된 버전/연결에 성공을 기록하지 않는 보호와 후속 재조회로 처리한다.

`ProductChangeTarget`은 `PENDING_DISPATCH`→`DISPATCHED`→`CONFIRMED_PRICE`로 이동한다. 검증되지 않은 필드는 `ACTION_REQUIRED`이며 미반영 수에 포함한다. 과거 가격 변경이 최신 가격 반영으로 대체되면 `SUPERSEDED_BY_CURRENT`로 남겨 과거 요청값이 적용되었다고 표시하지 않는다.

## 삭제 상품의 선택 등록

후보는 각 마켓의 실제 연결 상태를 기준으로 만든다. 과거 삭제가 확정된 연결은 후보에 포함하고, 영구 금지는 제외한다. 기존 상품번호가 있거나 상품번호 없는 과거 요청의 생성 여부가 불명확하면 중복 생성하지 않는다. G마켓·옥션은 카페24 하위 연결도 확인한다.

스마트스토어는 등록 전에 카테고리·이미지 업로드·출고지 등 요청 준비를 끝내고 정확한 요청 JSON을 저장한다. 실제 전송할 이름, 카테고리 경로/코드, 가격, 판매용 수량, 대표 이미지를 검토 화면에서 확인한다. 기존 카테고리 검색/기본값이 선택되었다면 그 경로도 표시하며, 접수 후 자동으로 다시 선택하지 않는다. 등록 후보와 검토 결과는 각각 체크박스로 선택한다. 한 번에 준비하는 등록 후보는 최대 100개다.

접수 시 등록 의도를 저장하여 다른 등록과 편집을 차단한다. 원상품 생성 POST는 자동 반복하지 않는다. 전송 중 서버가 중단되거나 응답이 끊기면 `UNKNOWN_CREATE`로 남으며 연결 잠금도 유지한다. 생성된 원상품 번호를 입력하면 동일 계정에서 SB코드와 검토한 이름·카테고리·가격·수량·이미지·HTML을 재조회한다. 과거 삭제 상품번호는 새 생성 결과로 지정할 수 없다. 일치한 경우 새 연결을 만들고 이전 상품번호·상태·삭제 근거를 보존한다. 그 밖의 고시·배송·외부 마켓 연결까지 전부 동기화되었다고 표시하지 않는다.

전송 시작 전 상품/가격 정책이 바뀐 경우에는 미전송 작업을 취소하고 등록 잠금을 해제한다. 전송 여부가 불명확한 작업은 임의로 잠금을 풀지 않는다. 실패 응답의 종류별 ‘확실히 미생성’ 판정 및 판매자코드 자동 대조는 후속 범위다.

## 확인한 API 근거

- [스마트스토어 멀티 상품 수정](https://apicenter.commerce.naver.com/docs/commerce-api/current/update-multi-products-product): 공식 v2.87 스키마에서 `PATCH /v1/products/origin-products/multi-update`, `multiProductUpdateRequestVos`, `multiUpdateTypes=[SALE_PRICE]`, `productSalePrice.salePrice`를 확인했다. 상품명·재고·판매 상태·할인 요청을 섞지 않는다.
- [쿠팡 상품 아이템별 수량/가격/상태 조회](https://developers.coupang.com/ko/api/products/query-quantitypricestatus-by-product-items), [가격 변경](https://developers.coupang.com/ko/api/products/changing-price-of-each-item-of-a-product): 부모 상품과 단일 `vendorItemId`를 대조한 뒤 `inventories` 응답의 `sellerItemId`, `salePrice`, `onSale`을 확인한다.
- [쿠팡 상품 조회](https://developers.coupang.com/ko/api/products/querying-product): 정확한 `sellerProductId`·`vendorId`와 명시된 `상품삭제`만 삭제 근거로 사용한다. 일반 오류 문구는 부재 증거가 아니다.
- [카페24 Admin API](https://developers.cafe24.com/docs/ko/api/admin/): 본상품 조회/수정의 `shop_no=1`, `product_no`, `price`, `selling`, `market_sync`를 확인했다. 본상품 판매 중지는 하위 마켓의 영구 판매금지를 의미하지 않는다.
- 프로젝트의 11번가 `신규상품조회.pdf`: `GET /rest/prodmarketservice/prodmarket/{prdNo}`의 `selStatCd=104`는 품절, `105/106`은 판매 중지/종료, `108`은 판매금지다. 보안 XML 파서로 정확한 `prdNo`와 단일 필드를 확인한다. 일반 404, 빈 응답, 오류 XML은 삭제로 판정하지 않는다.
- 11번가 `상품재고무게변경처리_PUT방식.pdf`는 옵션 무게 수정 API다. 재고수량 수정 근거로 사용하지 않았다. `makerNm` 생성 요청을 제거하고, 제조사 필드 수정 요청은 계약 확인 전 부분 전송 없이 거절한다.

카페24 `supply_quantity`와 로컬 `variants.quantity` 변경을 재고 확인 증거로 사용하지 않는다. 이후 [재고·GTIN 검증 보완](2026-09-06-cafe24-inventory-and-gtin-verification.md)에서 기존 가격·재고 메서드의 `supply_quantity`를 품목 재고 API로 대체하고, GTIN과 재고는 별도 GET 일치 후 결과를 기록하도록 수정했다. 카페24 재고·바코드 일부 성공이 전체 `markSynced()`를 호출하던 경로도 제거했다. 본상품 `market_sync=F`에 한정한 로컬 보완이며, 영속 재고 큐와 나머지 필드 전환은 남아 있다. 마켓플러스 연동 T인 실제 샘플 3개는 계약 확인 전 새 전송 경로에서 보류한다.

## 운영 전환 순서

운영 DB에 아직 실행하지 않은 다음 DDL을 백업 후 순서대로 적용하고, API/worker/frontend를 같은 버전으로 전환해야 한다.

1. `backend/docs/ddl/2026-09-06-product-edit-review.sql`
2. `backend/docs/ddl/2026-09-06-market-connection-lifecycle.sql`
3. `backend/docs/ddl/2026-09-06-market-inspection-jobs.sql`
4. `backend/docs/ddl/2026-09-06-market-inspection-daily.sql`
5. `backend/docs/ddl/2026-09-06-market-inspection-multiple-markets.sql`
6. `backend/docs/ddl/2026-09-06-market-price-sync.sql`
7. `backend/docs/ddl/2026-09-06-market-reviewed-publication.sql`

자동 가격 접수는 기본 10초 간격이며 새 편집 이력의 가격 변경을 대상으로 한다. 전송/재조회 작업은 기본 1초 간격으로 due 항목을 확인하되 DB gate의 간격과 429 대기를 따른다. 구버전은 새 등록 의도·연결 해제를 모르므로 혼합 실행하지 않는다. 롤백하더라도 미확인 생성 작업과 `publication_operation_id`, 기존 식별자 보존 기록을 삭제하지 않는다. 운영 PostgreSQL DDL 실행·성능 검사와 실제 마켓 쓰기 파일럿은 아직 수행하지 않았다.

## 확인을 기다리는 정보와 다음 범위

- Q25 정정: 별도 마켓플러스 공개 API 문서를 필수로 요구하지 않는다. 이후 [현재 설정·두 계정·표본별 상속·성공 및 실패 이력](2026-09-06-marketplus-live-settings-and-results.md)을 라이브 Chrome에서 확인했다. 새 API 경로별 자동 전달, 전송 결과 자동 수집·재시도, 품절 실패의 원인 구분이 남아 있다. 수정 자동 전송과 미등록/삭제 상품의 선택 등록은 구별한다.
- Q26: 쿠팡·11번가·카페24의 과거 상품번호가 각각 현재 연결한 한 계정 소유인지. Q24의 스마트스토어 계정 확인은 유지한다.
- Q27: 11번가 가격 수정 및 재고수량 수정의 정확한 API 문서.
- 다른 마켓의 등록 요청 고정·검증, 연결 상품의 수량·바코드·이미지·HTML 등 필드 동기화, 소싱 최신 콘텐츠 비교 적용, 전체 동기화 필터·정렬·배지는 별도 남은 구현이다.

백엔드 관련 검사 531건, TypeScript·빌드·Spotless와 크롬 가상 응답 검증을 통과했다.
