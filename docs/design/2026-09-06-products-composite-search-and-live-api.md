# 복합 마켓 검색과 라이브 크롬 API 확인

2026-09-06 로컬 구현·검증 기록. 운영 배포, 운영 DB 변경, 실제 마켓 상품 쓰기는 실행하지 않았다.

## 검색 구현

- `POST /api/v1/products/search`에 `registeredMarkets`, `missingMarkets`, `pendingChangesOnly`를 추가했다. 각 마켓 목록 내부와 두 목록 사이 모두 AND이며 소싱처·브랜드·재고·SB코드 조건도 함께 적용한다. 같은 마켓을 양쪽에 지정하면 400으로 거절한다.
- 프론트에서 등록 마켓과 미등록·연결 해제 마켓을 각각 다중 선택한다. 한쪽에 선택한 마켓은 반대쪽에서 제거한다. 빠른 조건 `IHB · 재고 있음 · 쿠팡 등록 · 11번가 미등록`, 조건별 제거, 전체 초기화를 제공한다. 빠른 조건은 브랜드·검색어 등 다른 조건을 유지한다.
- 등록 판정은 DB의 `LINKED` 상태와 현재 최상위 상품번호를 기준으로 한다. 외부 실시간 판매 상태나 정보 일치의 증거는 아니다. 일시 품절과 연결 해제가 확정되지 않은 과거 삭제 표시는 연결을 유지한다. 확정 삭제·영구 금지의 해제는 등록 조건에서 제외한다.
- `previousIdentifiers` 안의 과거 상품번호, 빈값·공백·null·객체·배열·잘못된 JSON을 현재 연결로 세지 않는다. 기존 코드에서 지원하던 상품번호 별칭을 공유한다. 카페24 본상품, G마켓, 옥션의 해제 상태는 독립적으로 적용하며 직접 G마켓·옥션 등록행도 포함한다.
- 미등록 검색 결과에는 영구 금지나 생성 여부 미확인 상품도 있을 수 있다. 검색은 등록 허가가 아니며 기존 등록 검토의 영구 금지 제외·중복 생성 방지를 유지한다.
- 기존 `markets` ANY 및 단일 `marketFilter`도 현재 연결 판정으로 통일했다. 단순 등록행 존재만으로 검색하던 과거 동작은 변경된다.
- 미반영 DB 변경은 기존 목록의 미반영 수와 같은 `PENDING_DISPATCH`, `DISPATCHED`, `ACTION_REQUIRED` 기준이다. 모든 마켓의 실제 필드 차이를 전수 조사한 결과는 아니다.
- DB에서 조건을 적용한 뒤 페이지 처리하며 상관 EXISTS로 중복 상품·페이지 수 증가를 방지한다.

별도 남은 범위: 마켓별 최신 실패·실제 필드 차이 필터, 이미지/HTML 성공 갱신일 및 90일 경과 필터, 조치 필요→성공 갱신 오래된 순 정렬. 실패한 크롤 시도도 포함하는 `lastCrawlAt`을 성공 갱신일로 대신 쓰지 않는다.

## 배포 의존성

앞선 7개 후속 DDL 이후 [8번째 검색 함수 DDL](../../backend/docs/ddl/2026-09-06-market-search-identifiers.sql)을 적용해야 한다. PostgreSQL 함수 `sb_market_has_identifier(text,text)`는 현재 최상위 문자열/숫자 상품번호만 확인하고 잘못된 JSON은 false로 처리한다. 기존 상품번호 데이터는 변경하지 않는다. API·worker·프론트 버전은 앞선 후속 전환 조건대로 함께 맞춘다.

## 라이브 크롬에서 확인한 문서

사용자 요청에 따라 실행 중인 Google Chrome의 문서 탭을 AppleScript로 조회했다. 일반 탭 본문이나 쿠키·저장 암호는 읽지 않았다. API 문서 주소에 한정한 읽기 도구는 [스크립트](../../tools/browser/read-market-api.applescript)에 보존했다. 크롬 메뉴 `보기 → 개발자 → Apple Events의 자바스크립트 허용`이 필요하다. 최초 차단 후 아래 가격 문서는 본문 읽기에 성공했으나 후속 문서 탭에서는 같은 차단이 다시 반환됐다. 모든 문서에 대한 안정적인 접근이 확인된 것은 아니다. 허용 설정을 자동 변경하지 않았다.

확인한 공식 페이지: [11번가 상품가격수정, apiSeq=1752](https://openapi.11st.co.kr/openapi/OpenApiGuide.tmall?categoryNo=81&apiSeq=1752&apiSpecType=1).

- 가격만 바꾸는 계약은 `GET /rest/prodservices/product/price/{prdNo}/{selPrc}`다. 문서에는 `http://api.11st.co.kr`가 기재되어 있다. **조회용 GET으로 간주해서 실행하면 안 된다.** 이번에는 문서 본문만 읽었다.
- 응답은 XML `ClientMessage`, `productNo`, `message`, `resultCode`다. 업무 성공은 `200`, 업무 오류는 `500`, 점검은 `-1000`으로 기재된다. HTTP 200만으로 성공 처리하면 안 된다.
- `preSelPrc`는 변경 전 가격이다. 변경 후 실제 값 확인 근거로 사용하면 안 되며 상품 조회 계약과 별도 대조해야 한다.
- 11번가와 협의한 쿠폰·서비스이용료 조정이 적용된 경우 기본즉시할인 적용 후 가격의 인상으로 조정 혜택이 종료될 수 있다고 명시한다. 적용 여부를 확인할 수 없는 상품의 자동 가격 인상 정책은 Q28로 질문했다. 답변 전 새 자동 인상 경로를 활성화하지 않는다.

Q27의 가격 수정 문서 위치는 확보했다. 재고수량 변경 및 조회 필드의 라이브 대조는 아직 완료하지 않았다. Q25의 ESM/마켓플러스 계약, Q26의 쿠팡·11번가·카페24 과거 번호 계정 귀속도 미확정이다. 이번에 11번가 가격 어댑터를 새 검증 큐에 활성화하지 않았다.

## 검증

- 백엔드 51건 통과: 검색 JPA 32, 검색/배지 API 8, 연결 쓰기 보호 3, 선택 등록 통합 8. 마켓 AND/NOT·페이지 집계, 과거 번호·비정상 JSON, 카페24 하위 독립 상태, 품절·미확정 삭제, 미반영 상태, 잘못된 검색 요청 400을 포함한다.
- [PostgreSQL 검증 스크립트](../../backend/tools/verify-market-search-postgres.py): 네트워크와 외부 포트가 없는 임시 PostgreSQL 16에서 JSON 식별자 15개 사례와 상품 10,000개/등록행 15,000개의 복합 검색 결과를 확인했다. 테스트 컨테이너는 제거했다. 운영 데이터 성능 측정이나 앞선 7개 DDL 검증은 아니다.
- 실제 React 상품 목록을 가상 API 응답으로 Chrome에서 검증했다. 빠른 조건의 요청 JSON, 상충 마켓 제거, 다중 SB코드 정규화·조건 유지, 미반영 필터, 조회 실패 시 이전 상품 선택 차단, 검색 후 선택 초기화와 조건 초기화를 확인했다.
- TypeScript, 프론트 빌드, 변경 파일 ESLint 오류 0건, 변경 Java 형식 검사, `git diff --check` 통과. 기존 TanStack React Compiler 호환 경고 1건과 큰 번들 경고는 유지된다.
