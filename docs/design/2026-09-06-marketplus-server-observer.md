# 마켓플러스 서버 수집기·저장 재개

2026-09-06. [전송 실패·결과 충돌 검색](2026-09-06-marketplus-issue-search.md)의 후속 단계다.

**2026-09-07 후속: 사용자 로그인·계정 대조 후 서버 수집과 DB 업로드를 모두 가동했다. 완료·실패 각 10페이지 200행을 수집하며, 실제 관측 402건의 중복 방지 저장을 확인했다. API·프론트와 선행 DDL 9개도 운영 반영했다.** 기본 완료 탭 주소·가변 아이콘 표기 문제를 실제 DOM 근거로 수정했다. 아래 설치 당시 기록과 최신 상태는 구분하며 [최신 운영 배포 기록](2026-09-07-products-deployment.md)을 따른다.

수집 장소는 서버 전용 브라우저(추천)와 맥 라이브 크롬 중 선택을 질문했다. 답변이 없어 추천한 서버 방식으로 준비한다고 설명한 뒤 설치했다. 사용자가 서버 방식을 확정했다고 기록하지 않는다. 새 서버 브라우저의 최초 로그인은 사용자 입력이 필요하며 맥 브라우저의 쿠키·암호를 복사하지 않았다.

## 구현

- `tools/marketplus/browser.py`: 전용 Chromium의 W3C WebDriver 연결, 세션 재접속, 기존 검증 DOM 스냅샷·다음 페이지 스크립트를 사용한다. 마켓플러스 사설 API를 만들거나 로그인 암호를 입력하지 않는다. 이력 화면과 로그인 URL 외의 페이지 이동은 노출하지 않는다.
- `tools/marketplus/worker.py`: 단일 프로세스 파일 잠금, 기본 15분 간격, 완료/실패 각 최대 10페이지, 파일 우선 보존 후 서버 저장. 새 탐색의 현재 날짜 범위를 확인하고 페이지 순서·조건·행 경계 검사를 재사용한다. 한 탭을 확인하지 못하더라도 다른 결과 탭은 확인하며 미확인 부분을 명시한다. 자동 수집/서버 저장을 별도로 켤 수 있고 기본값은 둘 다 중지다.
- `tools/marketplus/relay.py`: 종료된 수집 파일을 먼저 전체 검사하고 페이지별 저장 결과를 0600 권한으로 원자적 기록한다. POST 직전 결과 미확인 상태를 저장하므로 재시작·응답 유실 시 같은 페이지를 서버의 중복 방지 경로로 재전송할 수 있다. 확인된 페이지는 건너뛴다. 서버·계정·원본 내용이 다르면 과거 저장 기록을 재사용하지 않는다.
- HTTP 200만으로 저장 완료를 판단하지 않는다. 행 수·행 번호·상품번호·저장/중복/제외 합계를 검증한다. 부분 수집 파일의 저장 완료는 전체 수집 완료가 아니다.
- 저장 중 DB 오류는 서버 `Item.retryable=true`로 구분한다. 계정·상품 연결 불일치와 메시지 문자열 비교로 혼동하지 않는다. 영구 제외는 계속 표시하며 자동 반복하지 않는다. 수정 후 명시적으로 재검토할 수 있다.
- 429의 `Retry-After`는 파일 하나가 아닌 업로드 전체에 적용하고 재시작 후에도 대기를 유지한다. 인증 오류/미배포 경로/리다이렉트는 전송을 차단한다. 로그인 상실이 이미 수집된 파일의 저장을 막지 않는다. 중단/손상 파일 때문에 다른 정상 파일이 영구적으로 밀리지 않게 했다.
- 외부 마켓 상품 수정·재전송·판매 재개 기능은 이 수집기에 없다. 서버 저장 클라이언트도 준비 상태 GET와 관측 이력 POST만 허용한다.

`status.json`은 마지막 시도·동작 확인·수집·저장 확인 시각과 중지/대기/부분 범위를 기록한다. 동작 확인은 30초마다 갱신한다. API는 고정된 읽기 전용 상태 파일만 읽고, 최근 3분의 동작을 확인하지 못하면 `STALE`을 반환한다. 브라우저 세션 ID, 인증정보, 임의 파일 내용이나 원문 예외를 반환하지 않는다. 날짜/형식 오류·상태 조회 실패도 명시한다.

새 `GET /api/v1/marketplus/observer/status`와 상품 목록의 상태 표시를 연결했다. 이 API·프론트는 아직 운영 미배포다. [검증 화면](2026-09-06-marketplus-observer-preview.png)은 실제 컴포넌트의 가상 응답 Chrome 검사다.

## 실제 서버 설치

서버 폴더: `/home/ubuntu/projects/sbshop-marketplus-observer`. 이 폴더의 `observer.compose.json`은 저장소의 선택적 Compose 구성에서 전용 브라우저/수집기 두 서비스만 추린 설치본이다. Compose 프로젝트명은 `sbshop-marketplus`다.

| 항목 | 상태 |
| --- | --- |
| `projects-sbshop-marketplus-browser-1` | 가동, 사용자 로그인 완료 |
| `projects-sbshop-marketplus-worker-1` | 가동, `OBSERVED_PARTIAL` |
| 수집 / 업로드 플래그 | 수집 true / 업로드 true |
| 기존 API / 프론트 | 기동 시각 유지, 재시작 없음 |
| 브라우저 공개 포트 | 없음. 서버 `127.0.0.1:17900`만 사용 |
| Mac 접속 | SSH 터널을 통해 `http://127.0.0.1:17900/vnc.html?autoconnect=1&resize=scale` |

사용자 크롬에 원격 화면을 열고 canvas 연결과 실제 서버의 카페24 로그인 화면을 확인했다. 로그인 전 화면 검증이며 수집 성공 검증이 아니다. SSH 제어 소켓은 `/private/tmp/sbshop-marketplus-ssh.sock`이며 사용자 로그인 동안 유지한다. 화면 접속이 끝난 후에는 해당 소켓의 연결만 종료한다. 서버 수집기는 맥의 터널에 의존하지 않는다.

브라우저는 Selenium의 ARM64 지원과 noVNC 제공 구성을 따라 별도로 설치했다([공식 Docker Selenium 문서](https://github.com/SeleniumHQ/docker-selenium)). `4.48.0-20260905`와 manifest digest `sha256:fcf9eef47b9546a2252937481a8298ce0958d20c9d91e040d480184e80b41c76`를 고정했다. 기존 오래된 Selenium 컨테이너는 교체하지 않았다. 비밀번호 없는 VNC 화면은 공개 포트로 열지 않고 SSH 인증 경로에서만 접근한다.

영속 볼륨은 `sbshop-marketplus-browser-profile`, `sbshop-marketplus-observer-state`, `sbshop-marketplus-observer-status`로 분리했다. API 통합 배포 때는 마지막 상태 볼륨만 읽기 전용으로 연결한다. 인증정보는 원격 운영 API 컨테이너에서 필요한 두 환경변수만 내부 전달했고 명령 인수·소스·설치 기록에 쓰지 않았다.

1. 완료: 사용자 로그인 후 `younzara`, G마켓 `younzara`, 옥션 `shouldbe2480`, shop 1을 DOM에서 재확인했다. 매 주기 계정 대조도 추가했다.

3. 완료: 본 앱과 선행 DDL 9개를 운영 반영했다. 현재 계정의 이력 연동 사용을 위해 `is_active=true`와 판매 계정 환경변수를 설정했고 `ready=true`를 확인했다. 과거 false 설정 사유를 추정하지 않았으며 변경 근거·이전 값은 배포 기록에 보존했다.
4. 완료: 200행 파일럿 저장 후 자동 업로드를 켜 402건의 고유 관측과 실제 목록·실패 이력을 대조했다. 저장 응답을 확인하지 않은 관측은 저장 완료로 표시하지 않는다.
5. 실제 필드별 전달 검증·변경 버전 대응과 별도의 마켓 재전송 작업을 연결한다. 관측 이력만으로 `market_sync=T` 제한을 해제하지 않는다.

보관 파일은 자동 삭제하지 않는다. 과거 이력의 전체 수집·보관 주기 최적화, 실제 로그인 세션 만료·재로그인·장기 실행 검증은 남아 있다. 이 설치만으로 전체 자동 동기화가 완료된 것은 아니다.
