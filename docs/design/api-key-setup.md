# 소싱 자동화 API 키 발급 가이드

신규 상품 등록 자동화(추천→검수→등록)에 쓰는 외부 API 3종의 발급 절차다.
**전부 무료이고, 전부 선택사항이다** — 하나도 없어도 파이프라인은 돌아간다.

| 키 | 없으면 어떻게 되나 | 소요 시간 |
|---|---|---|
| 네이버 검색 API(쇼핑) | 경쟁 상품 수·국내 최저가 신호가 빠진다 → **가격 경쟁력 판단 불가** | 약 5분 |
| 네이버 검색광고 API | 월간 검색량·연관 키워드가 빠진다 → **수요 판단과 키워드 품질 저하** | 약 10분 |
| OpenCode Zen | 상품명·키워드가 규칙 기반으로 생성된다 → **상품명 품질 저하** | 약 2분 |

> 신호가 없는 항목은 0점이 아니라 **가중치에서 제외**되고 나머지 신호로 정규화된다.
> 즉 없어도 순위는 매겨지지만, 근거가 줄어 추천 정확도가 떨어진다.
>
> 식약처 반입차단 성분 목록(통관 게이트)은 **인증키가 필요 없다.** 별도 준비 없이 동작한다.

---

## 1. 네이버 검색 API (쇼핑) — 5분

키워드로 검색했을 때 **경쟁 상품이 몇 개인지**와 **국내 최저가가 얼마인지**를 준다.
"우리가 이 가격에 팔 수 있나"를 판단하는 근거다.

### 절차

1. <https://developers.naver.com/main/> 접속 → 네이버 계정 로그인
2. 상단 **Application** → **애플리케이션 등록**
3. 입력값
   - **애플리케이션 이름**: `sbshop-sourcing` (아무거나)
   - **사용 API**: **검색** 체크
   - **비로그인 오픈 API 서비스 환경**: **WEB 설정** 선택 →
     웹 서비스 URL에 `https://168.107.31.154` 입력
     > 서버에서 호출하므로 URL 검증은 실제로 걸리지 않지만, 등록 화면이 값을 요구한다.
4. **등록하기** → 발급된 화면에서 복사
   - **Client ID** → `NAVER_OPENAPI_CLIENT_ID`
   - **Client Secret** → `NAVER_OPENAPI_CLIENT_SECRET`

**한도**: 하루 25,000회. 후보 1건당 1회 쓰므로 넉넉하다.

## 2. 네이버 검색광고 API (키워드도구) — 10분

키워드의 **월간 검색량(PC/모바일)**과 **연관 키워드**를 준다.
수요 점수의 가장 큰 가중치(20)이고, 생성되는 검색 키워드의 품질도 여기서 나온다.

> 광고를 집행할 필요는 없다. 계정만 만들면 API를 쓸 수 있다.

### 절차

1. <https://searchad.naver.com/> 접속 → **신규 가입** (기존 네이버 계정으로 가능)
   - 사업자/개인 선택 후 가입. 광고 등록이나 결제수단 등록은 하지 않아도 된다.
2. 로그인 후 우측 상단 **... 도구** → **API 사용 관리**
3. **네이버 검색광고 API 서비스 약관 동의** → **등록** 버튼
4. 발급 화면에서 세 값을 복사
   - **액세스라이선스** → `NAVER_SEARCHAD_API_KEY`
   - **비밀키** → `NAVER_SEARCHAD_SECRET_KEY`
   - **CUSTOMER_ID** (화면 우측 상단 "고객 ID" 또는 API 관리 화면 상단의 숫자) →
     `NAVER_SEARCHAD_CUSTOMER_ID`

> ⚠️ **비밀키는 발급 시 한 번만 보인다.** 창을 닫기 전에 복사해 두자.
> 잃어버리면 재발급해야 하고, 재발급하면 이전 키는 즉시 무효가 된다.

**한도**: 공식 문서상 제한 명시 없음(과도한 호출 시 제한). 후보 1건당 1회.

## 3. OpenCode Zen — 2분

iHerb 영문 상품명을 **한국 오픈마켓용 한글 상품명**으로 바꾸고 검색 키워드를 만든다.
**무료 모델만 사용한다** (`nemotron-3-ultra-free` 주력, `ling-3.0-flash-free` 폴백).

### 절차

1. <https://opencode.ai/auth> 접속 → 로그인
2. API 키 발급 → 값 복사 → `ZEN_API_KEY`

이미 로컬에 `opencode` CLI를 쓰고 있다면 키가 이미 있다. 아래로 확인:

```bash
python3 -c "import json;print(json.load(open('$HOME/.local/share/opencode/auth.json'))['opencode-go']['key'])"
```

> 유료 모델은 쓰지 않도록 코드에 무료 모델만 지정해 두었다(`zen.models`).
> 다른 모델을 넣고 싶으면 `ZEN_MODELS` 환경변수로 바꿀 수 있다.

## 4. 서버에 반영하기

키는 **서버의 `~/projects/sbshop-agent/.env`** 에 넣는다. 이 파일은 git에 올리지 않는다.

```bash
# 1) 서버 접속
ssh -i ssh-key-2026-06-25.key ubuntu@168.107.31.154

# 2) .env 편집 — 파일 맨 아래에 이미 빈 항목이 만들어져 있다
cd ~/projects/sbshop-agent
nano .env      # 또는 vi .env

# 3) 아래 항목의 = 뒤에 값을 붙여넣는다 (따옴표 없이)
#    NAVER_OPENAPI_CLIENT_ID=
#    NAVER_OPENAPI_CLIENT_SECRET=
#    NAVER_SEARCHAD_API_KEY=
#    NAVER_SEARCHAD_SECRET_KEY=
#    NAVER_SEARCHAD_CUSTOMER_ID=
#    ZEN_API_KEY=

# 4) 저장 후 API 컨테이너만 재생성 (env는 재시작이 아니라 재생성해야 반영된다)
docker compose up -d sbshop-api
```

> `docker restart`로는 반영되지 않는다. compose가 환경변수를 컨테이너 생성 시점에 굽기 때문이다.
> 반드시 `docker compose up -d sbshop-api`를 쓴다.

### 반영 확인

```bash
# 컨테이너에 값이 들어갔는지 (키 이름만 확인 — 값은 출력하지 않는다)
docker exec projects-sbshop-api-1 printenv | cut -d= -f1 | grep -E 'NAVER|ZEN'

# 실제 동작 확인: 발굴을 1회 돌리고 후보에 수요 신호가 붙는지 본다
# 화면: 상품 추천·자동등록 → "지금 재수집" → 완료 후 목록의 '국내 시장' 열에
#       검색량/경쟁 숫자가 채워지면 성공. '-' 로 남으면 키가 안 먹은 것이다.
```

키가 잘못됐을 때는 조용히 실패하고 신호만 비는 설계라(파이프라인을 멈추지 않기 위해),
값이 계속 `-`로 나오면 API 로그를 본다:

```bash
docker logs projects-sbshop-api-1 | grep '\[수요신호\]'
# 예) [수요신호] 네이버 키워드도구 HTTP 401 — keyword=비타민D3   ← 키/서명 문제
#     [수요신호] 네이버 쇼핑검색 HTTP 429 — query=...            ← 일일 한도 초과
```

## 5. 참고 — 키 없이 먼저 써보기

키를 넣기 전에도 다음은 전부 동작한다:

- iHerb 베스트셀러 발굴 · 중복 제외
- **통관 게이트**(식약처 반입차단 성분 대조) — 인증키 불필요
- iHerb 신호 기반 점수(판매량·리뷰·평점·랭킹·할인율)
- 수익성 가드(마진 미달 탈락)
- 마켓별 초안 생성 · 검수 · 등록

즉 **키 없이 한 바퀴 돌려보고**, 추천 품질이 아쉬우면 그때 키를 넣어도 된다.
