# 판매자센터 기반 G마켓·옥션·11번가 상품 삭제 계획

상태: 사용자 요청으로 브라우저 삭제 구현 보류. 현재 적용할 정책은 11번가·카페24 자식 마켓 잔여 정보를 DB에 보존하고 SB 소프트 삭제를 허용하는 것이다. 아래 브라우저 실행 계획은 향후 검토용이며 실행하지 않는다.

## 1. 확인한 사실과 확인하지 못한 부분

### 11번가 — 로그인된 현재 화면 확인
- 상품관리 > 상품조회/수정에 `선택상품 삭제`가 있으며 복수 상품 선택을 지원한다.
- 현재 버튼 href는 `fnListDelete('U')`이고, onclick의 NPOF017은 통계 코드다.
- 현재 로드된 공식 화면 스크립트에서 fnListDelete는 상태 105/106/108/109만 허용한다.
- 확인 문구는 서비스 내 미노출·복구 불가와 삭제 전 반품지/출고지 변경 관련 주의사항을 안내한다.
- 화면 함수는 목록 숨김 처리(updateProductHideListJSON, hideYN=Y)에 연결된다. 이것을 공개 삭제 API 또는 물리적 데이터 삭제로 부르지 않는다.
- 별도 fnSellerListDelete(영구삭제) 코드도 존재하지만, 현재 버튼의 실행 경로가 아니다. 숨은 함수를 직접 호출하지 않는다.
- 대상 201126IHB012 / 3264931038은 현재 화면에서 판매중지로 확인됨. 프런트 조건은 통과할 수 있으나 서버의 삭제 허용 여부는 실행 검증 전 미확정.
- 현재 SB의 DELETE /rest/prodservices/product/{prdNo}는 -997(등록된 API 정보 없음)을 반환하며 공개 공식 문서에도 없다.
- 예전 공식 영구삭제 공지는 일정 연기된 2014년 자료여서 현재 조건의 근거로 쓰지 않는다.

### G마켓·옥션 — 공식 자료 및 로그인 진입 확인
- ESM 마스터 shouldbeshop 로그인과 상품 조회/수정 진입을 확인했다.
- 실제 상품 화면은 https://item.esmplus.com/goods/list 의 교차 도메인 iframe이다. 현 AppleScript 상위 문서 읽기로 직접 접근되지 않는다.
- 별도 탭 진입은 유지되지 않았으며, 화면 캡처 경로는 macOS 화면 기록 권한 요청이 발생했다. 삭제 컨트롤·확인창·현재 조건을 아직 검증하지 못했다.
- ESM 공식 FAQ에는 판매중지 후 미수정 상품 자동 삭제 기준이 G마켓 13개월, 옥션 90일로 안내된다. 즉시 삭제의 대안으로 간주하지 않는다.
- 옛 공식 광고 FAQ에는 옥션 판매상태 항목으로 상품삭제가 등장한다. 현재 ESM 동일 UI/동작을 보장하는 근거는 아니다.

## 2. 추천 방식

SB는 작업과 결과를 관리하고, 사용자의 맥에서 실행되는 전용 브라우저 실행기가 로그인된 판매자센터의 정식 화면을 조작한다. 처음에는 라이브 크롬으로 화면 절차를 검증한다. 상시 운영은 별도 작업용 Chrome 프로필과 Playwright 실행기를 우선 검토한다. 기존 개인 크롬을 재시작하거나 프로필·쿠키를 복사하지 않는다. 기존 크롬을 계속 사용하려면 프레임 권한이 있는 전용 확장 프로그램 방식의 기술 검증이 필요하다.

- 마켓 공개 API가 없어도 화면에서 제공하는 검색·선택·삭제 절차를 사용한다.
- 실제 화면에 연결된 정식 기능만 실행한다. 비공개 요청 주소 직접 재현은 초기 범위에서 제외한다.
- 브라우저 로그인·인증은 사용자가 수행한다. 세션 만료·추가 인증은 `로그인 필요`로 정지하고 재로그인 후 재조회부터 재개한다.
- 11번가와 ESM은 독립 큐로 처리할 수 있으나, G마켓·옥션은 같은 ESM 세션을 공유하므로 화면 조작을 직렬화한다.
- 맥이 꺼지거나 잠자기하면 작업은 대기한다. 서버 무인 브라우저는 별도 프로필·로그인 복구 검증 후 후속 단계로 검토한다.

## 3. 삭제 흐름

1. SB 선택 상품의 SB코드, 마켓, 판매자 계정, 실제 마켓 상품번호를 삭제 작업에 고정 저장한다.
2. 자동 가격·재고 동기화, 재판매, 재등록과 충돌하지 않도록 해당 상품/마켓에 삭제 진행 상태를 설정한다. 진행 중 쓰기가 있으면 완료를 기다린다.
3. 로그인 계정 확인 후 상품번호로 조회한다. 기간·판매상태 필터 누락에 의한 가짜 미조회가 없도록 전체 범위를 확인한다.
4. 조회 결과의 상품번호·계정·SB코드(제공되는 경우)를 대조한다. 불일치·중복·조회 오류는 실행을 멈춘다.
5. 삭제 미리보기에 마켓별 실행 방식과 상품번호를 표시한다. 판매중지 선행이 필요한 경우 이를 별도 작업으로 알린다. 판매금지 상품을 재판매하지 않는다.
6. 승인된 범위의 행만 선택하고 화면의 정식 삭제 버튼과 확인창을 처리한다. 성공/거절 메시지와 상품별 결과를 저장한다.
7. 새 조회로 상품 상태를 확인한다. 즉시 반영되지 않으면 일정 간격으로 재조회하며, 이 동안 삭제를 다시 누르지 않는다.
8. 결과 불명이면 `결과 확인 필요`로 남긴다. 재시도는 먼저 재조회하고 실제 미처리임을 확인한 경우에만 삭제를 재실행한다.

초기에는 한 번에 한 상품으로 결과를 명확히 구분한다. 단건 성공·거절·세션 만료 검증 후 10~20개 소규모 일괄 처리로 확대한다. 사이트의 실제 선택 한도는 별도로 확인하며 고정 추측하지 않는다.

## 4. 상태 및 성공 판정

실행 상태: 대기 / 로그인 필요 / 대상 확인 / 삭제 실행 / 반영 확인 중 / 완료 / 거절 / 결과 확인 필요.

처리 결과는 다음과 같이 분리한다.
- 실제 상품 부재 확인
- 판매자센터 삭제 처리 확인(11번가 목록 삭제 등)
- 판매중지 확인
- 삭제 거절
- 확인 불가

판매중지나 검색 0건 하나만으로 물리적 삭제 성공을 주장하지 않는다. 11번가 목록 삭제 완료는 화면의 성공 결과와 올바른 재검색 결과로 검증하되, 원상품 조회 API에 데이터가 남는지 파일럿에서 함께 확인한다. 남아 있어도 목록 삭제 결과와 혼동하지 않는다. 별도 상품 부재 확인 전에는 기존 DELETED_ON_MARKET 증거를 임의로 생성하지 않는다.

## 5. SB와의 연결

- 삭제 작업은 활성 상품 목록과 독립적으로 저장한다. 이미 소프트 삭제된 상품도 보존된 마켓 번호로 후속 삭제할 수 있어야 한다.
- 카페24 삭제 시 G마켓·옥션 상품번호를 작업에 복사한다. 카페24 소프트 삭제를 G마켓·옥션 실제 삭제로 간주하지 않는다.
- 사용자가 정한 기존 정책(카페24 연동 G마켓·옥션 수동 대기가 SB 소프트 삭제를 막지 않음)을 유지한다. 외부 삭제 잔여 작업은 별도 목록에 계속 남긴다.
- 11번가에서 목록 삭제만 확인된 경우 SB 소프트 삭제 완료 조건으로 인정할지는 물리적 부재와 차이를 보여준 뒤 정책을 확정한다. 승인 전에는 자동으로 조건을 완화하지 않는다.
- 마켓별 자동 동기화 금지는 SB 소프트 삭제 여부와 별개로 삭제 작업 상태에 연결한다. 재시작 후에도 다시 판매가능으로 바뀌지 않게 한다.
- 계정·상품번호·작업 ID·실행 회차, 전후 상태, 화면 메시지, 확인 시각, 근거 캡처를 보관한다. 비밀번호·쿠키는 서버 결과에 포함하지 않는다.
- 기존 MarketPlus 관측기의 계정 확인·브라우저 잠금·결과 전달 패턴은 참고하되 관측 전용 프로세스에 삭제 권한을 섞지 않는다.

## 6. 화면

배치 상품 상세/상품관리의 기존 삭제 버튼에서 하나의 삭제 작업을 생성한다.
- 마켓별 행: 처리 방식 / 진행 상태 / 실제 확인 결과 / 간결한 사유 / 재조회 또는 재시도.
- `브라우저 연결됨`, `로그인 필요`, `브라우저 실행기 꺼짐`을 사용자가 구분할 수 있도록 표시한다.
- 일괄 삭제 결과를 모두 성공으로 합치지 않는다. 완료 8 / 거절 1 / 확인 중 1 식으로 표시한다.
- SB 삭제 완료와 외부 마켓 잔여 삭제 작업을 각각 표시한다.
- 소프트 삭제 상품의 마켓 잔여 작업을 찾는 별도 `남은 마켓 삭제` 목록을 둔다.

## 7. 단계별 구현·검증

1. ESM 실제 화면의 삭제 컨트롤, G/A 분리 여부, 확인창, 처리 한도, 결과 조회 방법 검증. 현재 접근 제한 해결 필요.
2. 세 마켓의 읽기 전용 대상 검색과 미리보기 구현. 실제 상품번호 대조 검증.
3. 작업 DB·중복 실행 방지·자동 동기화 충돌 방지·브라우저 실행기·원문/화면 증거 저장 구현.
4. 11번가의 존재하지 않는 DELETE 호출 제거, 자동 삭제 미지원/브라우저 작업 안내와 resultMessage 파싱 보완.
5. 사용자가 선택한 삭제 대상에 대해 마켓별 단건 파일럿. 첫 실행 전에 실제 대상과 삭제 의미가 보이는 미리보기 승인.
6. 승인된 단건 결과를 근거로 SB 소프트 삭제 완료 정책 확정, 소규모 일괄 처리 확대.
7. 사용자 화면 검토 후 배포. 기능 구현 완료와 실제 운영 검증 완료를 구분하여 보고.

필수 검증: 다른 계정·다른 상품 보호, 선택 초기화, 일부 성공, 응답 유실 후 중복 삭제 방지, 로그인 만료, 화면 개편, 삭제 지연, UI 성공 후 상품 잔존, SB가 먼저 삭제된 상품 후속 처리, 실행 도중 배치 동기화 경쟁, 재기동 후 작업 복구.
