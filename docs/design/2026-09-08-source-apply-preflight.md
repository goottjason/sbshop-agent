# 소싱 검토 결과 적용 전 점검

2026-09-08 소싱 콘텐츠·가격재고의 검토→DB 적용 경로를 점검했다. 이 단위에서는 운영 DB 적용, 외부마켓 쓰기, 배포를 실행하지 않았다. DB 변경 검사는 격리 H2 테스트 DB에서 수행했다.

## 확인한 적용 계약

콘텐츠 수집 요청 시 상품명·원문명·묶음수량·용량·단위와 기존 이미지를 `Captured`에 고정한다. 수집 작업은 이 입력으로 기존 상품상세 템플릿을 생성하고 `Proposed`에 영속 보관한다. 검토 시 선택한 필드만 변경 명령에 포함한다. 저장 시에는 수집을 다시 실행하거나 HTML을 새로 생성하지 않고, 고정한 검토 명령과 현재 편집 정책의 재계획 결과가 일치해야 한다.

- 상세 HTML만 선택하면 상품명·묶음수량·대표/부가 이미지 DB 필드는 유지되며, 검토한 HTML 문자열만 저장된다. 상세 HTML 안에는 수집 당시 생성에 사용한 최신 게시 이미지가 포함될 수 있다는 안내는 유지한다.
- 이미지만 선택하면 원본 URL과 게시 이미지 URL을 함께 검토·저장하고, 기존 상세 HTML은 바꾸지 않는다.
- 수집 이후 상품명·묶음수량·용량·단위가 바뀌어도 생성 결과는 캡처한 값으로 유지된다. 변경된 revision의 상품에는 해당 오래된 검토를 적용할 수 없다.
- 소싱 스냅샷은 잠금으로 직렬화하고, 상품 잠금·revision·마켓 연결 fingerprint·검토 만료·현재 편집 정책을 확인한다.
- 상품 변경·revision·변경이력·마켓 미반영 target·선택한 필드의 적용시각은 동일 transaction에 참여한다. 이력 또는 target 생성이 실패하면 전부 rollback된다.
- 완료한 검토를 다시 저장하면 기존 이력 ID를 반환하고 중복 변경·target을 만들거나 적용시각을 갱신하지 않는다. 이후 소싱 URL이나 검토 만료가 달라져도 완료된 요청의 재응답은 동일하다.

## 발견한 결함과 보완

콘텐츠 경로에는 가격·재고 경로와 달리 현재 `sourceUrl`·`vendor`를 수집 스냅샷과 명시적으로 대조하는 검사가 없었다. 콘텐츠 조회·검토·저장에 동일성 검사를 추가했다. JPA revision을 갱신하지 않은 SQL/가져오기 작업이 소싱처나 URL을 바꿔도 이전 콘텐츠는 적용하지 않는다.

또한 이미지 선택은 `sourceImages`와 `hostedImages`를 함께 바꾸는데, 원본 추적값 `sourceImages`가 마켓 필드로 취급되어 스마트스토어와 쿠팡의 지원 가능한 이미지 변경까지 제외됐다. 사용처를 조사한 결과, 기존 상품의 원본 URL 목록은 마켓 adapter와 HTML 생성에서 사용하지 않는다. 기존 HTML 생성과 실제 마켓 이미지 payload는 게시 이미지 `hostedImages`를 사용한다. 신규상품 소싱 DTO의 원본 URL→호스팅 흐름은 별개다.

따라서 `sourceImages`를 내부 추적 필드로 표시하고 마켓 target에서는 제외했다. 검토와 변경이력에는 원본·게시 이미지 변경을 모두 남긴다. 원본 URL만 바꾸는 경우 이력만 만들고 마켓 미반영 대상으로 기록하지 않는다. 게시 이미지의 실제 수정 제한은 유지한다.

외부마켓 필드 전송 모달에서도 원본 이미지 URL을 선택 목록에서 제거했다. 과거 작업에 원본 이미지 필드가 남아 있어도 재검토 요청에는 포함하지 않으며, 원본 이미지뿐인 과거 작업은 재접수하지 않는다. DB 편집과 소싱 비교의 원본 이미지 정보는 유지한다.

| 연결 상태 | 소싱 이미지 적용 검토 |
|---|---|
| 스마트스토어 | 게시 이미지 계약에 따라 검토 가능; target에는 `hostedImages`만 포함 |
| 쿠팡 sellerProductId·vendorItemId 확인됨 | 검토 가능; target에는 `hostedImages`만 포함, 후속 승인·재조회 조건 유지 |
| 쿠팡 vendorItemId 미확정 | 제외 유지 |
| 카페24 단독 | 게시 이미지 수정 조건 미확인으로 제외 유지 |
| 카페24의 G마켓·옥션 연결 또는 G마켓·옥션 직접 연결 | 게시 이미지 수정 조건 미확인으로 제외 유지 |

## 검증

수정한 Java 4개 파일만 포맷하고 다음 범위 **82건 모두 통과**했다.

| 회귀 범위 | 통과 |
|---|---:|
| ProductContentServiceIntegrationTest | 26 |
| ProductSourceServiceIntegrationTest | 21 |
| ProductEditServiceIntegrationTest | 35 |

추가 검사는 소싱 URL/소싱처가 revision 증가 없이 바뀐 경우의 차단, 고정 HTML의 정확한 저장값, 원본 URL의 내부 이력, SS/CP 게시 이미지만 target 생성, 미지원 마켓 제한 유지, target 실패의 원자적 rollback과 같은 검토의 재시도, 적용시각·이력 ID 불변을 포함한다.

프론트의 `npx tsc -b`, `npm run build`, 기존 필드 전송 브라우저 fixture 12개 항목도 통과했다. fixture는 로컬 HTTP와 API 모의 응답을 사용하며 실제 마켓 요청을 하지 않는다.

운영 실제 적용 및 이후 마켓 동기화 성공은 이 점검으로 주장하지 않는다. 운영 적용 전에는 해당 상품의 최신 수집 결과로 새 검토를 만들고, 실제 변경값과 마켓별 허용 조건을 확인해야 한다.
