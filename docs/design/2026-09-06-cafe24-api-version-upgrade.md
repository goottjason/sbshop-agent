# 카페24 앱 API 버전 변경

2026-09-06. 사용자가 개발자센터 버전관리 탭을 열고 최신 API 버전으로 직접 변경하는 것을 명시적으로 승인했다.

## 확인한 설정과 변경 요청

- 대상: [카페24 개발자센터 API 버전관리](https://developers.cafe24.com/admin/apps/front/apiupgrade)의 선택된 앱 `younzara`.
- 변경 전 표시: `2021-09-01`. 화면은 `2022-12-01`에 만료되었다고 안내한다. 이는 저장된 설정 표시이며 만료 버전 대신 실제 호출에 적용되던 대체 버전까지 확인한 것은 아니다.
- 선택 가능한 버전: `2026-09-01`, `2026-06-01`, `2026-03-01`, `2025-12-01`. 화면의 최신 버전은 `2026-09-01`이다.
- 확인창의 변경 전·후 버전과 선택된 앱을 대조한 뒤, 사용자가 승인한 `2021-09-01 → 2026-09-01`의 **변경** 버튼을 클릭했다.

**변경 완료를 확인했다.** 사용자가 적용 완료 알림을 확인하고 닫았으며, 이후 Chrome에서 페이지를 새로 고침하고 `younzara` 앱을 다시 선택해 서버에 저장된 설정을 재조회했다. 본문에 `현재 버전: 2026-09-01`과 최신 버전을 사용 중이라는 안내가 나타났다. 버전 선택 항목도 `data-api-curr-version=2026-09-01` 및 `2026-09-01 Current`로 일치했다. 변경 버튼은 한 번만 눌렀다.

변경 완료 알림은 macOS 보조 접근 권한 제한으로 자동 조작할 수 없어 사용자가 닫았다. 이후 재조회는 정상 동작했으며 남아 있는 차단 사항이 아니다. 이 기록의 완료 근거는 버튼 클릭뿐 아니라 새로 고침 후 앱 재선택으로 얻은 현재 버전 표시다.

## 코드 대조와 남은 검증

화면의 변경 이력에서 상품 수정의 `has_option` 제거, 세율 관련 조건 변경, 이미지 URL과 상품 상세 응답 변경을 확인했다. 현재 카페24 어댑터의 `has_option` 사용은 옵션 여부 조회이며 상품 수정 요청에 이 필드를 추가하지 않는다. 앞 단계의 [가격 조건 보완](2026-09-06-cafe24-live-api-contracts.md)은 세금 설정에 맞지 않는 가격 전송을 보류한다.

`Cafe24RestClient`는 현재 `X-Cafe24-Api-Version`을 지정하지 않는다. 따라서 앱 설정 변경은 애플리케이션 코드 배포와 별개의 작업이다. 이번 요청으로 상품 관리 후속 코드 전체를 배포한 것으로 기록하지 않는다. 특정 API 버전을 코드에 추가로 고정하지 않았고, 상품 가격·재고·이미지 등 외부 상품값을 직접 수정하는 호출도 수행하지 않았다.

앱 버전 변경 후 실제 상품 유형별 품목 조회·수정 가능 범위와 G마켓·옥션 전달 계약 검증은 남는다. 이번 설정 변경에 대해 애플리케이션 테스트를 새로 실행하거나 실제 상품 쓰기를 검증하지 않았다. 버전 업그레이드만으로 무옵션 바코드 수정 지원이나 전체 마켓 동기화 완료를 확정하지 않는다.
