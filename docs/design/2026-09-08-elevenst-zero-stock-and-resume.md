# 11번가 수량 0·품절·판매 재개 확장

이 문서는 [최초 양수 전용 구현](2026-09-08-elevenst-reviewed-stock.md)의 후속이다. 수량 0 저장과 품절·일시 전시중지 재개를 지원하되, 실제 재고와 판매 상태를 독립적으로 확인한다. 상품 전체 수정이나 재등록 API를 사용하지 않는다.

## 계약과 실제 관측

- [수량 변경](../external-api/elevenst/live-2026-09-08/stock-update.json): `PUT /rest/prodservices/stockqty/{prdStckNo}`. 직전 단일 품목의 `prdNo`, `prdStckNo`, 목표 `stckQty`, 보존한 `optWght`만 전송한다. 성공 영수증 `productNo`는 재고번호다.
- [상품 조회](../external-api/elevenst/live-2026-09-08/product-read.json)와 [재고 조회](../external-api/elevenst/live-2026-09-08/stock-read.json)를 각각 호출한다. 판매 상태 `103` 판매중, `104` 품절, `105` 전시중지를 재고 상태 `01` 사용, `02` 품절과 구분한다.
- [전시중지 해제](../external-api/elevenst/live-2026-09-08/display-restart.json): `PUT /rest/prodstatservice/stat/restartdisplay/{prdNo}`. 일시 전시중지 `105`이고 실제 양수 수량·재고 사용 상태가 이미 목표와 맞는 경우에만 호출한다. 영수증은 실제 판매 상태 재조회를 대신하지 않는다.
- 2026-09-08 13:16 KST 사용자 승인 아래 상품 1229에서 별도 가역 실험을 완료했다. `103/01/300` → 수량 PUT 0 → 독립 GET `104/02/0` → 수량 PUT 300 → 독립 GET `103/01/300`. 두 PUT 모두 업무 코드 200, 현재 무게 0 보존, 상품 DB 전체 행 해시 및 판매가 217,800원·즉시할인 N 불변을 확인했다. 일반 품절 전환과 복구에는 `restartdisplay`가 필요하지 않았다. 운영 원문은 배포 백업의 `elevenst-zero-contract/probe.json`에 보존하며 계정 원문을 이 문서에 복사하지 않는다.

## 실행 및 완료 조건

| 목표 | 완료에 필요한 별도 GET 증거 | 표시 |
| --- | --- | --- |
| 양수 | 실제 수량=목표, 판매 `103`, 재고 `01` | 수량·판매중 확인 |
| 0 | 실제 수량=0, 판매 `104`+재고 `02` 또는 판매 `105`+유효한 재고 `01/02` | `104`는 품절, `105`는 전시중지로 각각 표시 |

전시중지 상태에서도 실제 수량이 300이면 관측값은 300이다. 상태만 보고 0으로 합성하지 않는다. `103/01/0`처럼 수량만 맞고 판매 상태가 다른 경우에도 완료하지 않는다. 3회 실제 전송 이후 계속 불일치하면 `FAILED_MISMATCH`로 종료한다.

`103/104/105` 외 상태는 수량 변경과 재개를 보류한다. `107` 강제종료·`108` 판매금지·승인대기·정상종료·미확인 상태를 재개하지 않는다. 매 호출에서 현재 상품번호/SB·재고번호·계정·판매 상태를 다시 확인한다. 다중 재고항목과 추가구성상품은 계속 제외한다.

한 작업 tick은 실제 변경 요청을 최대 한 번 실행한다. 전시중지 상품의 수량이 다르면 수량만 먼저 보내고, 다음 tick에서 재조회한 뒤 필요한 재개를 별도로 실행한다. `mutateStockOnce`가 네트워크 송신 직전에 공용 호출 제한·배치 pause·revision·계정 가드를 실행하며, 자동 HTTP 재전송·리다이렉트를 허용하지 않는다. 응답 유실 및 429 뒤에는 같은 작업으로 읽기부터 재시도한다. 명시적 업무 오류는 원인 확인 전 반복 쓰기를 차단한다.

`MarketStockTask.observedSaleState/observedStockState`와 작업 API에 실제 상태를 보존한다. [새 DDL](../../backend/docs/ddl/2026-09-08-elevenst-stock-state.sql)은 기존 수량·상태·작업 이력을 추론하거나 변경하지 않고 nullable 열만 추가한다. `CONFIRMED_QUANTITY`는 이 수량·판매 상태 목적의 완료이며 다른 상품 필드나 전체 마켓 동기화 성공을 의미하지 않는다.
