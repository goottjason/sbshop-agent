# 배치 상세에서 상품 삭제

## 확인한 내용
- 사용자 제시 상품 `200901WA005` / iHerb 62771의 원본 페이지를 독립 Chromium에서 읽어 `Discontinued` 표시 확인. URL 문자열만으로 단종 판정하지 않음.
- 기존 삭제는 모든 마켓 삭제 성공 시 SB 상품을 소프트 삭제하며 등록행과 과거 주문 이력을 보존한다. 실패 또는 수동 처리 필요 시 HTTP 409와 disposed=false.
- 기존 일부 어댑터는 삭제 호출이 예외 없이 끝나면 성공으로 간주했다. 이번 변경에서 삭제 후 동일 계정의 엄격한 inspectListing 재조회가 DELETED인 경우에만 성공으로 인정한다.
- 응답 유실 후에도 같은 계정의 DELETED 관측이면 복구 가능. UNKNOWN·품절·판매중지·판매금지·타계정 관측은 SB 폐기를 허용하지 않는다.

## 화면
- 배치 상품 상세의 원본 링크 인근에 `상품 삭제` 버튼.
- 확인창에 상품명/SB코드, 등록 마켓 목록, 마켓 삭제 후 SB 폐기 조건 표시. 사용자 확인 전 삭제 요청 없음.
- 삭제 중 중복 실행/창 닫기 차단. 마켓별 삭제 확인·실패·수동 필요 사유 표시.
- 부분 실패 시 SB 유지 및 명시적 재시도. 기존 삭제 확인된 등록행은 재시도에서 건너뛴다.
- 배치 실행/정지 처리 중에는 버튼 비활성. SB 폐기 후에도 배치 이력은 유지하고 재시도를 비활성화.
- 이 작업에서 실제 상품 삭제나 마켓 변경 요청은 실행하지 않았다.

## 검증
- 삭제 및 배치 통합 테스트 46개, 이후 삭제 보호 조건에 추가한 5개 상태 사례를 포함한 보호 테스트 재실행 통과.
- 삭제 확인창 브라우저 3개, 기존 배치 브라우저 19개, 프론트 빌드 통과.
- 커밋 `00a9ca01`; 배포 작업 `34300476635`.

## 카페24 하위 마켓 삭제 보호
- 운영 확인창 검증 중 대상 Cafe24 등록행에 G마켓 `3490138764`, 옥션 `D888922206` 식별자가 포함된 것을 확인했다. 두 하위 연결 상태는 LINKED이며 SB 상품은 폐기되지 않은 상태였다.
- 부모 Cafe24 삭제 응답은 하위 마켓 삭제 확인을 대체하지 못한다. 하위 식별자가 있고 DETACHED_DELETED가 아니면 해당 마켓을 수동 확인 대상으로 반환하고 Cafe24 삭제도 보류한다.
- 삭제 확인창에 하위 G마켓·옥션까지 표시한다. 이 작업에서 하위 상품을 자동 삭제하는 API를 새로 추정·구현하지 않았다.
- 하위 마켓 미확인 시 부모 삭제/폐기 차단, 삭제 확인된 하위 연결이면 부모 삭제 허용 테스트 추가 통과. 하위 마켓 노출 브라우저 검증 통과.
- 최종 보완 커밋 `690872a4`, 배포 작업 `34300919846`.
- 최종 배포 성공 후 운영 브라우저 검증 통과: 200901WA005 확인창에 스마트스토어·카페24·G마켓·옥션 표시, 하위 삭제 확인 전 보류 안내, 확인 체크 전 실행 버튼 비활성. 모든 운영 검증 요청 GET, 실제 삭제 요청 0, 독립 세션 정리 완료.
