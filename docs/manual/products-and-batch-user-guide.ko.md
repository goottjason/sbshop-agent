# 상품 관리 · 배치 업데이트 사용자 매뉴얼

기준: 2026-09-08 운영 버전 `16ec51f6`. 현재 화면의 버튼명과 운영 API를 대조해 작성했다. 이 문서는 사용법 안내이며, 작성 과정에서 상품 저장·마켓 전송·배치 실행은 하지 않았다.

## 1. 먼저 알아둘 현재 제한

**현재는 ‘아이허브 전체 상품 + 마진율·쿠폰율·최소마진 지정 + 한 번에 배치 실행’ 기능을 사용할 수 없다.** 사용자가 메뉴를 못 찾는 문제가 아니다. 배치 개편 과정에서 기존 전체 실행 동선을 대체하지 못한 기능 공백이다.

현재 배치 페이지는 소싱처를 선택한 후 **현재 페이지에서 최대 50개**를 골라 수집·비교·저장한다. 기존 상품별 가격 정책을 유지하며, 이 화면에는 마진율·쿠폰율·최소마진 입력칸이 없다. 과거 전체 배치 API도 검토 필요 응답을 반환하므로 옛 경로를 호출하는 우회 방법은 사용할 수 없다.

2026-09-08 10:34 KST 운영 조회에서 IHB 활성 상품은 **2,114개**였다. 50개씩 수집하려면 최소 **43묶음**이 필요하다. 수집 실패·편집 제외·마켓 보류가 발생하면 별도 처리가 필요하므로 43번의 작업이 곧 전체 성공을 뜻하지 않는다. 삭제 상품은 이 활성 상품 수에 포함되지 않는다.

## 2. 요청한 조건을 입력하는 위치

요청 조건: **아이허브(IHB), 마진율 10%, 쿠폰율 0%, 최소마진 1,500원**.

아래는 현재 가능한 **선택 상품 단위 절차**다. 전체 배치를 한 번에 실행하는 절차가 아니며, 정책 저장 시 지원되는 마켓 반영 작업이 자동 접수될 수 있다. 이후 수집 저장과 하나의 원자적 작업으로 묶이지 않는다.

### A. 상품별 가격 조건 변경

1. [상품 관리](http://168.107.31.154/sbshop-agent/products)에 접속한다.
2. 기존 검색 조건을 초기화하고 **소싱처 → IHB → 검색**을 누른다. 전체 대상이라면 재고 있음·특정 마켓 등록·콘텐츠 경과일 등의 조건을 추가하지 않는다.
3. 소싱 갱신까지 이어서 할 경우 **50개씩 보기**를 사용하고, 원하는 상품을 체크한다. 표 머리 체크박스는 **현재 페이지 상품 선택**이다. 검색된 2,114개 전체 선택이 아니다. 다른 페이지에서 선택한 항목이 남을 수 있으므로 상단 선택 수를 확인한다.
4. **일괄 편집 (N) ▾ → 가격·수량 계산**을 누른다.
5. 처음 보이는 **기준 판매가** 행의 필드를 **마진율**로 바꾼다. 판매가 자체를 10원으로 입력하지 않는다.
6. **변경 필드 추가**로 총 세 행을 구성한다.

| 변경 필드 | 변경 방식 | 입력값 | 의미 |
|---|---|---:|---|
| 마진율 | 값 지정 | `10` | 10%로 설정. `0.1`이나 ‘증감 10’이 아님 |
| 쿠폰율 | 값 지정 | `0` | 0%로 설정 |
| 최소 마진가 | 값 지정 | `1500` | 1,500원으로 설정. 입력에는 쉼표 없이 사용 |

7. **변경 전후 계산**을 눌러 세 필드의 변경 예정값을 확인한다. 이 단계의 ‘수치 검사 통과’는 저장·마켓 전송 성공이 아니다.
8. **수정 제한·저장값 검토**를 누른다. 상품별 저장 가능/저장 제외, 파생 판매가 변경, 마켓별 계산가와 최소마진 하한을 확인한다.
9. 내용이 맞으면 **검토한 N개 상품 저장**을 누른다. 제외된 상품은 저장되지 않는다. 변경 없음은 실패가 아니다.
10. 저장 결과를 확인하고 아래 ‘마켓 결과 확인’ 절차로 이어간다.

**정책 변경과 가격의 관계:** 마진·쿠폰·최소마진은 마켓별 가격 계산에 쓰인다. 그리드의 기준 판매가가 모든 마켓의 계산가와 같다는 뜻은 아니다. 정책만 바꾸는 경우 기존 기준 판매가는 반올림·최소마진 보정만 일어날 수 있다. 검토표의 마켓별 계산가를 함께 확인한다.

**설정 및 연동에서 IHB 기본 정책만 바꾸면 되는가?** 모든 기존 상품을 일괄 변경하는 방법은 아니다. 가격 계산은 상품에 저장된 정책값을 소싱처 기본 정책보다 우선 사용한다. 상품별 값이 있으면 기본 정책만 바꿔도 유지된다.

### B. 최신 아이허브 가격·재고 수집

정책을 저장한 상품 중 **최대 50개**를 선택하고 **소싱 가격·재고 비교 (N)**를 누른다.

1. **선택 N개 상품 최신 내용 수집**을 누른다.
2. 수집 대기·진행이 끝날 때까지 기다린다. 필요하면 **수집 결과 재조회**를 누른다.
3. 상품의 **비교 및 적용 항목 선택**을 펼쳐 기존/수집 값을 확인한다.
4. 가격을 반영할 때 **적용 가능한 가격**, 재고 상태도 반영할 때 **적용 가능한 재고 상태**를 누른다. 일부 상품만 개별 체크할 수도 있다.
5. **선택 내용 적용 검토**를 누른다.
6. 저장 가능/제외, 판매가·최소마진 영향 등을 확인하고 **검토한 N개 상품 저장**을 누른다.
7. DB 저장 결과와 마켓별 반영 결과를 각각 확인한다.

가격·재고를 함께 적용하려면 같은 검토에서 함께 선택한다. 일부 항목을 먼저 저장하면 상품 변경으로 나머지 항목은 재수집이 필요할 수 있다.

이 수집은 **판매용 설정 수량(예: 300개)을 바꾸지 않는다.** 소싱처의 재고 상태와 마켓에서 판매하도록 설정한 수량은 별도다. 수집 실패·소싱처 상품 소실은 임의의 품절 확정이나 기존 값 삭제로 대체하지 않는다.

### C. 다음 묶음 처리

현재 묶음의 결과를 확인한 후 기존 선택을 해제하고 다음 상품들을 선택한다. 정렬이 갱신 시각이나 조치 상태에 따라 달라지면 처리 중 순서가 바뀔 수 있으므로, 반복 수작업에서는 **SB코드 오름차순**과 처리한 코드 목록을 이용해 중복·누락을 확인한다. 이 수작업은 고정된 전체 대상 배치의 대체 기능이 아니다.

## 3. 배치 업데이트 페이지

[배치 업데이트](http://168.107.31.154/sbshop-agent/batch)의 현재 제목은 **배치 가격/재고 일괄 업데이트**다.

| 탭 | 용도 | 실제 동작 |
|---|---|---|
| 소싱업체별 수집·검토 | 소싱처로 대상을 찾기 | 코드 IHB → 수집·검토 대상 확인 → 현재 페이지 최대 50개 선택 → 선택 N개 수집·검토 |
| 상품ID 지정 수집·검토 | 알고 있는 상품 ID로 대상을 지정 | 숫자 상품 ID를 쉼표/줄바꿈으로 1~50개 입력 → 수집·검토 대상 확인 |
| 값 직접 지정 | 이미 계산된 판매가·재고 값을 직접 적용 | 상품 ID, 판매가, 재고 입력 → 입력값 적용 → 확인창에서 적용 |

**상품ID와 SB코드는 다르다.** 숫자 상품 ID 입력란에 `220114OC012` 같은 SB코드를 넣지 않는다. SB코드만 있으면 상품 관리의 **여러 SB코드 붙여넣기**로 찾는다.

**값 직접 지정은 이번 마진 조건 배치에 쓰는 메뉴가 아니다.** 마진·쿠폰·최소마진으로 가격을 계산하지 않고 입력한 판매가·판매상태를 적용한다. 최신 소싱 가격 수집도 하지 않는다. 재고 입력을 판매용 수량 300 설정과 같은 기능으로 해석하지 않는다.

직접 지정의 형식 예:

```text
1024, 32900, 12
1025, , 0
1026, 18500,
```

이는 사용 형식 예시이며 실제 대상이 아니다. 빈 값이나 `-`는 해당 값을 유지한다. 판매가에 천 단위 쉼표를 쓰지 않는다. 확인창의 설명과 상품 목록을 검토한 후 실행한다.

기존 **배치 진행현황**은 직접 지정 등 기존 배치 작업의 진행 상태다. 새로운 소싱 수집의 완료 여부는 수집 창에서 확인해야 한다. 배치 진행현황에 새 배치 ID가 안 보인다고 수집을 반복 접수하지 않는다.

## 4. 상품 관리의 기본 사용법

### 검색·필터·정렬

- 통합 검색: 상품명·SB코드·브랜드·바코드.
- **여러 SB코드 붙여넣기**: 쉼표 또는 줄바꿈으로 여러 코드 입력.
- 소싱처·브랜드·재고 상태, 등록/미등록 마켓 등을 조합하고 **검색**을 누른다.
- ‘IHB · 재고 있음 · 쿠팡 등록 · 11번가 미등록’은 해당 조건에 맞는 일부 상품이다. IHB 전체 실행용 조건이 아니다.
- 기본 정렬은 조치 필요 우선 → 콘텐츠 적용 오래된 순. SB코드·브랜드·상품명 등으로 바꿀 수 있다.
- 이미지·상세정보 경과 조건에는 적용 기록 없음이 포함될 수 있다. 모두 실제로 90일 이상 오래됐다는 뜻은 아니다.
- 표시는 20/50/100/200개씩, 행 간격은 기본 촘촘하게 또는 넓게 선택한다. 표시 개수와 작업별 실행 한도는 다르다.

### 버튼별 역할

| 하고 싶은 일 | 사용하는 버튼 |
|---|---|
| 상품 하나의 DB 정보 편집 | 해당 행의 열기 |
| 여러 상품의 마진·쿠폰·최소마진·숫자 수정 | 일괄 편집 → 가격·수량 계산 |
| 여러 상품의 기본정보·이미지·HTML 수정 | 일괄 편집 → 기본정보·이미지·상세 편집 |
| 소싱처의 최신 가격·재고 확인 | 소싱 가격·재고 비교 |
| 최신 이미지·자동 생성 상세 확인 | 이미지·상세 갱신 |
| 외부마켓의 실제 가격 반영·결과 확인 | 마켓 반영·작업 → 판매가 반영·작업 |
| 외부마켓의 판매용 수량 반영 | 마켓 반영·작업 → 판매용 수량 반영·작업 |
| 이미지·HTML 등 마켓 반영 | 마켓 반영·작업 → 이미지·상세·기본정보 반영·작업 |
| 마켓에서 상품이 존재하는지 확인 | 마켓 상태 확인·작업 |
| 미등록·과거 삭제 상품의 등록 검토 | 미등록 마켓 등록·작업 |

필드가 잠기거나 저장 제외이면 표시된 사유를 확인한다. 연결 마켓의 수정 제한 때문에 저장할 수 없는 항목이 있다. 모든 연결이 해제된 경우에도 수치·필수값 등의 검사는 유지된다.

### 이미지·상세 갱신

최대 50개 선택 → **이미지·상세 갱신** → 최신 내용 수집 → 기존/최신 비교 → 필요한 항목 선택 → **선택 내용 적용 검토** → 저장 순서다. HTML은 상품명·묶음수량 등 자동 생성 규칙을 따른다. 수집 시각과 DB 적용 시각은 다르며, 마켓 전송은 별도로 확인한다.

## 5. 마켓 반영 결과 확인

DB 저장과 마켓 완료는 같은 단계가 아니다. 저장 시 지원되는 변경은 자동 반영 작업으로 접수될 수 있다. 결과를 보기 전에 같은 상품을 다시 접수할 필요는 없다.

1. 해당 상품을 선택한다.
2. **마켓 반영·작업 ▾**에서 가격/수량/기본정보 중 해당 메뉴를 연다.
3. 최근 작업에서 저장·접수한 작업을 선택해 마켓별 상태와 사유를 확인한다.
4. 미반영·실패·보류 상품만 최신 상태로 다시 검토한다.

| 표시 | 해석·다음 행동 |
|---|---|
| 수집 완료 | 소싱 데이터를 가져온 상태. DB 저장 전일 수 있음 |
| 저장 가능 / 실행 전 확인 대상 | 검토 결과. 아직 저장·마켓 반영 완료가 아님 |
| DB 저장 완료 | 시스템상품 저장 성공. 마켓 결과는 별도 확인 |
| 조회 대기 / 실제 반영 재조회 대기 | 처리 중. 같은 대상을 반복 접수하지 않고 조회 |
| 판매용 수량 일치 확인 | 마켓에서 해당 수량을 다시 읽어 목표와 일치 확인 |
| 저장 제외 / 전송 보류 | 사유를 확인하고 입력·연결·마켓 상태를 정리한 후 재검토 |
| 반영 불일치 / 결과 미확인 | 성공 아님. 이력과 재조회 결과를 확인 |
| 다시 검토 필요 | 검토 뒤 상품·연결·정책 변경 또는 유효 시간 경과 가능. 최신 값으로 재검토 |

‘등록됨/연결됨’은 모든 필드가 최신으로 일치한다는 뜻이 아니다. ‘마켓 상태 확인’도 가격·이미지 등을 수정하는 기능이 아니다. 품절은 정상 연결을 유지하고, 삭제·영구금지가 확정되면 과거 상품번호·근거를 남기고 활성 연결에서 제외한다.

11번가 수량은 현재 판매중인 단일 재고 상품의 양수만 지원한다. 사용자 승인으로 `220114OC012`의 997→300개 전송 1회 및 별도 재조회를 확인했다. 0개·품절 해제·판매 재개까지 검증된 것은 아니다. 11번가 등록은 입력 준비만 가능하며 실제 신규 등록 실행은 아직 열려 있지 않다. G마켓·옥션 최종 반영 자동화도 미완료이므로 카페24 성공만으로 두 마켓까지 성공이라고 판단하지 않는다.

## 6. 이번 요청을 위해 보완해야 할 동선

전체 소싱처 대상 확정 → 이번 실행의 마진 10/쿠폰 0/최소마진 1500 지정 → 최신 수집 → 상품별 기존/예정 가격·제외 사유 요약 → 검토 후 전체 접수 → 중단/재개·실패만 재시도 → DB/마켓 결과 분리 확인이 필요하다.

내부 처리는 묶음으로 나누더라도 사용자가 43묶음을 수동으로 처리하게 해서는 안 된다. 대상·정책을 고정한 전체 작업 기능은 아직 구현되지 않았으며, 이 매뉴얼의 선택 상품 절차로 ‘전체 배치 기능 완료’를 대신하지 않는다.
