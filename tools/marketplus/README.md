# MarketPlus observer

The observer reads verified MarketPlus history DOM into local capture files. The relay writes only
observations to SB. It never modifies an external product or restarts its sale.

Run checks from the repository root:

```sh
python3 -m unittest discover -s tools/marketplus -p 'test_*.py'
python3 -m unittest discover -s tools/browser -p 'test_*.py'
```

`docker-compose.marketplus.yml` is an optional overlay for the main Compose configuration. It adds
the isolated observer services and a read-only status mount to the API. An observer-only deployment
must exclude the API service instead of recreating the existing application. The deployment record
is `docs/design/2026-09-06-marketplus-server-observer.md`.

The worker defaults to paused. After interactive login and account review, `/state/enabled.json`
controls the two functions independently:

```json
{"collect": true, "upload": false}
```

Enable upload only after the target SB API, required DDL and reviewed account settings are ready.
The worker checks its flags every 30 seconds while idle. Default collection interval is 900 seconds;
each result tab has a 10-page ceiling. A page ceiling always remains partial coverage.

Set `MARKETPLUS_GMARKET_ACCOUNT` and `MARKETPLUS_AUCTION_ACCOUNT` to the reviewed seller IDs.
Before each collection cycle, the worker checks the mall's administrator links and both linked
accounts on the actual account-management page. Missing, different, duplicate or shop-2 accounts
stop new collection. Existing captures remain available for independent upload.

The default completed tab has no `queue_status` parameter. It is accepted only with the selected
completed tab and success-prefixed rows; explicit conflicting, empty or duplicate parameters fail.
Market icon numeric suffixes are generated by React, so they are not treated as fixed seller IDs.
Login loss, unstable history pages and account mismatches have distinct status codes. A browser
failure between pages finalizes the saved portion and does not prevent checking the other tab.
Pending file counts remain visible when upload is disabled.

Files are retained in `/state/captures` and `/state/receipts`. `status.json` is atomically copied to the
separate status mount. `upload-gate.json` survives restarts and governs all pending files. Authentication,
missing API and redirect failures require operator correction; after correcting the cause, review the
blocked receipts and clear the blocked gate for resumption. Never clear a future 429 deadline early.
Invalid or unfinished captures remain visible as blocked; valid other files can still be uploaded.

For a manual relay invocation, provide `SBSHOP_RELAY_USERNAME` and `SBSHOP_RELAY_PASSWORD` in the
process environment through a protected secret mechanism. Do not put credentials in command arguments.
Use HTTPS or an SSH-forwarded loopback address. Internal `http://sbshop-api:8080` is supported inside
the server's private Docker network.

```sh
python3 tools/marketplus/relay.py \
  --input /path/to/completed-capture.json \
  --receipt /path/to/private-receipt.json \
  --base-url http://127.0.0.1:18080
```

The same invocation resumes unknown results safely. A changed file, destination or username cannot
reuse its previous receipt. `--retry-rejected` explicitly rechecks previously rejected mappings after
correction. Exit 0 means all supplied pages have validated receipts without rejections; it never
means all MarketPlus history was captured or every external product is in sync. Exit 2 means pending,
blocked or rejected results; exit 1 is input/configuration/storage failure. Receipt files do not store
credentials. Redirects are not followed.

The server browser profile belongs only to this observer. Do not automate a human's unrelated tabs,
copy their browser profile or take over an unknown WebDriver session. A profile volume and session
file preserve state across worker recreation; live login recovery still requires operator verification.
